Gradient descent and stochastic gradient descent

Most models have no closed-form solution. Gradient descent needs only the gradient of the loss; stochastic gradient descent needs only the gradient on a small batch. Every network in this course, and every LLM, is trained by a descendant of this loop.

The idea

wt+1 = wt − η ∇L(wt)

  • Near w, L(w + Δ) ≈ L(w) + ∇L(w)ᵀΔ. Among small steps of a given length, Δ = −η∇L lowers the loss the most.
  • The approximation only holds for small steps, so η trades speed for safety.
  • A minimum is where the gradient is zero; the iteration stops moving there. So does it at a maximum or a saddle point, which is why we also watch the loss.

How large can the step be?

On a quadratic with curvature λ, one step multiplies the distance to the minimum by (1 − ηλ): it converges only if η < 2/λ. The steepest direction caps η, and the flattest direction then sets the pace. A large condition number κ means slow progress for any η.

Convex and non-convex losses

  • Convex (linear and logistic regression): every local minimum is global, and gradient descent with a suitable η converges to it from any start.
  • Non-convex (any network with a hidden layer): many minima, saddle points and flat regions. Where you start (deck 07) and how you step (deck 08) matter.
  • In practice large networks reach low training loss from random starts with remarkable reliability. Theory explains this only in part, so the course treats it as an empirical fact and teaches you to measure.

Stochastic gradients

∇L(w) = (1/n) Σi ∇ℓi(w) ≈ (1/B) Σi∈batch ∇ℓi(w)

  • The full gradient is an average over all n examples. A random mini-batch of B examples gives an unbiased estimate at B/n of the cost.
  • The estimate is noisy: its variance falls as 1/B, so doubling the batch halves the variance but doubles the cost of each step.
  • Robbins and Monro proved in 1951 that such noisy steps converge if the step sizes shrink so that Σ ηt = ∞ and Σ ηt² < ∞, for example ηt ∝ 1/t. Deck 09's learning-rate schedules are the practical form of that condition.

The training loop

for epoch in range(num_epochs):
    for batch in shuffle(train_set).batches(B):
        loss = mean(loss_fn(model(batch.x), batch.y))
        grads = gradient(loss, params)          # deck 06
        params = params - lr * grads           # deck 08 replaces this line
    evaluate(model, validation_set)            # deck 04
  • A step is one update; an epoch is one pass over the training set, n/B steps.
  • Shuffle every epoch so batches differ; sorted or grouped data gives biased gradient estimates.

Why the noisy method wins at scale

  • A full-batch step costs n gradient evaluations, so its price grows with the data. An SGD step costs B, whatever n is.
  • Early in training, a few hundred examples point in nearly the same direction as all of them: many cheap steps beat one exact step.
  • Bottou, Curtis and Nocedal show that for large data sets SGD reaches a given test error with less computation than batch methods, because the optimization error need not be smaller than the statistical error of a finite sample.
  • The noise is not only a cost: it lets the iterate escape sharp regions and saddle points, a regularizing effect revisited in deck 09.
Bottou, Curtis and Nocedal 2016, arXiv:1606.04838, §3 and §4 · bibliography

Checking gradients

∂L/∂wj ≈ [ L(w + εej) − L(w − εej) ] / 2ε

  • Central differences have error of order ε², against ε for one-sided differences. Use float64 and ε around 10−6.
  • Compare with the relative error |a − b| / (|a| + |b|). Around 10−7 is correct; 10−2 is a bug.
  • The check costs two loss evaluations per parameter, so run it on tiny inputs. Every gradient in labs L0 and L1 is checked this way.

Where this shows up in LLMs

  • LLM pre-training is mini-batch stochastic optimization. A batch is a few million tokens; a run is hundreds of thousands of steps, and usually less than one or a few passes over the data.
  • Adam (deck 08) replaces the update line, a schedule (deck 09) sets η at each step, and the loop is otherwise the one on slide 6.
  • Because each step sees only a batch, training curves are noisy; teams watch smoothed loss and held-out loss rather than single steps.
  • Data-parallel training splits a batch across devices and averages their gradients, which is the same estimate computed in pieces.
