Training practice: a debugging recipe

A network with a bug usually still trains, just worse, so nothing tells you it is broken. This deck collects the checks used throughout the course into one order of work: know the data, check the start, overfit on purpose, then regularize and tune, changing one thing at a time.

Problem: training fails silently

  • A wrong sign in a gradient, labels shuffled against inputs, a softmax over the wrong axis, dropout left on at test time: none of these raises an error. The loss still goes down, a little.
  • Karpathy's summary: "neural net training fails silently". The defence is to build in small steps, and to check each step against something you can predict.
  • Every lab in this course does that: each gradient is compared with finite differences, and each result with a number known in advance (a closed form, chance level, a known paper result).

1. Know the data, start from a baseline

  • Look at many examples by hand, with their labels. Check class balance, duplicates and leaks between training and validation splits.
  • Train the simplest model first: a linear or logistic regression (deck 01, 02) or the majority class. It gives the number every later model must beat, and a pipeline you trust.
  • Fix the random seeds, so that a change in the result comes from a change in the code.
  • Write down the expected numbers before running: initial loss, chance accuracy, a rough target.

Does the perturbation cross a kink?

Before calling it a backward bug, check whether the two forward evaluations stay on the same smooth branch.

The code may choose a subgradient at zero. A symmetric numerical slope of 0.5 is not proof that choice is wrong.

3. Overfit on purpose

  • Take one small batch and train on it alone. The loss should reach nearly zero. If it cannot, the model, the loss or the update is broken: no amount of data will fix it.
  • Then make the model large enough to fit the whole training set well, before thinking about validation error. Lab L3's unregularized network reaches 100% training accuracy on 40 points.
  • Start from a known recipe: the closest published architecture and its optimizer settings. Adam at about 3 × 10−4 is a common safe start; the course's small labs use 10−3 to 10−2.
  • Only now regularize (deck 10): more data or augmentation first, then weight decay, dropout and early stopping, keeping the training loss you gave up in view.

4. Set the learning rate first

  • Sweep it in factors of about 3 (10−4, 3 × 10−4, 10−3, …) for a short budget and plot the final loss. The best value is usually a little below the one that starts to diverge.
  • The edge is sharp: in lab L2, gradient descent on a quadratic with largest curvature 100 converges at 0.0199 and diverges at 0.0201 (2/λmax = 0.02, deck 03).
  • Greff et al. found the learning rate mattered more than any LSTM variant (deck 16); with batch norm, lab L3 trained across a 30-fold range of learning rates (deck 11).
  • Then warm-up and decay (deck 09), and only then the other hyperparameters.

5. Read the curves

Always plot training and validation loss against steps, on the same axes, with the initial loss marked. Loss spikes: lower the learning rate, add warm-up or clip the gradient (deck 15). Flat at ln K: look for a gradient that never arrives (a detached tensor, dead ReLUs, a too-deep plain network, deck 14).

6. Tune fairly

  • Change one thing at a time, with the same data, budget and seeds, and run more than one seed when the difference is small.
  • Random search beats grid search when only a few hyperparameters matter: with the same number of trials it tries more values of each one.
  • The tuning playbook separates scientific hyperparameters (the thing you are testing), nuisance ones (to be re-tuned for each value of it, such as the learning rate) and fixed ones, so that a comparison is not just a comparison of how well each option was tuned.
  • Keep a log of every run: the configuration, the code version and the curves.

Where this shows up in LLMs

  • An LLM's initial loss is ln V for a vocabulary of V tokens: about 10.8 for 50,000. A first step far above that is a bug.
  • Large runs monitor the gradient norm and the loss at every step, clip at a global norm of 1.0, and watch for loss spikes; the response (skip batches, restart from a checkpoint with a lower rate) is part of the training procedure.
  • Recipes are chosen on small models first, then scaled: small-scale ablations and scaling laws are the "overfit a small batch, then grow" step at industrial scale.
  • The LLM Training course takes this up for large runs: loss spikes, z-loss and other stability fixes (its deck 03).

Near zero: inspect absolute and relative error

Constructed perturbation: add 1e−12. Raw relative error uses |a−b| / max(|a|, |b|).

At reference 0: absolute error = 1e−12, relative error = 1. Choose justified absolute + relative tolerances; no universal cutoff.
