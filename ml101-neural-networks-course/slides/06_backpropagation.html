Backpropagation

Rumelhart, Hinton and Williams, 1986, "Learning representations by back-propagating errors". A network with millions of weights needs the derivative of the loss with respect to each one. Backpropagation computes all of them for roughly the cost of two forward passes, by applying the chain rule backward through the computation.

Problem: one derivative per parameter

  • Finite differences need two forward passes per parameter. For a 10-million-weight network that is 20 million passes per gradient step.
  • Writing the derivative of each layer by hand, as deck 02 did for one layer, does not scale to deep and changing architectures.
  • What we want: a mechanical procedure that, given any composition of differentiable operations, returns every partial derivative of a scalar loss at a small constant multiple of the cost of evaluating it.

A computation is a graph

Forward (blue boxes): compute and store every intermediate value. Backward (amber): start from ∂L/∂L = 1 and, at each node, multiply the incoming gradient by the node's local derivative. ∂L/∂w = −12 is ∂L/∂r · ∂r/∂v · ∂v/∂u · ∂u/∂w = (−6)(1)(1)(2).

The rule at each node

  • Local: each operation only needs to know its own derivative. For u = w·x: ∂u/∂w = x and ∂u/∂x = w. For v = u + b, both derivatives are 1.
  • Chain: gradient into an input = gradient arriving at the output × local derivative.
  • Fan-out adds: if a value feeds several operations, its gradient is the sum of the gradients coming back along each path. Forgetting to accumulate is a classic bug (a lab L1 test).
  • Order: visit nodes in reverse topological order, so a node's gradient is complete before it is passed further back.

Why backward, not forward

  • Forward-mode differentiation pushes derivatives along with values from inputs to outputs. Its cost grows with the number of inputs you differentiate with respect to: one pass per parameter.
  • Reverse mode (backpropagation) pulls derivatives from outputs to inputs. Its cost grows with the number of outputs. A loss is one number, so one backward pass gives every parameter's gradient.
  • The backward pass costs a small constant times the forward pass; for matrix products it is about twice the forward cost (two products per forward product).
  • The price is memory: the backward pass needs the forward pass's intermediate values, so training stores activations that inference throws away.

An autograd engine in a few lines

def __matmul__(self, other):
    out = Tensor(self.data @ other.data, parents=(self, other))
    def backward():
        self.grad  += out.grad @ other.data.T     # dX = G W^T
        other.grad += self.data.T @ out.grad      # dW = X^T G
    out._backward = backward
    return out

def backward(self):                      # on the scalar loss
    for t in reverse_topological_order(self):
        t._backward()

Each operation records its inputs and a closure that adds its share of the gradient. Lab L1 builds the whole engine (add, multiply, matmul, ReLU, tanh, sigmoid, sum, fused softmax cross-entropy) this way, and PyTorch's autograd works on the same principle.

What the 1986 paper showed

  • Reverse-mode differentiation was older (Linnainmaa 1970; Werbos 1974 proposed it for networks). Rumelhart, Hinton and Williams showed what it does for learning: hidden units trained this way discover useful internal representations that nobody specified.
  • Their examples include a network that learns family relationships from triples and whose hidden units come to encode features such as generation and family branch.
  • They noted that the loss surface may have local minima but that these rarely caused trouble in their tasks, a pattern that has held for far larger networks.

Where this shows up in LLMs

  • Every training step is a forward pass, a backward pass and an optimizer update. Frameworks (PyTorch, JAX) build the graph and run reverse mode for you.
  • Forward costs about 2 FLOPs per parameter per token and backward about 4, which is where the 6ND estimate of training compute comes from (Transformer course deck 05 and its lab L0).
  • Stored activations dominate training memory for long sequences; activation checkpointing recomputes some of them during the backward pass to trade compute for memory.
  • Gradient checks on tiny models are still how new kernels and layers are tested.
