## Worked dossier and counterexample

Start with ROCm **10.1.0**, hipBLASLt **1.4.1**, MI350X **gfx950**, and the selected Ubuntu **24.04.5 / GA 6.8** row. Mark this **documentation inspected; local execution not run**. This partial tuple is not a complete qualified environment: exact firmware, driver, installed package/container identity and full operation contract remain unset. The matrix explicitly requires coordinated firmware/driver/user-space alignment. No arbitrary driver from its list was paired with a local device.

An entry claiming `hipblaslt_f8_fnuz` on gfx950 contradicts the selected library's platform note. That is a **documentation counterexample**, not a captured runtime rejection. It must not be reported as a failed kernel test or universal absence of FP8 hardware. Renaming/casting the data does not prove compatible representation or numerical behavior. Recheck at each release rather than extending the restriction to every future library or all ROCm layers.

Before execution, record A/B/C/D and compute/scale types, transpose, shape/strides/layout/alignment, batch mode, epilogue, workspace and chosen algorithm/backend. Then establish artifact/driver/firmware identity, run numerical/tail/unsupported-contract cases and measure a matched workload only on an eligible target. A library enum, successful import, responsibility map or platform listing cannot substitute for these results.
