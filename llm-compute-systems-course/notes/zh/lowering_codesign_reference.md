# 模型降级与协同设计：参考讲义与工作表

配套[第 34 讲](../../slides/zh/34_model_lowering_codesign.html) · [English](../lowering_codesign_reference.md)。核验于 2026-11-01。课堂保留机制主线，这里放可选集成细节；不是已执行编译实验，也不是通用 API 配方。

## 谁决定什么？

| 参数 | 模型与质量决策 | 硬件与实现约束 |
|---|---|---|
| 层维度 | 隐藏层、FFN、注意力头、词表 | 指令形状、tile、split-K 与派发 |
| 权重表示 | 质量容差与量化配方 | 原生格式、打包布局、缩放与转换 |
| 组或块大小 | 配方特有的量化组 | 原生块缩放指令可能约束另一种粒度，不能自动等同 |
| KV 状态 | 实际 MHA/GQA/MLA 表示 | 容量、缓存布局、缩放粒度与注意力 kernel |
| 卷积 | 核、步幅、通道与填充 | 算法、工作区、变换误差与目标性能 |

固定芯片要求负载适配资源；ASIC/FPGA 设计还可把阵列维度和本地缓冲作为变量。两者都不保证某个 tile 或更低位宽必然改善完整任务。

## 编译器与运行时的独立责任

| 栈 | 图与编译路径 | 设备与运行时集成 | 所需证据 |
|---|---|---|---|
| IREE | 导入 MLIR 后面向目标编译 | HAL 设备、驱动与兼容产物 | 编译、加载、搬运、执行和输出检查 |
| TVM | Relax 图与 TensorIR，外部派发可分区子图 | 运行时模块、目标代码生成与外部库 | 每个算子都有合法目标或显式回退，并测量边界成本 |
| OpenXLA | 输入 IR 经兼容目标编译器 | PJRT 缓冲、编译与执行接口 | API 符合性、编译覆盖与数值行为 |

阅读 [IREE 部署配置](https://iree.dev/guides/deployment-configurations/)，按目标选择示例，不要跨机器复制“通用”命令。编译后端、目标 triple、运行时设备与 ABI 必须匹配。`.vmfb` 路径与裸机静态产物是不同配置，参见[裸机指南](https://iree.dev/guides/deployment-configurations/bare-metal/)。

TVM 的[架构](https://tvm.apache.org/docs/arch/index.html)与 [BYOC](https://tvm.apache.org/docs/arch/external_library_dispatch.html) 说明模式匹配、分组、外部生成与普通降级可共存。**分区本身不会提供缺失算子实现。** 剩余部分仍需合法路径；若用 CPU 回退，还需决定放置、搬运与同步，不能把主机回退默认为全加速器覆盖。

阅读 [PJRT 集成](https://openxla.org/xla/pjrt/pjrt_integration)。运行时插件不是新 ISA 的自动代码生成器，必须共同测试编译器、驱动与插件。第 22、23 讲的部署路径可供对照，但产物不能互换。

## Bring-up 关卡

1. 缓冲往返：分配、搬运、简单运算、完成与清理均正确。
2. 代表性算子：先验证形状、尾部与精度，再与适用边界比较时间。
3. 完整模型：验证输出、实际放置、其余算子与临时内存。
4. 集成：保持顺序、生命周期、错误传播与框架约束。
5. 调优：先找暴露的时间占比，再比较组件及端到端结果。

这是规划框架，不断言所有模型都由 GEMM 主导，也不认为一个代表性 kernel 就完成移植。

## 协同设计工作表

选择一个 decoder 与两种目标环境，分别记录 prefill、decode 的 M/N/K、质量约束、权重表示、实际 KV 张量及预期流量。为每个目标写明编译与运行时边界及所有回退。必须有三类独立检查：数值或质量一致、执行覆盖与放置、范围明确且标注搬运及启动成本的计时。未执行的目标档案仍标为分析。

课堂预测题在只支持 GEMM 的目标上放置 GEMM 加归一化图。插件无法产生缺失的归一化实现，方案仍需降级或显式回退并计入边界成本。格式、卷积与历史时间占比来源保留在[注释书目](../../references/bibliography_and_links.md#model-lowering-and-hardware-co-design-reviewed-2026-10-30)，历史百分比不是练习的通用假设。
