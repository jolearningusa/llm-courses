Parallel without locks

  • One launch is many blocks. A kernel launch is a grid of independent blocks; the hardware places them on the N SMs as resources free up. Blocks do not wait on each other, so no locks are needed between them.
  • Inside a block, order comes from barriers. The producer signals “tile ready”, the consumer signals “buffer free” (see “Pipeline hazards”). That is a handshake, not a lock.
  • Across blocks, order comes from the decomposition. Stream-K waits on a per-tile flag only to fix up tiles it split; MPK waits on event counters that dependent tasks increment.
  • Cost of fewer launches: a persistent or megakernel holds registers and shared memory for its whole life, and one slow task can idle its SM.

Reported results: Stream-K beat cuBLAS by up to 6.7× on some of 32,824 A100 GEMM shapes; MPK cut end-to-end latency by up to 1.7× against kernel-per-operator vLLM and SGLang. Both are research or library measurements, not course measurements.

Spatial chips make the pipeline explicit

On Tenstorrent’s Tensix cores the pipeline is three programs per core:

reader (NoC 0 → SRAM) → circular buffer → compute (matrix and vector units) → circular buffer → writer (SRAM → NoC 1)

  • Circular buffers in the core’s 1.5 MB SRAM are the producer/consumer queues: each kernel proceeds when its data or space is ready.
  • Cores pass data to each other over a 2D torus network-on-chip, so the compiler or kernel author also chooses which core feeds which.

Same idea as warp specialization on a GPU, but the roles are separate processors and the queues are visible in the program.
