A minimal traffic model

B = bytes/element × (MK + KN + MN)

One read of each input and one output write. This is an idealized baseline: caches, repeated loads, output accumulation and intermediates change actual traffic.

6 / 16

A roofline lower bound

t ≥ max(F / C, B / W)

C is an applicable compute rate; W is bandwidth for the same scope. Perfect overlap gives a lower bound, not a complete runtime predictor.

Rates decide the bound

For the previous GEMM, assume 100 TFLOP/s and 1 TB/s:

math ≈ 1.374 ms; traffic ≈ 0.101 ms

The idealized bound is compute-limited. Replace assumed rates with measured achievable rates before comparing a device.

9 / 16

Decode changes the shape

Now M = 1, K = N = 4096 with the same storage and assumed rates.

F ≈ 33.55 MFLOP; B ≈ 32 MiB

Math ≈ 0.336 μs; ideal traffic ≈ 33.6 μs. The weight-read term can dominate at small batch. Launch and synchronization costs are still omitted.

10 / 16

Capacity is a separate constraint

live bytes + workspace + headroom ≤ usable memory

A bandwidth-efficient kernel may still fail to fit. Logical tensor bytes, allocated bytes and allocator-reserved bytes are different measurements.

Communication and dependencies

Compute phase → collective / transfer → dependent phase

Use payload and effective link rate for a transfer bound; add latency and contention. Sequential phases cannot all be hidden by taking one global maximum.

13 / 16

Amdahl’s limit

speedup = 1 / ((1 − f) + f / s)

If a kernel occupies 20% of runtime and becomes twice as fast, total speedup is about 1.11×. Measure the time fraction in the actual workload.
