Host and device clocks

CPU enqueue → device work → completion notification

A host timer around an asynchronous launch can measure enqueue time. A device event pair measures work ordered between those events, not every part of the request.

End-to-end wall time

Synchronize the relevant device work before the start and after the end when measuring a completed operation. Keep synchronization outside inner iterations unless it belongs to the workload.

Synchronization itself can remove realistic overlap; state the scope.

A sample distribution

median + p95 + minimum + repetition count

Use a declared percentile convention. A small sample p95 is a noisy order statistic, not a reliable service tail estimate. Keep raw samples.

7 / 17

A constructed overlap example

elapsed window: 0–10 ms
copy:            0–4 ms
kernel A:        2–7 ms
kernel B:        8–10 ms

Summed durations = 11 ms; union busy time = 9 ms; uncovered time = 1 ms. This is arithmetic for a constructed example, not a device trace.

8 / 17

Critical path and overlap

Summing every event double-counts overlap. Union busy time identifies uncovered intervals within a scope; it does not identify which resource or dependency caused them.

Use dependencies and stream/device identity to find the actual critical path.

9 / 17

Profiler perturbation

Profiling can serialize, replay or otherwise perturb work. Use focused traces for diagnosis, and unprofiled repeated runs for the primary timing comparison.

11 / 17

Fair comparisons

  • Use the same computation, effective batch and quality constraints.
  • Match allocation/copy/cache scope; record selected backend.
  • Keep power/clock/thermal and other job interference visible.
12 / 17

Correctness before timing

Check outputs and numerical tolerance before the repeated loop. For training, also check gradients and loss behavior. Ensure the result is consumed so the intended work really executes.

13 / 17

Speedup with uncertainty

S = baseline_time / changed_time

Use comparable summaries and raw trials. If run-to-run dispersion overlaps the alleged gain, repeat or explain the uncertainty rather than claiming a stable improvement.
