RMSNorm

yᵢ = xᵢ wᵢ / √(mean(x²) + ε)

Use one reduction over a row, then scale each element. The example uses contiguous float32 input/weights; other dtypes and strides require explicit support.

2 / 17

Reduction order and rounding

Floating-point addition is not associative. A parallel tree can differ from a serial reference; declare an appropriate error tolerance and inspect difficult inputs rather than require identical bits.

3 / 17

Stable softmax

m = max(x); pᵢ = exp(xᵢ − m) / Σexp(xⱼ − m)

Subtracting the row maximum prevents avoidable overflow in the exponentials. Check normalization and masked/all-invalid behavior explicitly.

Optimization sequence

Correct baseline → coalescing → reduction layout → fusion → shape tuning

Change one mechanism at a time. Keep a reference and negative cases while changing the implementation.

7 / 17

Warp-level reductions

A warp-local method may reduce shared-memory/barrier traffic. Check active masks, tail lanes and supported execution width. Do not substitute a warp primitive for required block-wide communication.

8 / 17

A reduction is a dependency tree

Parallel order changes rounding. Masks, synchronization and participation rules remain part of correctness.

9 / 17

Fusion tradeoffs

Combining operations can remove traffic and launches, but increases live state and may constrain available parallelism. Compare the fused path with the actual separate baseline.

10 / 17

Custom operator metadata

Specify shapes, dtype/device support, layout assumptions, aliasing and mutation. Metadata used during tracing must agree with runtime behavior.

11 / 17

Backward is separate work

A forward CUDA implementation alone is not a training operator. Implement or register the backward, then compare input and parameter gradients against an eager reference.

12 / 17

Compiler integration

Operator schema → metadata / fake execution → backend kernel → autograd

A successful eager call does not prove export, compilation or shape-polymorphic behavior. Test each required path.

13 / 17

Sanitizer and error handling

Check memory access and synchronization using appropriate tools. Also check launch/runtime errors and asynchronous completion. A passing numerical sample alone can miss a race.
