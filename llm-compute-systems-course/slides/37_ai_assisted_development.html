The CPU case study

Evaluate RMSNorm-style implementations: reference, legal reduction reorder and three deliberate mutants.

Then inspect a queue trace: submission pins a buffer; completion or valid cancellation ends device use; release follows.

These are numerical fixtures and authored event traces, not a GPU benchmark or concurrent device simulator.

7 / 11

A test must sometimes reject

  • An all-zero input cannot expose every constant-zero implementation.
  • A deliberately incorrect tail or epsilon placement checks numerical coverage.
  • An early release and stale reset completion check lifetime/generation coverage.
  • Also accept a legal reorder: rejecting everything is not a useful oracle.

Runtime changes need state evidence

“Free immediately after enqueue” can return correct values in one run and still violate outstanding ownership.

Trace a failing ordering; minimize it; fix the invariant. A single passing ordering does not cover all schedules.
