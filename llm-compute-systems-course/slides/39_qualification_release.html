Performance gates at the right boundary

Sustained runs and observability

Record latency distributions, memory growth, errors, resets and available power/thermal/clock telemetry over a declared duration.

Counters need definitions and ownership. Software observability is related to testability, but is not silicon scan/BIST coverage.

HIL can start with one test device

Reserve a designated board, deploy a known artifact, run tests, collect logs and restore a known-good version.

Scale the farm only after single-device recovery is reliable. Emulator pass and silicon pass are separate records.

Release boundaries and security

Validate manifests and input bounds; track dependency provenance, artifact identity and deployment authorization.

Malformed graph robustness and software supply-chain integrity are different checks. Signing does not prove numerical correctness.

Rollback and failure containment

Keep a compatible fallback and explicit abort conditions. Cancel admission, drain or reset according to the runtime contract, then restore.

Do not release live buffers merely because a timeout elapsed. First establish that device access has stopped.

The follow-on accelerator course

Study command ABI, queues/DMA, interrupts, firmware lifecycle, driver/runtime ownership, failure injection and HIL as a separate execution stack.

Use an executable virtual accelerator first; physical qualification needs a supported test target.
