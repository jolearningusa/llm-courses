最简流量模型

B = bytes/element × (MK + KN + MN)

每个输入读一次，输出写一次。这是理想化的基线：缓存、重复加载、输出累加和中间结果都会改变实际流量。

屋顶线下界

t ≥ max(F / C, B / W)

C 是适用的计算速率；W 是同一范围内的带宽。完全重叠只给出下界，而不是完整的运行时间预测。

容量是另一个约束

live bytes + workspace + headroom ≤ usable memory

带宽效率高的内核仍可能放不下。逻辑张量字节数、已分配字节数和分配器预留字节数是不同的测量值。

13 / 20

阿姆达尔极限

speedup = 1 / ((1 − f) + f / s)

如果一个内核占运行时间的 20%，并变快两倍，总加速约为 1.11×。要在实际工作负载中测量时间占比。

16 / 20

代入 f=0.2、s=2，得到 1/(0.8+0.1)≈1.11。固定分解下，即使目标 kernel 无限快，也只有 1/0.8=1.25。追问重叠关系变化为何可能使原时间占比失效。

一个能推翻预测的实验

  • 保持语义和工作负载不变；改变 M 或批大小。
  • 分别记录墙钟时间、设备时间和流量证据。
  • 把预测的转折点与实测行为比较；解释任何差距。
