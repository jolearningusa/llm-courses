GEMM 计算量

F = 2 × M × N × K

一次乘法加一次加法记为两次浮点运算。写明维度、dtype 和累加方式；峰值速率必须与运算类型对应。

最简流量模型

B = bytes/element × (MK + KN + MN)

每个输入读一次，输出写一次。这是理想化的基线：缓存、重复加载、输出累加和中间结果都会改变实际流量。

屋顶线下界

t ≥ max(F / C, B / W)

C 是适用的计算速率；W 是同一范围内的带宽。完全重叠只给出下界，而不是完整的运行时间预测。

速率决定瓶颈

对上面的 GEMM，假设 100 TFLOP/s 和 1 TB/s：

math ≈ 1.374 ms; traffic ≈ 0.101 ms

理想化的下界受计算限制。比较设备之前，用实测可达速率替换假设的速率。

解码改变了形状

现在 M = 1，K = N = 4096，存储和假设速率不变。

F ≈ 33.55 MFLOP; B ≈ 32 MiB

计算 ≈ 0.336 μs；理想流量 ≈ 33.6 μs。小批量时读取权重的时间可能占主导。启动和同步开销仍未计入。

容量是另一个约束

live bytes + workspace + headroom ≤ usable memory

带宽效率高的内核仍可能放不下。逻辑张量字节数、已分配字节数和分配器预留字节数是不同的测量值。

通信与依赖

Compute phase → collective / transfer → dependent phase

用负载大小和有效链路速率估计传输下界；再加上延迟和争用。顺序执行的阶段不能靠取一个全局最大值全部隐藏。

阿姆达尔极限

speedup = 1 / ((1 − f) + f / s)

如果一个内核占运行时间的 20%，并变快两倍，总加速约为 1.11×。要在实际工作负载中测量时间占比。

一个能推翻预测的实验

  • 保持语义和工作负载不变；改变 M 或批大小。
  • 分别记录墙钟时间、设备时间和流量证据。
  • 把预测的转折点与实测行为比较；解释任何差距。
