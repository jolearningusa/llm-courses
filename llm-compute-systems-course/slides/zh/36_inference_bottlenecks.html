构造示例：权重带宽预算

假设未分片的稠密模型：80 亿参数、BF16 权重、理想情况下读取一次，有效 HBM 带宽为 2 TB/s。

16 GB / (2 TB/s) = 8 ms

这仅是权重读取项。注意力、KV、启动、选择和通信仍可能增加成本。

较窄的矩阵运算可以让内存繁忙，同时只使用很少的可用浮点算力。

Roofline reasoning; constructed example
5 / 18

批处理改善序列之间的复用

独立序列在同一算子中可复用权重读取。在迭代时间明显增长之前，总 tokens/s 可能提高。

批大小为 8，并不意味着单个序列生成下一个依赖 token 的延迟缩短为八分之一。

更大的批量也会增加 KV 占用、注意力工作和排队。应同时报告吞吐与单请求延迟。

Sarathi-Serve §3 · Batching and latency
6 / 18

长上下文使预算向 KV 转移

32 层 × 8 个 KV 头 × 128 维 × K/V × BF16 = 每个已存 token 占 128 KiB。

32,768 个已存 token → 每序列 4 GiB 逻辑 KV；八个序列 → 32 GiB，尚未计入开销。

容量限制准入；读取保留的 KV 则从另一个方面限制执行。权重量化不会自动缩小 KV。

这是构造的 MHA/GQA 示例。布局、共享、精度和注意力变体会改变实际流量。

瓶颈诊断流程

  • 固定模型、分词器、精度、引擎、目标和输出语义。
  • 分别扫描批量 / 到达并发和上下文；区分 prefill 与 decode。
  • 在明确边界测量线性层、注意力、输出投影、选择、主机和通信。
  • 用时间线 / 计数器验证，再在无 profiler 时测 TTFT / TPOT / goodput。
  • 每次只改一个因素；包含收益消失的情况，并重测完整路径。
