即时执行路径

Python operation → dispatcher → backend implementation → runtime

一个可见的操作可能调用优化库，也可能调用一个或多个原生内核。要确定实际路径，而不是从 Python 名称推断。

算子与内核

算子内核
是什么要计算什么，用 aten::gelu 这样的 schema 命名某个后端如何计算它：针对某种设备、dtype 和布局编译出的函数
由谁选择程序（或一次图捕获）分发器，根据输入上的分发键
例子aten::mm一个 cuBLAS GEMM、一个 CPU 内核，或注册在 PrivateUse1 下的内核

在即时模式下，大多数算子启动一个内核。视图不启动内核，有些算子会启动多个内核或调用库。编译器会改变这种映射（第 06 讲）。

视图与拷贝

视图可以共享底层存储，同时改变形状/步幅。转换为连续布局可能会分配并拷贝。比较针对特定布局的快速路径时，要把这些开销计算在内。

5 / 18

布局算例

x: shape (4, 8), contiguous strides (8, 1)
x.T: shape (8, 4), strides (1, 8)

转置可以描述同一块存储。需要另一种布局的消费者可能引入额外工作；要检查，而不是假设总开销为零。

自动求导记录依赖

Forward operations → saved state → backward operations → gradients

前向的中间结果可能比它的直接消费者活得更久。这些生命周期会推高峰值内存。

线性层的反向

Y = XWᵀ; dX = dY W; dW = dYᵀ X

只看前向速度会漏掉两次主要的反向计算。偏置和非线性层还会增加各自的计算和状态。

梯度累加

重复调用 backward 会累加参数梯度。在预期的边界清零，并在比较实现时保持有效批大小的语义。

11 / 18

优化器的范围

Forward → loss → backward → optimizer update

说明基准测试是否包含每个阶段。L2 的核心实验计时前向和反向；不会悄悄把优化器工作包含进去。

12 / 18

正确性契约

  • 相同的初始权重、输入、loss 和模式。
  • 比较输出以及参数/输入梯度。
  • 声明 dtype 和容差；保持修改和别名行为。

训练模式与推理模式

评估模式控制模块的行为；关闭梯度记录控制自动求导的工作。这是两个独立的选择。基线和干预使用相同的预期模式。

自定义算子的职责

声明形状/dtype 行为、修改/别名以及梯度支持。编译出的前向实现并不会自动提供正确的反向或元数据契约。
