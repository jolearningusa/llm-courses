线程块提供协作/调度单元。启动把工作映射到这个层次上；它并不保证所有线程块同时驻留。

按行归一化的映射

one block → one row
thread t → columns t, t + blockDim.x, …

所有线程都参与行归约，包括第一列已经超出短行范围的线程。

4 / 17

尾部处理

行长度不一定是线程块大小的倍数。用列边界保护每次加载/存储。把块级屏障放在所有参与线程都会经过的控制流路径上。

共享内存归约

partial[thread] = local_sum
barrier
for stride = block_size/2 down to 1:
    if thread < stride: add neighbor
    barrier

这个示意的归约树假设线程块大小是选定的 2 的幂。

8 / 17

屏障的正确性

屏障只作用于一个协作范围。它不是跨所有线程块或设备的通用排序原语。写明生产者/消费者关系和内存序要求。

9 / 17

寄存器与占用率

更多存活的值可能增加寄存器需求，限制驻留的工作。更高的占用率本身不是目标：驻留线程块更少但复用友好的内核可能仍然更快。

10 / 17

每行一个线程块会限制可用的工作

行数少就只有很少的线程块，即使每行很长。拆分一行可以提高并行度，但需要正确地合并部分结果，并带来额外开销。

流量估算算例

对 D 个 float32 值和 D 个权重，一次理想的输出遍历读 8D 字节、写 4D 字节。

ideal baseline = 12D bytes / row

简单的 RMSNorm 内核在归约之后为输出再次读取输入，所以它在源码层面的输入流量更大。HBM 流量由缓存决定。

12 / 17

延迟受限与带宽受限

短行可能暴露启动/归约开销；长行可能暴露流量、寄存器或调度约束。扫描形状，而不是只调一个方便的维度。

CUDA 与 HIP 的可移植性

源码翻译不能证明性能。检查执行组的假设、矩阵指令、共享/局部内存，以及目标上后端的实际支持情况。
