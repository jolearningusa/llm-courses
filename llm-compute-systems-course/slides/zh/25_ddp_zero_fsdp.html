混合精度训练

FP32 parameters → autocast forward → scaled / unscaled backward → optimizer

Autocast 为各操作选择数据类型。不要盲目转换每个张量；归约和优化器状态的要求各不相同。

梯度缩放

FP16 下溢可能需要梯度缩放和溢出检测。BF16 指数范围更宽；CPU 上的 BF16 autocast 通常不用 GradScaler。两者都不能保证收敛。

状态仍是一项预算

矩阵操作数用低精度，并不会让每个参数、梯度、优化器槽位、保存的激活或集合通信缓冲区都变成低精度。要核对持久内存与瞬态内存。

DDP 比较算例

两个 rank 各处理 16 个样本，使用平均损失。对两者的梯度取平均，并与 32 个样本的平均损失参考结果比较。

(g₀ + g₁)/2 = g_global

这个等式假设各分区大小相等，且模型行为与 rank 无关。

分片变成瞬时的完整参数

13 / 22

峰值不等于持久状态

一个 rank 可能同时临时持有收集的参数、激活、梯度桶和预取的下一层缓冲区。持久状态估算最低的方案仍可能内存不足。

14 / 22

包装边界很重要

分组太小会增加启动/集合通信开销；分组太大会增加瞬态驻留，并可能减少重叠机会。依据内存和时间线证据选择边界。

15 / 22

梯度累积

每个微批次都同步可能浪费通信。延迟同步需要正确的损失缩放和足够的内存保存梯度；DDP 与分片训练的实现细节不同。

16 / 22

初始化与可复现性

  • 相同的初始参数、优化器和数据覆盖。
  • 控制随机种子和随机层。
  • 记录采样、被丢弃/填充的样本以及 token 加权。
  • 在解读吞吐之前先比较更新张量。
17 / 22

失败模式

缺失某个 rank、集合通信顺序不一致或循环结束不均，都可能让作业挂起。带诊断信息和超时地失败；不要用更长的超时掩盖协议错误。

18 / 22

CPU 证据有其边界

我们的双进程 Gloo 路径测试的是 DDP 更新语义。它不能验证 NCCL/RCCL GPU 重叠、FSDP 内存节省或多节点网络性能。
