CUDA 之外的编程模型

每个加速器厂商都有自己的“CUDA”吗？还是业界正在向 Triton、TileLang 这样可移植的分块语言收敛？

目标：准确描述 CUDA 执行模型，把各厂商的编程层映射到它上面，并为一个新设备（从数据中心 GPU 到边缘 DSP）选择切入点。

第 07 讲的补充。事实依据厂商文档于 2026-10-28 审阅；本讲未在非 NVIDIA 硬件上运行任何内核。

CUDA Programming Guide §1.2 (13.4.2)
1 / 19

一页讲清 CUDA 编程模型

  • 异构：应用从主机（CPU）启动，由主机在设备（GPU）上启动内核，并管理拷贝和同步。
  • 线程层次：grid → 可选的 cluster（计算能力 9.0+，一个 GPC）→ 线程块（运行在一个 SM 上）→ 由 32 个线程组成的 warp → 线程。
  • SIMT：一个 warp 执行一条指令流；分歧的通道被屏蔽。不要依赖文档未说明的 warp 行为。
  • 内存：每线程寄存器、每线程块（或 cluster）共享内存、L1/L2 缓存、全局内存（HBM）、统一内存。
  • 分块模型：当前指南还介绍了以整个线程块为单位、在不可变分块上编写代码的方式；它“并不取代 SIMT 编程”。

NVIDIA 也在增加分块层

层次是什么
CUDA C++（SIMT）逐线程代码；由你选择线程块形状、共享内存暂存和同步。
CUDA Tile IR基于 MLIR 的分块 IR，与 CUDA 13.1 对齐；开源（Apache-2.0 附 LLVM 例外）。

定义了 SIMT 的厂商如今也提供线程块级的分块。“分块还是 CUDA”不是公司之间的竞争，而是抽象层次的选择。

在 AMD 上运行 CUDA 代码

路线输入作用
HIPIFY（AMD）CUDA 源码改写为 HIP 源码，之后由你拥有和维护
SCALE（Spectral Compute）CUDA 源码面向 AMD 和 NVIDIA 目标的 nvcc 兼容编译器（列出 CDNA gfx906–gfx950、RDNA 1–4）
ZLUDA（开源）CUDA 二进制面向未修改应用的“非 NVIDIA GPU 上 CUDA 的直接替代品”

三种不同的主张：源码可移植（能编译）、功能可移植（在容差内结果相同）和性能可移植（达到每个设备可实现速率的合理比例）。翻译层只能证明第一种，不能证明第三种。

层次：图编译器、内核 DSL、厂商目标

  • 图编译器（TorchInductor、XLA）接收整个模型，决定融合、布局和库调用。
  • 内核 DSL（Triton、TileLang、Pallas、cuTile）在分块级别表达单个算子。
  • 厂商目标（CUDA/PTX、HIP/AMDGCN、Metal、TPU Mosaic）掌握 ISA、运行时和库。
  • 连接方式：Inductor 为 GPU 生成 Triton，为 CPU 生成 C++。JAX 通过 jax_triton.triton_call 调用 Triton，并通过 XLA FFI 自定义调用调用任意已编译内核。Pallas 下沉到 Mosaic（TPU）或 Mosaic GPU。

XLA 是开源的吗？

  • 编译器是：openxla/xla、StableHLO 和 Shardy 都在 GitHub 上，采用 Apache-2.0。XLA 接收 StableHLO，先运行与目标无关的 pass，再进行目标相关的代码生成。
  • 仓库中的后端：基于 LLVM 的 CPU 和 GPU。NVIDIA 经由 NVPTX；AMD ROCm 在上游运行，自 2026 年起 PR 以 MI350 CI 作为合并门槛。
  • TPU 后端不是：一位 XLA 维护者表示“TPU 后端不开源”；它以 libtpu.so 形式发布，位于 PJRT 插件 API 之后。
  • 因此 TPU 上的 JAX 使用开放的前端和 IR 加一个闭源的设备编译器，这与开源 Triton 之下 CUDA 的 ptxas 和驱动闭源的情况类似。

XLA 与 TileLang 兼容吗？

不直接兼容：TileLang 不是 XLA 后端，XLA 也不生成 TileLang。两者在自定义调用边界处相遇。

内核源码从 PyTorch 调用从 JAX / XLA 调用
Triton原生：Inductor 会生成它；手写内核可直接调用jax-triton 的 triton_call，可在 jax.jit 内使用
TileLang直接对张量调用封装为 XLA FFI 自定义调用。TileLang 的运行时已迁移到 Apache TVM FFI（2025 年 10 月），nvidia/jax-tvm-ffi 可将 TVM-FFI 函数注册给 jax.ffi_call
cuTile—通过 JAX FFI 使用 cuda.tile.jax.cutile_call()

自定义调用对 XLA 是不透明的。它无法跨该内核做融合，其分片、梯度和布局约定都由你负责。
