主机时钟与设备时钟

CPU enqueue → device work → completion notification

包住异步启动的主机计时器可能只测到了入队时间。一对设备事件测量的是排在两个事件之间的工作，而不是请求的每个部分。

提交不等于完成

主机提交的计时可能在 GPU 工作仍在运行时就结束了。在与问题相符的边界上同步。

端到端墙钟时间

测量一个完整的操作时，在开始前和结束后同步相关的设备工作。除非同步本身属于工作负载，否则不要放在内层循环里。

同步本身会消除真实存在的重叠；要说明范围。

冷启动与热执行

阶段潜在开销
构建 / 导出编译与产物生成
首次调用加载、特化和初始化
预热分配器/缓存与趋于稳定
稳定的重复声明的重复计算

分开报告这些阶段。不要在没有解释的情况下丢掉与生产相关的启动开销。

6 / 17

样本分布

median + p95 + minimum + repetition count

使用声明好的百分位约定。小样本的 p95 是有噪声的顺序统计量，不是可靠的服务尾延迟估计。保留原始样本。

7 / 17

构造的重叠示例

elapsed window: 0–10 ms
copy:            0–4 ms
kernel A:        2–7 ms
kernel B:        8–10 ms

时长之和 = 11 ms；忙碌时间的并集 = 9 ms；未覆盖时间 = 1 ms。这是构造示例的算术，不是设备 trace。

关键路径与重叠

把所有事件加起来会重复计算重叠部分。忙碌时间的并集能找出某个范围内未被覆盖的区间，但无法指出是哪个资源或依赖造成的。

利用依赖关系和流/设备标识找出真正的关键路径。

剖析器的扰动

性能剖析可能让工作串行化、重放或受到其他扰动。用聚焦的 trace 做诊断，用不开剖析器的重复运行做主要的计时比较。

内存测量

量含义
逻辑字节算法需要的张量
已分配字节运行时跟踪的存活分配
预留字节分配器持有的内存
峰值取决于重置点和观察区间

常驻状态估计很低，并不排除临时峰值很高。

11 / 17

公平比较

  • 使用相同的计算、有效批大小和质量约束。
  • 对齐分配/拷贝/缓存的范围；记录选中的后端。
  • 让功耗/时钟/温度以及其他作业的干扰保持可见。
12 / 17

先验证正确性再计时

在重复循环之前检查输出和数值容差。训练还要检查梯度和 loss 行为。确保结果被使用，这样预期的工作才真正执行。

13 / 17

带不确定性的加速比

S = baseline_time / changed_time

使用可比较的统计量和原始试验数据。如果多次运行的离散程度覆盖了所声称的收益，就重复实验或说明不确定性，而不是宣称稳定的改进。

常见的失败特征

观察到的现象待检验的假设
第一次调用很慢编译或初始化
设备很快，请求很慢事件之外的主机/队列/传输工作
大量空闲区间依赖、输入或分发的等待
后端变了换了实现或发生了回退

每一行都是假设，不是仅凭计时得出的诊断。

CPU 计时是实测的；区间示例是分析性的。两者都不是 CUDA 基准测试。
