组大小必须匹配硬件的块

格式块缩放因子由谁施加缩放
MXFP8 / MXFP6 / MXFP4 / MXINT8 (OCP MX)32 个元素E8M0（2 的幂）硬件，在原生支持 MX 的芯片上
NVFP4 (Blackwell)16 个元素每块 FP8 E4M3 + 每张量 FP32Tensor Cores
INT4 仅权重（GPTQ、AWQ）由软件选择，常为 128每组 FP16内核，在寄存器中反量化之后

对原生的块缩放格式，块大小由格式和硬件固定；用别的组大小就会离开快速路径。对仅权重的 INT4，组大小是内核契约：更小的组会增加缩放因子的加载和元数据（第 13 讲）。

融合反量化 GEMM：Marlin

W4A16：权重在 HBM 中保持 INT4，只在寄存器里、紧挨着 Tensor Core 指令之前才变成 FP16。

  • 权重和组缩放因子离线重排成内核能高效加载的布局（16×64 的分块连续存放）。
  • 反量化指令和 Tensor Core 指令经过编排，让两条流水线都保持忙碌。
  • 在 A10 上，批大小到 16–32 时接近理想的 4×（相对 FP16）；批大小 128 时约 1.5×，此时 GEMM 变为计算受限。

加速来自搬运更少的权重字节，所以它出现在内存受限的解码阶段。打包布局属于内核：为一个内核打包的检查点不能直接给另一个内核用。

KV 缓存量化是内核契约

  • KIVI（2 位）：键按通道量化，值按 token 量化，因为它们的离群值模式不同。报告的峰值内存最多降低 2.6×，批大小最多增大 4×，吞吐提升 2.35–3.47×。
  • vLLM：kv_cache_dtype 可以是 fp8、fp8_e4m3 或 fp8_e5m2。缩放因子按张量（未校准时为 1.0）或按 KV 头设置；按头的缩放因子需要 FlashAttention 后端和 llm-compressor 校准。使用 FlashAttention 3 时，注意力本身以 FP8 运行，查询也会被量化。
  • 分页的 KV 块容纳固定数量的 token，因此每块字节数 = token 数 × KV 头数 × 头维度 × 2（K 和 V）× 每元素字节数，再加上缩放因子。注意力内核必须读取这种布局。

KV 字节减半会让 KV 流量减半，并让一个块或分块容纳的 token 翻倍：这是线性收益，不是二次收益。长上下文的 KV 存放在 HBM 中，而不是 L2。
