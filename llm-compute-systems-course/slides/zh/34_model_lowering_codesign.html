下沉：模型变成制品

框架图 → 图 IR → 划分与融合 → 库内核 | 生成的内核 → 运行时制品

  • 图编译器决定分组、布局、内存规划和执行顺序。
  • 锚点算子（GEMM、注意力、卷积）通常交给厂商库或手写的内核模板。
  • 长尾算子（归一化、RoPE、逐元素链）通常是生成的代码。
  • 输出把主机程序（调度）与设备二进制配对，由运行时加载。

IREE：一个编译器，多个 HAL 目标

iree-compile model.mlir \
  --iree-hal-target-device=local \
  --iree-hal-local-target-device-backends=llvm-cpu \
  --iree-llvmcpu-target-triple=x86_64-pc-linux-elf \
  -o model.vmfb
  • 稳定的编译器后端：llvm-cpu、vmvx、vulkan-spirv、rocm、cuda、metal-spirv；webgpu-spirv 为实验性。
  • 运行时 HAL 设备（local-sync、local-task、cuda、hip、vulkan、metal）负责运行模块；新驱动可以通过 IREE_EXTERNAL_HAL_DRIVERS 放在主仓库之外。
  • 裸机：用静态库和头文件代替 .vmfb 文件，单线程，无文件 I/O。

TVM：Relax、TensorIR 与 BYOC

  • IRModule 包含 Relax 函数（图）和 TensorIR 函数（循环）。各 pass 对 Relax 算子进行融合、合法化并下沉为 TensorIR，再翻译为 LLVM、CUDA C 或其他目标。
  • BYOC（外部库分派）：FuseOpsByPattern 把匹配的子图包装成组合函数；MergeCompositeFunctions 可选地将其分组；RunCodegen 调用各后端的代码生成器。已注册的后端包括 cuBLAS、CUTLASS 和 cuDNN。
  • 未被认领的算子经过 LegalizeOps 和 FuseOps 正常编译，因此只支持部分算子的芯片也能运行整个模型。
  • MetaSchedule 在目标设备或模拟器上搜索循环调度。它只适用于静态形状的工作负载。

OpenXLA：实现 PJRT，接收 StableHLO

PJRT 插件在稳定的 C API 之后实现设备缓冲区、编译和执行，使 JAX 等框架无需修改即可接入芯片。

  • Google 把 JAX 的 CUDA 后端打包为 PJRT 插件；Apple 的 Metal 插件和 Intel 的 GPU 后端使用相同的接口。
  • Tenstorrent 的 tt-xla 实现了一个 PJRT 设备，并把 StableHLO 图交给自家的 MLIR 编译器（tt-mlir）。
  • 插件所有者仍需编写从 StableHLO 往下的编译器；PJRT 是运行时约定，而不是代码生成器。

新芯片：工作顺序

阶段构建内容出口测试
1. 跑起来驱动、分配器、DMA、队列、事件让一个缓冲区经过一个简单内核往返
2. 一个锚点内核带片上分块双缓冲的 GEMM在预填充和解码形状下接近实测屋顶线
3. 整个模型内存规划、异步分派、层间无主机同步端到端模型在数值上与参考结果一致
4. 编译器集成模式改写为融合内核；按形状选择内核或自动调优未修改的框架代码能运行；没有悄无声息的 CPU 回退
5. 长尾为归一化、RoPE、softmax、采样生成内核性能剖析显示时间花在屋顶线预测的地方

速度来自第 2–3 阶段；覆盖面来自第 4–5 阶段。在你自己的工作负载上测量算子时间占比：Anthony 等人报告在其设置中，GEMM 在中型模型上占延迟的 68%，在大型模型上占 95%。

核查生成的回答

聊天机器人回答中的说法资料实际怎么说
“NVFP4 使用原生 32 元素块”NVFP4 的块为 16 个元素，带 E4M3 缩放和 FP32 张量缩放；OCP MX 格式使用 32 个元素和 E8M0 缩放
“脉动阵列大小为 16×16 到 64×64”TPU MXU 为 128×128，自 v6e 起为 256×256；要逐个目标核实
“更小的 KV 位宽会使 DRAM 流量按平方下降”KV 字节数与位宽成线性关系
“压缩后的 KV 缓存可以常驻 L2”长上下文 KV 远大于 L2；它存放在 HBM 中并以流式读取
“编译器生成所有内核”编译器负责划分和融合；锚点算子通常调用库或 BYOC 代码
“3×3 用 Winograd，其他用隐式 GEMM”这是合理的经验法则，但 Winograd 需要步长为 1，且在大分块和低精度下会损失精度；库会通过实测来选择

练习：协同设计审查

  1. 选取一个解码器配置（隐藏层大小、注意力头数、KV 头数、FFN 大小、词表）和两个目标，例如数据中心 GPU 和手机 NPU。
  2. 对每个 GEMM，分别记录预填充和解码时的 M、N、K，以及它们是否为目标偏好对齐值的倍数。
  3. 为每个目标选择一种权重格式和一种 KV 格式。说明由谁应用缩放：硬件、融合内核，还是单独的转换步骤。
  4. 根据“哪个栈适合哪种芯片？”为每个目标选一条下沉路线，并说明你要实现的集成点。
  5. 列出能证明或否定每个选择的三项测量。
