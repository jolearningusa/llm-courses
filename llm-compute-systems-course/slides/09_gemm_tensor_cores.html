The matrix contract

C[M,N] = A[M,K] B[K,N]

Declare transpose, strides, dtype, accumulation and any epilogue. Different contracts are not interchangeable benchmarks.

2 / 16

Naive repeated reads

A simple output-per-thread kernel repeatedly reads operand values across outputs. The arithmetic is correct but nearby outputs could reuse the same A/B data.

3 / 16

A shared-memory tile

Load A/B tiles → synchronize → accumulate → next K tile → store

Cooperative staging makes operand reuse explicit. Edge tiles need guarded loads and stores.

4 / 16

Worked tile intensity

For a square T×T output tile and K-step of T, ideal operand reads are 2T² elements and work is 2T³ FLOP.

input-only intensity ≈ T / bytes_per_element

Output writes and extra traffic lower whole-operation intensity. This is an analytical tile model.

5 / 16

Registers hold accumulated outputs

Keeping more accumulators can improve reuse, but increases per-thread live state. Tile size choices interact with register/shared-memory limits and available parallel work.

Tensor Core execution

Matrix instructions impose operand-layout, dtype, shape and accumulation requirements. Select a supported path and inspect actual instructions or backend dispatch.

7 / 16

Training and prefill shapes

Large token batches can create substantial M dimension and reuse weights across rows. Large arithmetic work still needs compatible tiles and enough device work.

8 / 16

Decode shapes

Small M can leave output tiles underfilled and make weight traffic or launch/communication latency important. A kernel tuned for a large square GEMM can lose here.

9 / 16

MoE grouped shapes

Tokens per expert vary → many small GEMMs → grouped scheduling

Inspect the distribution, not just average tokens/expert. Routing skew can extend the critical path.

10 / 16

Epilogue fusion

Bias, activation or output conversion can sometimes be fused into the GEMM epilogue. Match semantics and numerical order, and account for any extra live state.

11 / 16

Library baseline

Use a supported optimized framework/library call and record layout, workspace and chosen implementation. A naive student kernel beating an intentionally weak baseline is not enough.
