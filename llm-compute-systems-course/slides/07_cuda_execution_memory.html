Launch hierarchy

Grid → thread blocks → warps → threads

Blocks supply a cooperation/scheduling unit. The launch maps work to this hierarchy; it does not guarantee simultaneous residency of every block.

A row-normalization mapping

one block → one row
thread t → columns t, t + blockDim.x, …

All threads participate in the row reduction, including threads whose first column is outside a short row.

4 / 17

Tail handling

A row length need not be a multiple of the block size. Guard each load/store by its column bound. Keep block-wide barriers on control-flow paths reached by every participating thread.

5 / 17

Coalesced access

Adjacent lanes → adjacent element addresses → grouped memory transactions

Inspect stride and alignment. A convenient logical indexing scheme may generate inefficient physical accesses.

8 / 17

Barrier correctness

A barrier is about a cooperation scope. It is not a universal ordering primitive across all blocks or devices. Document producer/consumer and memory-ordering requirements.

9 / 17

Registers and occupancy

More live values may increase register demand and limit resident work. Higher occupancy is not itself the objective: a reuse-friendly kernel with fewer resident blocks may still run faster.

10 / 17

One block per row limits available work

A small row count creates few blocks, even if each row is long. Splitting a row can increase parallelism but requires a correct partial-result combination and extra costs.

11 / 17

Worked traffic estimate

For D float32 values and D weights, one ideal output pass reads 8D bytes and writes 4D bytes.

ideal baseline = 12D bytes / row

The simple RMSNorm kernel rereads input for output after reduction, so its source-level input traffic is larger. Caches determine HBM traffic.

12 / 17

Latency and bandwidth regimes

Short rows may expose launch/reduction overhead; long rows may expose traffic, register or scheduling constraints. Sweep shape instead of tuning one convenient dimension.

13 / 17

CUDA and HIP portability

A source translation is not a performance proof. Check execution-group assumptions, matrix instructions, shared/local memory and actual backend support for the target.
