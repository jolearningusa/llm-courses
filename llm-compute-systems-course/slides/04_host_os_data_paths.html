Host, OS and data paths

A GPU can wait even when its arithmetic kernels are fast.

Outcomes: trace data ownership, identify omitted host work and design a controlled pipeline intervention.

The data path

Storage → CPU preparation → host buffer → transfer → device kernel

Add queues and ownership between each stage. A throughput problem may be upstream of the GPU.

2 / 16

Latency versus pipeline throughput

A single item traverses dependent stages. A stream of items may overlap preparation, transfer and compute.

Serial item time ≈ sum(stage times)

Ideal steady throughput is bounded by the slowest stage; real queues and contention add costs.

4 / 16

Python and dispatch overhead

Many tiny operations can expose interpreter and launch gaps. Batching, compilation or graph replay can help only when overhead is material and the computation supports the required constraints.

5 / 16

CPU affinity and NUMA

CPU placement and memory locality can affect preparation and transfer. Compare documented placement under the actual topology; do not assume every host buffer is equally close to a GPU.

6 / 16

Pageable and pinned host memory

Pinned memory enables supported asynchronous transfer paths, but pinning itself has costs and consumes a constrained host resource. Include allocation/pinning in end-to-end accounting where it belongs.

Asynchronous copy is not guaranteed overlap

Ready host buffer → supported copy path → stream ordering → consumer

Observe the timeline. Dependencies, device capabilities, buffer lifetime and bandwidth contention determine whether overlap actually occurs.

8 / 16

Memory ownership

Keep source buffers valid until asynchronous transfers finish. Do not overwrite a staging buffer merely because the enqueue call returned. A faster pipeline that races its inputs is incorrect.

9 / 16

Virtual memory and faults

Shared addressability, coherent access and high bandwidth are different properties. Faults and migration can change the observed data path.

Linux HMM
10 / 16

Allocator behavior

Repeated allocation can introduce overhead and change peaks. Reuse buffers where semantics permit, and compare both steady reuse and a realistic allocation-inclusive workload.

11 / 16

Prefetch and backpressure

A queue can hide preparation jitter until it drains. More prefetch increases memory use; an unbounded producer can consume resources without raising throughput.

Measure queue occupancy and memory alongside the achieved rate.

One intervention at a time

  • Find a suspected gap and its upstream dependency.
  • Change preparation, buffer reuse or placement with a matched workload.
  • Verify correctness; compare trace signature and end-to-end result.

Analyze a constructed pipeline budget or inspect a real trace you can obtain. Separate measured evidence from hypothetical phase costs.

A shorter Python region alone does not prove the GPU is less starved.
