Where specialized inference designs can win

  • Regular tensor work can amortize control and keep operands near arithmetic units.
  • SIMT supports flexible per-thread behavior; scheduling, register state and caches have costs and benefits.
  • Modern GPUs combine SIMT with Tensor Cores. “GPU versus tensor hardware” is a false binary.
Jouppi et al., ISCA 2017 · CUDA SIMT guide · CUDA tile guide

Inference changes the optimization objective

  • Serving adds repeated requests, latency constraints and long-lived model/KV state.
  • Prefill offers larger matrix work; small-batch decode may expose weight bandwidth and underfill arrays.
  • Inference demand motivates specialization; training and post-training still matter. Ironwood supports both.

Cost, availability and the software bill

Evaluate cost per accepted output token at a fixed quality and latency target.

  • Include utilization, energy, memory capacity, networking and porting/operations effort.
  • Supply and export restrictions can change procurement choices; BIS tightened advanced-chip controls in January 2025.
  • Domestic supply is a strategic driver, not evidence that one chip is faster.

A systolic PE grid

A processing element (PE) multiplies operands and updates a partial sum. Neighbor links move data in a regular rhythm.

For C = A × B, reuse a tile inside the array instead of fetching each operand again for every multiply.

Reuse against the memory wall

A blocked GEMM performs 2 × BM × BN × K floating-point operations. Reusing A across columns and B across rows avoids repeated HBM reads.

Ideal bytes = sA·BM·K + sB·K·BN + sC·BM·BN

This analytical bound assumes each input is read once and the output written once, with no spills or rereads. Larger tiles improve reuse only while buffers and occupancy remain feasible.

Sze et al. §V-B · Triton GEMM tutorial

Array utilization depends on shape

  • A dense array needs enough independent rows, columns and reduction work to stay busy.
  • Toy mapping: one useful row in a fixed 256-row tile occupies only 1/256 of its rows. This is not a measured chip utilization figure.
  • Batching, different tiling or a vector path can help small decode GEMMs; long-context attention also needs a KV-bandwidth plan.

Huawei Ascend: heterogeneous AI Core pipelines

  • Huawei documents Cube, Vector and Scalar compute units, plus data-movement resources.
  • Local buffers and explicit data movement support reuse; synchronization connects independently executing pipelines.
  • Co-design means mapping GEMM, elementwise work and transfers together, rather than assigning the entire graph to a matrix unit.

This is the documented AI Core abstraction. Unit organization and supported instructions depend on the Ascend product; no universal core count or throughput is assumed.
