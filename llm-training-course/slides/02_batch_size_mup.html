Batch size and hyperparameter transfer

Two questions every run answers before it starts: how big a batch, and what learning rate. McCandlish et al. (2018) predict the useful batch size from the gradient noise; Yang et al. (2022) tune hyperparameters on a small model and copy them to a large one.

Problem: two settings that do not scale on their own

  • Batch size. More sequences per step means more parallel hardware and fewer steps, but past some size each extra example buys almost nothing. Where is that point, and does it move during training?
  • Learning rate and friends. The best values for a 100M model are not the best for a 10B model in the usual parametrization, and the 10B model is too expensive to sweep.
  • Both are paid in compute: a wrong batch wastes GPUs, a wrong learning rate wastes the run.

Method: the gradient noise scale

  • A minibatch gradient is the true gradient G plus noise with covariance Σ / B.
  • The simple noise scale compares the two: Bsimple = tr(Σ) / |G|2 (Eq. 2.9).
  • For SGD, the best step size grows with the batch and then saturates: εopt(B) = εmax / (1 + Bnoise / B) (Eq. 2.6). Below Bnoise, doubling the batch nearly doubles the progress per step; far above, it barely helps.
  • For Adam the paper finds a power law ε ∝ Bα, 0.5 < α < 1, that flattens at large B.

The steps–examples trade-off

Smin: fewest steps (huge batches). Emin: fewest examples (tiny batches). Bcrit = Emin / Smin; at Bcrit a run takes twice the minimum of both. Lab L0 computes this curve.

Problem 2: the best learning rate moves with width

  • In the standard parametrization (SP), the best learning rate for an MLP shifts by about an order of magnitude as width goes from 256 to 8,192 (Fig. 3).
  • So a sweep on a small model gives the wrong answer for the large one, and a sweep on the large one is unaffordable.
  • μP (the maximal update parametrization) rescales initialization, per-layer learning rates and multipliers with width so that each layer's update stays the same size as the model widens. Then the optimum stays put.

Impact and limits

  • What transfers: learning rate, initialization scale and multipliers across width; depth, batch size and sequence length were checked on Transformers only.
  • What does not: regularization such as dropout and weight decay, which depends on data size; depth transfer is incomplete, and does not work for Post-LN Transformers.
  • A second opinion: Wortsman et al. (deck 03) find μP keeps the best learning rate stable across sizes but does not make training less sensitive to it.
  • Both papers move tuning from the expensive run to cheap ones: measure the noise scale and sweep on a proxy, then train once.
