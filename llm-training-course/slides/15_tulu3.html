An open post-training recipe end to end: Tülu 3

Allen AI's Tülu 3 (2024) takes Llama 3.1 base models through SFT, DPO and reinforcement learning with verifiable rewards, and releases the data, code and evaluations. This deck follows its SFT stage closely and the mechanics every SFT run needs: the loss mask, packing and how the loss is averaged.

Problem: post-training recipes were closed

  • Open base models were close to closed ones; open post-trained models lagged, and the recipes behind the strongest chat models were not published.
  • Post-training is many choices at once: which prompts, which answers, which stages, which hyperparameters, and which evaluations decide.
  • Tülu 3 publishes every one of them, with ablations, so each choice can be checked.

Evaluation first, and decontaminated

  • Development and unseen suites: recipes are tuned on development evaluations; a separate set of unseen evaluations is checked only at the end, to measure how much the recipe overfit its own benchmarks.
  • Decontamination: 8-gram matching of training prompts against every evaluation. A training set overlapping more than 2% of an evaluation's instances counted as contaminated; sets contaminated with unseen evaluations were removed.
  • Evaluations run through the open OLMES toolkit. Contamination and benchmark design are taught in deck 32.

Mechanics 1: the loss mask

L = − Σt mt log p(xt | x<t) / Σt mt
  • mt = 1 on the assistant's reply and the end token that closes it, 0 on the system and user turns and the role markers the template always writes. The model learns to answer, not to imitate users.
  • The template must be identical in training and inference, down to whitespace. Tülu 3 found that the newline before the model's response mattered, and removed it (replacing it with an end token scored 53.0 against 52.8).
  • Templates and special tokens: architecture deck 11. Lab L3: a loss on every token cut held-out exact match from 0.87 to 0.29.

Mechanics 2: packing without leaking

  • Padding wastes compute when lengths vary: 40% of tokens in Lab L3's padded batches, 15% packed.
  • Packing is exact only with a block-diagonal causal mask and positions that restart per example; then the loss equals the unpacked loss (Lab L3 checks it).
  • Naive packing (plain causal mask, running positions) lets examples see each other in training but not at inference: held-out exact match fell to 0.17 in Lab L3.

Mechanics 3: how the loss is averaged

  • Averaging the loss over padding, or taking a mean per micro-batch and then averaging those means, weights tokens unequally: a short example in a small micro-batch counts more. Results then change with the gradient-accumulation setting.
  • Fix: sum the loss over trained tokens and divide by the total count across all micro-batches and devices, or use a summed loss with a matching learning rate. Tülu 3 chose a sum loss; Lab L3 shows that only sum-then-divide reproduces the full-batch mean.
  • Tülu 3 8B SFT: learning rate 5 × 10−6, linear schedule, 3% warm-up, effective batch 128, 2 epochs, sequences up to 4,096 tokens.
  • Seeds matter: 8B runs ranged 59.8–60.1 and 70B runs 70.0–72.6 by seed; averaging checkpoints ("soups") did not always beat the best single run, so the best single run shipped.

After SFT: preferences and verifiable rewards

  • DPO on 271,409 preference pairs for 8B and 334,302 for 70B, built from on-policy and off-policy answers judged by a model. DPO is deck 22.
  • RLVR: reinforcement learning where the reward is a program's check (a correct math answer, a satisfied format constraint), applied to GSM8K, MATH and IFEval-style prompts. It improved those skills; RLVR is deck 27.
  • Each stage starts from the previous checkpoint, and each is judged on the same development suite.
