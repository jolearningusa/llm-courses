A language model reads text as a sequence of tokens. Before the model sees anything, a tokenizer splits the text into pieces and maps each piece to an integer. Frequent words become a single token, while rare words are spelled out from smaller pieces. The model never sees letters directly; it only sees the integers that the tokenizer produced. This is why the tokenizer decides how long a document is, how much text fits in the context window, and how much each request costs. A good tokenizer for one language can be a poor tokenizer for another. If a language is rare in the training data of the tokenizer, its words are split into many short pieces, and the same sentence needs more tokens. The attention layers then do more work for the same meaning, and the context window holds less of it. Byte-level tokenizers start from the 256 possible byte values, so any string can be encoded, and decoding always returns the original text.
