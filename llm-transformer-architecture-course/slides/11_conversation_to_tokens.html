Problem: a decoder only sees one sequence

  • A decoder-only model (deck 02) reads a single stream of token IDs and predicts the next one. It has no notion of "user", "assistant" or "tool".
  • GPT-1 already encoded tasks with start, delimiter and extract tokens (deck 02); T5 with text prefixes (deck 04); GPT-3 with few-shot examples in the prompt (deck 05).
  • Chat models need the same thing, made precise: who said what, where a turn ends, where the model should start writing and when it should stop.

Why roles exist: instruction tuning

  • InstructGPT fine-tuned GPT-3 to follow instructions. Labelers preferred outputs of the 1.3B InstructGPT to those of the 175B GPT-3, with 100× fewer parameters.
  • The training data are prompts and responses, so the format that separates them is part of what the model learns. A chat template is that format, fixed per model.

What the template decides

  • Special tokens. <|eot_id|> and <|im_end|> are single vocabulary entries that no merge can produce (deck 07). User text cannot forge them, if the serving stack tokenizes user text separately.
  • Generation prompt. Both templates end with an open assistant header; the model writes from there and stops when it emits its end-of-turn token.
  • Defaults. Qwen2.5's template inserts a default system prompt ("You are Qwen, created by Alibaba Cloud. You are a helpful assistant.") when none is given.
  • Tools. Tool schemas and calls are more text in the same stream; Qwen2.5 wraps calls in <tool_call> tags.
  • A template mismatch between training and serving silently degrades a model. Lab L4 renders both templates by hand and checks them.

Training side: packing and masks

Pre-training packs many documents into each fixed-length sequence to avoid padding. Llama 3 adds a mask "that prevents self-attention between different documents within the same sequence"; the authors found it mattered for continued pre-training on very long sequences. In chat fine-tuning, the loss is usually applied to assistant tokens only.

Evidence: windows are not used evenly

  • Liu et al. tested multi-document question answering and synthetic key-value retrieval, moving the relevant information through the context.
  • Accuracy is U-shaped: highest when the relevant passage is at the start or the end, and clearly lower when it sits in the middle.
  • The drop holds "even for explicitly long-context models". A longer window does not guarantee the model uses all of it.
  • Practical rule that follows: put instructions and the most relevant material near the start or the end of the context.

Modeling impact

  • The template is part of the model. Its special tokens are trained embeddings; its layout is what instruction tuning learned. Change it and quality drops.
  • Every turn re-enters the window. A long conversation resends all previous turns; the KV cache (deck 12 onward) and prefix caching (compute course) make that affordable.
  • Position in the window matters for what the model retrieves, beyond whether the content fits.
  • Agents. Tool results, memory and retrieved documents are all just text in this stream. The AgentOS course studies how to manage it.
