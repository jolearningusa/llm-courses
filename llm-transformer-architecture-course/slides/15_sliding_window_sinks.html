Sliding windows and attention sinks

Problem: cost that grows without bound

  • Full causal attention costs O(n) per generated token and keeps a KV cache that grows with every token (decks 12–13).
  • A chat or an agent that runs for hours cannot keep every token. Simply dropping old keys ("window attention") is the obvious fix.
  • Two questions: does a model with a window still see far enough, and what breaks when old keys are dropped from a model trained with full attention?

Rolling buffer cache and chunked prefill

  • The cache holds W entries; the key and value of position i go to slot i mod W, overwriting the oldest. At 32K tokens this cuts cache memory 8× without hurting quality, according to the paper.
  • The prompt is known in advance, so it is pre-filled into the cache in chunks of size W; each chunk attends to itself causally and to the cache through the window.
  • Result reported by the paper: Mistral 7B outperforms Llama 2 13B on most benchmarks in its Table 2 (MMLU 60.1% against 55.6%, GSM8K 52.2% against 34.3%); Llama 2 13B is slightly ahead on NaturalQuestions (29.0% against 28.8%).

StreamingLLM: the attention sink

  • Run a model trained with full attention under window attention: perplexity is fine until the first tokens are evicted, then explodes. Llama-2-13B: 5,158 perplexity with a pure window, 5.40 when the first four tokens are kept.
  • Inspecting attention maps shows a large share of every head's attention on the initial tokens, whatever they say. The authors call them attention sinks.
  • Their explanation: softmax must sum to one, so a head with nothing to attend to still has to put its weight somewhere. The first tokens are visible to every later token, so training makes them the dump.

StreamingLLM: keep the sinks, roll the rest

  • Positions are assigned by place in the cache, not in the original text, so keys are cached before RoPE and rotated at each step.
  • Llama-2, MPT, Falcon and Pythia model more than 4 million tokens stably this way, with no fine-tuning.
  • Up to 22.2× faster per token than a sliding window that recomputes its KV states.
  • Pre-training a 160M model with one learnable sink token prepended to every sample: streaming then works with that single token.

Modeling impact

  • Bounded cost. A window caps per-token compute and cache size; depth carries information further than W.
  • Not all layers need the full context. Mixing windowed and full layers keeps long-range retrieval in some layers and saves memory in the rest.
  • Softmax needs a place to put nothing. Sinks show that attention learns a "no-op" target; architectures now provide one on purpose.
  • A stream is not a memory. StreamingLLM keeps the model fluent over millions of tokens, but evicted tokens are gone; it does not extend what the model can recall.

Afterlife

  • Gemma 2: alternates local sliding-window layers (4,096 tokens) and global layers (8,192 tokens).
  • Gemma 3: five local layers per global layer, with a 1,024-token window, to cut KV memory at long context.
  • gpt-oss: alternates banded-window layers (128 tokens) and dense layers, and gives each head a learned bias in the softmax denominator so it can attend to nothing, which the model card relates to attention sinks.
  • Not everyone adopted it: Qwen2.5 7B's config carries sliding_window but sets use_sliding_window to false (lab L0 configs).
