Problem: long context is mostly attention

  • At 64K tokens, attention dominates the cost of every forward pass and every decoding step: each query reads every key (decks 14–16).
  • Most attention weight in a long context falls on a few tokens, so most of the work is wasted. Earlier sparse methods exploited this only at inference, on a model trained densely, or used patterns that do not run fast on GPUs.
  • Goal: sparsity that is trainable end to end and fast in real kernels.

NSA: three branches per query

  • Compressed: blocks of 32 keys (stride 16) summarized into one coarse token each: a cheap view of the whole context.
  • Selected: the 16 most important blocks of 64 keys, scored with the compressed branch's attention, always including the first block and 2 local ones.
  • Sliding window: the last 512 tokens. A learned sigmoid gate per branch mixes the three outputs.
Yuan et al. 2025, arXiv:2502.11089 §3.2–3.3, §4.1 · bibliography
3 / 10

NSA: built for the hardware

  • Selection is shared by all query heads in a GQA group (deck 13): scores are summed across the group, so one set of key blocks is loaded once for every head that uses it.
  • Blocks are contiguous, so loads are coalesced and the inner loop uses tensor cores, like FlashAttention (deck 14).
  • Every branch is differentiable, so the model learns where to look during pre-training; nothing is bolted on afterwards.

DSA: a lightning indexer and top-k tokens

It,s = Σj wt,j · ReLU(qt,j · ks)

  • A small indexer with few heads, runnable in FP8, scores every earlier token s for query t. ReLU instead of softmax, for throughput.
  • Only the top k = 2,048 tokens by index score enter attention. Selection is per token, not per block.
  • Built on MLA (deck 16) in its MQA mode, so each selected latent is shared by all query heads.
  • Core attention becomes O(L·k) instead of O(L²); the indexer is still O(L²) but far cheaper per pair.
DeepSeek-V3.2, arXiv:2512.02556 §2.1, §2.3, Eqs. 1–2 · bibliography
6 / 10

DSA: added to a trained model

  • Warm-up: 1,000 steps of 16 × 128K-token sequences; sparse stage: 15,000 steps of 480 × 128K. The indexer learns to imitate the dense attention distribution, then the model adapts to seeing only the selected tokens. The indexer's input is detached: it learns only from its KL loss.
  • Result (DeepSeek-V3.2-Exp): no substantial degradation against V3.1-Terminus on short- or long-context benchmarks, with much lower cost per token at long positions (H800 estimates).
DeepSeek-V3.2, arXiv:2512.02556 §2.1.1–2.3, Figure 3 · bibliography

Modeling impact

  • Sparsity became trainable. Both papers learn the selection, NSA from scratch and DSA by continued training, instead of applying a fixed pattern at inference.
  • Attention cost per token stops growing with context for the main attention; a cheap scorer still looks at everything.
  • The KV cache is unchanged. All keys are kept; sparsity saves reads and compute, not memory. Compare with windows (deck 15), which drop keys, and recurrences (decks 23–25), which never store them.
  • Designed with the kernel. Block selection shared by GQA groups (NSA) and selection in MLA's MQA mode (DSA) both exist to make memory access efficient.

Afterlife

  • DeepSeek-V3.2 ships DSA as its attention; the family deck (deck 31) places it after V3 and R1.
  • The three-branch idea (coarse summary, selected detail, local window) is a template for other learned sparse attention designs.
  • Sparse attention, sliding windows and linear-attention hybrids now compete for the same job: long context at bounded cost.
