Problem: next-token prediction is short-sighted

  • Since GPT (deck 02), language models are trained to predict one token ahead. Teacher forcing makes that easy: most next tokens are locally obvious.
  • The authors argue the signal is spent on easy local transitions and too little on the few "choice points" that decide the rest of a passage.
  • Separately, decoding emits one token per forward pass, which leaves the GPU memory-bound (deck 12).

Change: n heads on a shared trunk

Loss = Σi=1..n cross-entropy of token t+i given tokens ≤ t. n = 1 is ordinary training. Heads run one after another in the forward and backward pass, so peak memory stays O(V + d) instead of O(nV + d).

Evidence: faster decoding

  • Self-speculative decoding. The extra heads propose tokens t+2 … t+n; the next forward pass verifies them, keeping the longest correct prefix. No separate draft model.
  • A 7B 4-token model decoded 3.0× faster on code and 2.7× on text; the 8-byte model 6.4×.
  • Speculative decoding never changes the output distribution: verification rejects wrong drafts.
Gloeckle et al. 2024, arXiv:2404.19737 §3.2, Tables S2–S3 · bibliography

Evidence: where it does not help

  • Natural-language multiple-choice benchmarks: n = 2 matches the baseline, n = 4 regresses slightly.
  • Summarization: both n = 2 and n = 4 improve ROUGE-L.
  • Small models: a 2-token loss helps induction heads form below about 30M non-embedding parameters; the advantage is gone at about 100M.
  • The paper's explanation: n-token prediction weights choice points by about n(n+1)/2 against n for inconsequential tokens, so the model invests in decisions that matter later.
Gloeckle et al. 2024, arXiv:2404.19737 §3.7, §4.1, §5.1 · bibliography

Afterlife: DeepSeek-V3 and Qwen3-Next

  • DeepSeek-V3 trains with a sequential MTP module (depth 1) that predicts one extra token while keeping the full causal chain: the module sees the main model's representation and the embedding of the next token. The module is dropped or reused for speculative decoding at inference.
  • Unlike Gloeckle et al.'s independent heads, each extra prediction depth is a full Transformer block chained on the previous depth, sharing the embedding and output head with the main model. DeepSeek-V3 uses depth D = 1.
  • Qwen3-Next includes native MTP for speculative decoding (deck 25).

Modeling impact

  • The objective is part of the architecture. Extra heads cost little in training and change what the trunk learns to represent.
  • Decoding without a draft model. The same weights draft and verify, attacking the memory-bound decoding step from the objective side, where Part III attacked it through the cache.
  • Scale-dependent. Harmful for small models, helpful for large ones and for code: a result to re-test, not assume, for a new domain.
