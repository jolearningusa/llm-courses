Flamingo and LLaVA

Two ways to give a frozen or pre-trained language model eyes. Flamingo (DeepMind, 2022) inserts gated cross-attention layers into a frozen LM. LLaVA (2023) projects image features into the LM's input embeddings with one matrix and fine-tunes on GPT-4-written instructions.

Problem: reuse a strong LM without breaking it

  • Training a vision-language model from scratch throws away the knowledge in a pre-trained LM, and costs as much as a new LM.
  • Fine-tuning the whole LM on image-text data risks catastrophic forgetting of language skills.
  • Flamingo's goal: few-shot learning from a handful of interleaved image-text examples, as GPT-3 does for text (deck 05). LLaVA's goal: a chat assistant that follows instructions about an image.

Flamingo: the architecture

  • The new layers' output is multiplied by tanh(α), with α initialized to 0, so at the start the model is the pre-trained LM.
  • Each text token cross-attends only to the image just before it; earlier images reach it through the LM's self-attention. Training uses up to 5 images per sequence; evaluation uses up to 32 shots.
  • Sizes: Flamingo-3B, 9B and 80B, built on Chinchilla 1.4B, 7B and 70B (deck 06).

LLaVA: one projection and synthetic instructions

  • No new attention layers: image patch features become ordinary input tokens of the LLM (early in the sequence, late in the pipeline).
  • Data: text-only GPT-4 was given COCO captions and bounding boxes and asked to write 158K samples: 58K conversations, 23K detailed descriptions, 77K complex-reasoning answers.

Modeling impact

  • Two late-fusion designs. Cross-attention adapters (Flamingo; Llama 3's vision adapters, deck 29) keep the LM untouched. Input-token projection (LLaVA) is simpler and became the most copied open recipe.
  • Gated, zero-initialized additions let new layers enter a trained network without disturbing it; DiT's adaLN-Zero uses the same idea (deck 39).
  • Synthetic instruction data. LLaVA showed that a strong text model can write the training data for a multimodal one.
  • Images cost context. Every image becomes tens to hundreds of tokens in the KV cache; resamplers and pooling exist to keep that number down (Gemma 3 uses 256, deck 32).
