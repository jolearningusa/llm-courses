Who this course is for

  • Engineers and students who use LLMs and want to read a model card, a config.json or a technical report and know what every choice does.
  • Prerequisites: Python, NumPy or PyTorch, linear algebra (matrix products, softmax), and basic probability.
  • All labs run on a laptop CPU with tiny models. No GPU and no model download beyond small config files.
  • Outcome: given a new model paper, say which known component it changes, what problem that change targets, and what it costs.

How every paper deck is built

  1. Problem. What was failing or too expensive when the paper was written.
  2. Change. The architectural idea, with the equation or diagram that defines it.
  3. Evidence. What the paper measured, on what scale, against which baseline.
  4. Modeling impact. Effect on quality, parameters, FLOPs, KV memory and what it made possible.
  5. Afterlife. Which later models kept, changed or dropped it, checked against their configs.

Direct sequels (GPT-1 and GPT-2, Mamba and Mamba-2) share a deck. Kernels and serving are left to the compute course.

Where this course stops

  • Here: what the model computes and why it was designed that way.
  • Efficient LLM Computing Systems: how it runs fast, including attention kernels, KV paging, MoE execution, quantization and serving.
  • LLM AgentOS: what an agent puts into the context window and how it manages memory across turns.
  • Training recipes (data, RLHF, RL for reasoning) appear only where they explain an architecture choice, as in DeepSeek-R1 reusing the V3 architecture.

How to use the decks

  • One paper deck per session, then its lab. Read the paper sections named on each slide before class.
  • When a slide cites a number, it gives the table or section. Check it there, and against the released config when one exists.
  • Assessment: labs 50%, two paper critiques 20%, capstone 30%. The capstone designs a model for a given parameter, KV-memory and modality budget and defends each choice with the papers.
