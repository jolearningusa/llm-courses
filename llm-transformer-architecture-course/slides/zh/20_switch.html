问题：MoE 复杂、通信成本高、不稳定

  • 早期的 MoE 工作把每个 token 路由到 k ≥ 2 个专家，直觉是路由器至少要比较两个专家才能学习。
  • MoE 模型难以用低精度训练，设备间通信量大，也没能取代 T5 这样的稠密模型。
  • 问题：保留收益的最简单的稀疏层是什么？

改动：top-1 路由

  • 每个 token 一个专家：路由计算更少，最小专家容量是 top-2 的一半，通信也更简单。
  • 作者发现 k = 1 保持了模型质量。

专家容量与丢弃的 token

容量 = （每 batch token 数 ÷ 专家数）× 容量因子。超出专家容量的 token 通过残差连接跳过该层。论文比较了 1.0、1.25 和 2.0 三种因子；有均衡损失时，通常被丢弃的 token 少于 1%。

改动：更简单的均衡损失

loss = α · N · Σi fi · Pi , α = 10−2

  • fi：分派到专家 i 的 token 比例（不可微）。Pi：专家 i 的平均路由概率（可微）。
  • 均匀路由时 fi = Pi = 1/N，求和再乘以 N 等于 1，即其最小值。把 token 集中到少数专家会使它增大。
  • 作者把 α 从 10−1 扫到 10−5；10−2 能均衡负载而不损害主损失。
Fedus et al. 2021, arXiv:2101.03961 §2.2, Eq. 4 · 参考文献
5 / 10

改动：让它能训练

  • 选择性精度。模型用 bfloat16 运行，但路由器在本地用 float32 计算：速度接近 bfloat16，训练稳定。
  • 更小的初始化。把默认权重初始化乘以 0.1；质量提高，各次运行之间的方差下降。
  • 专家 dropout。微调时专家内部用 dropout 0.4，其他地方用 0.1；专家参数多，而每个专家的样本少。

建模影响

  • 稀疏性成为一条缩放轴。在每 token 计算量固定时，增加专家持续降低损失；参数量和 FLOPs 成了两个独立的旋钮。
  • 稳定性是架构的一部分。路由器精度和初始化尺度与层一起列出，而不是当作训练细节。
  • 容量是一种权衡。更高的容量因子丢弃的 token 更少，但把计算浪费在填充上；推理时则希望完全不丢弃。
  • 编码器-解码器时代。Switch 构建在 T5 之上；仅解码器的 MoE LLM 随 Mixtral 和 DeepSeek 而来（讲义 21–22）。
Fedus et al. 2021, arXiv:2101.03961 §2–3 · 参考文献

后续

  • fi · Pi 均衡损失成为辅助损失的标准形式；DeepSeekMoE 的专家级均衡损失也是同样的 fi · Pi 形式（讲义 22）。
  • top-1 路由本身没有成为 LLM 的默认做法：Mixtral 用 top-2，DeepSeek 和 Qwen 从许多小专家中路由到 8 个，gpt-oss 从 32 或 128 个中路由到 4 个。
  • float32 路由器和容量因子仍是标准的训练做法。
