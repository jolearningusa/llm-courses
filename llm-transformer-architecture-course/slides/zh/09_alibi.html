问题：模型超过训练长度就失效

  • 训练代价随序列长度增长，所以人们倾向于短训练、长运行。
  • 作者直接测量了外推能力。正弦编码在训练长度之外只略有提升，随后就变差。旋转编码好一些，但仍然不够。
  • T5 的可学习相对偏置外推更好，但在他们的设置中训练速度至少比正弦模型慢一倍。
  • 目标：一种能外推、训练时没有额外代价的位置方法。

改动：每个头一个固定的线性惩罚

softmax(qi Kᵀ + m · [−(i−1), …, −2, −1, 0])

  • 任何地方都没有位置嵌入。唯一的位置信号是加到注意力分数上的偏置，与查询和键之间的距离成正比。
  • 斜率 m 是固定的而不是学出来的，每个头不同：一个等比数列。8 个头时斜率为 1/2, 1/4, …, 1/256。
  • 斜率大的头主要看最近的 token；斜率小的头仍能看到很远。

证据

  • 一个 1.3B 参数、在 1,024 token 输入上用 ALiBi 训练的模型，在 2,048 长度上评估时，与在 2,048 token 上训练的正弦模型困惑度相当。
  • ALiBi 模型训练快约 11%，内存少约 11%。
  • 当评估长度远超训练长度时，ALiBi 的困惑度继续改善或保持平稳，而其他方法变差。
  • 同样的斜率在所测试的各文本领域和模型规模上都有效，无需按模型调整。

外推的实质是什么

  • 论文自己的分析：较长评估长度下的收益很大一部分来自“开头 token 诅咒”。把文本切成不重叠的块评估时，每块开头的 token 上下文很少；块越长，这样的 token 越少。
  • 用滑动窗口评估（每个预测都有完整上下文）时，ALiBi 的困惑度随输入增长大致持平。它并没有明显用上额外的远处 token。
  • 作者把这作为假设提出。它预示了“Lost in the Middle”（讲义 11）：往窗口里塞更多 token，不等于用上了它们。

建模影响

  • 近因先验。每个头都被推向附近的 token，这适合语言建模，也是它能平稳外推的部分原因。
  • 没有参数，不进入残差流，每个分数加一次偏置。FlashAttention 式的算子可以把它融合进去。
  • 长程检索受损。固定的线性惩罚使模型很难尖锐地关注很远处的某一个 token，而这正是后来评判长上下文模型的任务。

后续

  • 2022–2023 年有若干开源模型使用 ALiBi，包括 BLOOM 和 MPT。
  • 取而代之成为标准的是 RoPE 加上上下文扩展方法（讲义 10）：它保留尖锐的长程检索，并能在预训练后被拉伸。
  • 廉价距离偏置的思想以滑动窗口和局部注意力（讲义 15）的形式回归，也出现在把 RoPE 层与无位置层混合的模型中（Llama 4，讲义 29）。
  • ALiBi 在评估上的教训延续了下来：衡量长上下文能力要用需要远处 token 的任务，而不只是困惑度。
