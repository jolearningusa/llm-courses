问题：无限增长的代价

  • 完整的因果注意力每生成一个 token 代价为 O(n)，并保留一份随每个 token 增长的 KV 缓存（讲义 12–13）。
  • 运行数小时的聊天或智能体无法保留所有 token。直接丢弃旧的键（“窗口注意力”）是显而易见的办法。
  • 两个问题：带窗口的模型是否仍看得够远？从用完整注意力训练的模型中丢弃旧键时，什么会坏掉？

滚动缓冲区缓存与分块预填充

  • 缓存保存 W 个条目；位置 i 的键和值写入槽位 i mod W，覆盖最旧的。论文称在 32K token 时这使缓存内存减少 8 倍而不损失质量。
  • 提示是预先已知的，所以以大小为 W 的块预填充进缓存；每块对自身做因果注意力，并通过窗口关注缓存。
  • 论文报告的结果：在其表 2 的大多数基准上，Mistral 7B 胜过 Llama 2 13B（MMLU 60.1% 对 55.6%，GSM8K 52.2% 对 34.3%）；在 NaturalQuestions 上 Llama 2 13B 略好（29.0% 对 28.8%）。

StreamingLLM：注意力汇点

  • 让用完整注意力训练的模型在窗口注意力下运行：在最初的 token 被淘汰之前困惑度正常，之后就爆炸。Llama-2-13B：纯窗口困惑度 5,158，保留前四个 token 时为 5.40。
  • 查看注意力图会发现，每个头都有很大一部分注意力落在开头的 token 上，不管它们的内容是什么。作者称之为注意力汇点（attention sink）。
  • 他们的解释：softmax 之和必须为 1，所以一个无处可关注的头仍要把权重放在某处。开头的 token 对之后的每个 token 都可见，于是训练让它们成为倾倒处。

StreamingLLM：保留汇点，其余滚动

  • 位置按在缓存中的位置分配，而不是按原文中的位置，所以键在施加 RoPE 之前缓存，每一步再旋转。
  • Llama-2、MPT、Falcon 和 Pythia 用这种方法能稳定地建模 400 万以上的 token，无需微调。
  • 每 token 比重算 KV 状态的滑动窗口最多快 22.2 倍。
  • 预训练一个 160M 模型时在每个样本前加一个可学习的汇点 token：之后流式推理只用这一个 token 就能工作。

建模影响

  • 有界的代价。窗口限制了每 token 的计算和缓存大小；深度把信息传得比 W 更远。
  • 不是每一层都需要完整上下文。把窗口层和完整层混合，可以在部分层保留长程检索，在其余层节省内存。
  • softmax 需要一个放“空”的地方。汇点表明注意力会学出一个“无操作”目标；现在的架构会有意地提供一个。
  • 流不是记忆。StreamingLLM 让模型在数百万 token 上保持流畅，但被淘汰的 token 就消失了；它并没有扩展模型能回忆的内容。

后续

  • Gemma 2：局部滑动窗口层（4,096 token）与全局层（8,192 token）交替。
  • Gemma 3：每个全局层配五个局部层，窗口 1,024 token，以降低长上下文时的 KV 内存。
  • gpt-oss：带状窗口层（128 token）与稠密层交替，并给每个头在 softmax 分母中加一个可学习的偏置，使它可以什么都不关注；模型卡把这与注意力汇点联系起来。
  • 并非所有模型都采用：Qwen2.5 7B 的配置中有 sliding_window，但把 use_sliding_window 设为 false（实验 L0 的配置）。
