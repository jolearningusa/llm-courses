问题：解码受限于内存而不是算术

  • 训练时所有位置并行处理。生成时一次产生一个 token，每一步都要在每一层重读之前所有 token 缓存的键和值。
  • Shazeer 统计了多头注意力一个解码步的内存访问量与算术量之比：对 n 个缓存 token、模型宽度 d 和 batch b，该比值为 Θ(n/d + 1/b)。
  • 当上下文 n 接近 d，或 batch 很小时，比值接近 1，这一步在等内存带宽。随上下文增长的是缓存，而不是权重。

改动：一个键头和一个值头

  • 查询保留 h 个头。键和值只投影一次（宽度 dk），由所有头共享。
  • 内存与算术之比变为 Θ(1/d + n/(dh) + 1/b)：n/d 项缩小为原来的 1/h。

建模影响

  • 缓存成为设计目标。MQA 之前，注意力按质量和训练 FLOPs 评判。之后，每 token 的 KV 字节数成为每种架构的一项核心指标（第三部分，实验 L0）。
  • 参数在转移。K 和 V 的投影各自从 d×d 缩小到 d×dk；论文把省下的参数用来加宽 FFN。
  • 代价是质量略有下降，并且模型必须从一开始就用 MQA 训练。讲义 13 去掉了这两个限制。
  • 这个想法与块的其余部分无关：它可以与 RoPE（讲义 08）、滑动窗口（讲义 15）和 MoE（第五部分）组合。

后续

  • PaLM（2022）和 Gemma 2B 使用多查询注意力。Gemma 的 2B 检查点有 8 个查询头和 1 个 KV 头；它的 7B 检查点保留了多头注意力。
  • 大多数后来的开源模型选择了讲义 13 的折中方案：Llama 2 34B 和 70B、Llama 3、Mistral 7B 和 Qwen2.5 都使用有多个 KV 头的分组查询注意力。
  • DeepSeek 走了另一条路，压缩缓存而不是共享它（MLA，讲义 16）。
