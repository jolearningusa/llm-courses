问题：Kaplan 的分配对吗？

  • 按照 Kaplan 等（讲义 05）的结论，大模型无论多大都在约 300B token 上训练：GPT-3 175B、Gopher 280B。
  • Kaplan 的大多数实验用的是同一个固定长度的学习率调度，所以训练 token 较少的小模型从未得到与其长度匹配的调度。
  • 问题：给定 FLOP 预算 C，什么样的模型规模 N 和 token 数 D 能使最终损失最小？

改动：对最优点的三种估计

  1. 训练曲线上的最小值。每种规模用几种长度的调度训练；在每个 FLOP 数上取达到的最低损失。
  2. 等 FLOP 曲线。对九个固定预算改变模型规模；每条曲线都有明确的最小值。
  3. 参数化拟合。用 L(N, D) = E + A / Nα + B / Dβ 拟合所有实验，并在 C ≈ 6ND 下求最小值。

超过 400 个模型，参数从 70M 到 16B 以上，在 5B 到 500B token 上训练。

建模影响：没有新层，只有新比例

  • 更小的模型，更多的数据。以四分之一的参数达到同等质量，意味着每个 token 的推理 FLOPs 和权重内存都只有四分之一。
  • 数据成为瓶颈。对 1T 参数的模型，每个参数 20 个 token 就是 21T token。数据质量、去重和多语言覆盖成为头等设计工作。
  • 架构比较需要匹配预算。只有在相同计算和数据下胜出，一个设计才算更好：这是之后每份论文讲义都要检查的标准。

后续：超越计算最优

  • Chinchilla 最小化的是训练计算量。一个服务数百万用户的模型，其成本以推理为主，所以值得把更小的模型训练得久得多。
  • LLaMA（2023）明确这样说：它的 7B 模型在 1T token 之后仍在进步，远超计算最优点；65B 模型看了 1.4T token。
  • Llama 3 8B 在超过 15T token 上训练，接近每个参数 2,000 个 token。
  • 第七部分会用这条规律审视每个家族的 token 预算；MoE（第五部分）改变了核算方式，因为每个 token 只有部分参数被激活。
