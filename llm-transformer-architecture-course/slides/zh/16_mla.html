MLA：多头潜在注意力

DeepSeek-AI，2024（DeepSeek-V2）。每个 token 只缓存一个小的潜在向量，而不是每个头的键和值，再从它重建各个头。缓存比 GQA 更小，论文报告的质量还好于多头注意力。

问题：共享头会牺牲质量

  • MQA 和 GQA（讲义 12–13）让头共享键和值来缩小缓存。不同的 KV 头变少了，质量也有所损失。
  • DeepSeek-V2 的目标是 128K 上下文，以及廉价地服务一个 236B 参数的 MoE 模型（每 token 激活 21B）。它的前身 DeepSeek 67B 使用的缓存大得多。
  • 问题：能否压缩缓存而不是共享它，让每个头保留自己的键和值？

改动：对 K 和 V 做低秩联合压缩

  • 只缓存潜在向量 ctKV（外加一个小的位置键，见第 5 页）。每个头的键和值由它向上投影得到。
  • 查询也被压缩（到 d′c = 1,536）。这节省的是训练时的激活内存，而不是缓存。

  • 矩阵乘法满足结合律：WUK 可以并入查询投影，WUV 可以并入输出投影。

改动：解耦的 RoPE

  • RoPE（讲义 08）把键乘以一个依赖位置的旋转。放在 WQ 和 WUK 之间时，这个旋转会阻止上面的吸收，每一步都必须重算所有过去 token 的键。
  • 解决办法：把位置放在一个单独的小部分中。每个头多一个宽度为 dhR = 64 的查询部分 qR，所有头共享一个宽度 64 的旋转键 kR。
  • 分数 = 内容部分（经潜在向量）+ 位置部分（经 RoPE）。缓存保存 cKV 和 kR：每 token 每层 512 + 64 = 576 个数。

证据

  • 与 DeepSeek 67B 相比：KV 缓存减少 93.3%，最大生成吞吐量提高到 5.76 倍，训练成本降低 42.5%（每万亿 token 172.8K 对 300.6K GPU 小时）。
  • 论文称 MLA "achieves better performance than MHA"（性能优于 MHA），同时缓存少得多，消融实验在其附录中。
  • 93.3% 和 5.76 倍比较的是整个模型（MLA、MoE 层，以及部署时的 KV 缓存量化），而不只是注意力。应把它们看作系统层面的结果。

建模影响

  • 压缩而不是共享。缓存变成一个可学习的瓶颈；每个头仍有不同的键和值。
  • 算术量转移到解码。用吸收后的矩阵对 576 维潜在向量打分，每个缓存字节对应的计算比 GQA 多，这适合受内存限制的解码。
  • 位置需要自己的通道。任何跨缓存折叠矩阵的方案，都必须把依赖位置的部分分开。
  • 更难实现。算子和推理服务栈需要专门的 MLA 路径，计算课程会讲到。
