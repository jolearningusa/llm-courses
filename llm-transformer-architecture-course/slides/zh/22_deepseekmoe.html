问题：粗粒度专家混杂且重复知识

  • 知识混杂。只有 8 或 16 个专家时，每个专家接收的 token 差异很大，必须容纳难以在一个 FFN 中融合的知识。
  • 知识冗余。通用知识（语法、常见事实）每个专家都需要，于是每个专家都各学一份。
  • 两者都浪费参数：专家的专门化程度不如 MoE 思想所承诺的那样高。

改动 1：细粒度专家切分

16 个专家中选 top-2，每个 token 有 C(16, 2) = 120 种组合。每个拆成 4 个（64 个中选 top-8）则有 C(64, 8) = 4,426,165,368 种。

改动 2：共享专家隔离

  • 共享专家把通用知识只存一份，路由专家就能专门化。
  • 激活的专家总数仍为 mK：Ks 个共享加 mK − Ks 个路由专家。
  • 专家级和设备级均衡损失（与讲义 20 相同的 fi · Pi 形式）防止路由坍缩，并使各设备负载均匀。

问题：均衡损失与模型目标相冲突

  • 辅助均衡损失引入了与语言建模无关的梯度。系数 α 小时负载不均，路由可能坍缩；系数大时均衡良好，但模型变差。
  • 专家选择路由（由专家挑选 token）能完美均衡，但在解码器中，它让一个 token 的路由依赖于 batch 中后面的 token：信息从未来泄漏。
  • Wang 等希望既不用损失项、也不泄漏信息地实现均衡。
Wang et al. 2024, arXiv:2408.15664 §2.2, §5.2 · 参考文献

改动 3：用偏置实现无损失均衡

按 si,t + bi 取 top-K；门控值 gi,t 只来自 si,t；bi ← bi + u · sign(负载误差)

  • 每个专家有一个偏置 bi，只在选择 top K 时加到路由分数上。施加在专家输出上的权重忽略这个偏置。
  • 每个 batch 之后，把分到的 token 少于平均值的专家的偏置调高，多于平均值的调低，步长固定为 u = 0.001。
  • 偏置只用过去的 batch，因此没有未来 token 影响路由。没有梯度，也没有干扰。

对建模的影响与后续

  • 大量小专家加共享专家成为主流的 MoE 结构。DeepSeek-V3：1 个共享专家和 256 个路由专家，激活 8 个，总计 671B、激活 37B，用偏置方法均衡，并辅以一个很小的序列级补充损失。
  • Kimi K2：384 个专家，激活 8 个，1 个共享。Qwen3 MoE：128 个专家，激活 8 个，没有共享专家。
  • 均衡变成了一个控制问题。按负载计数微调的偏置取代了需要调参的损失权重。
  • 大量小专家意味着更多、更小的矩阵乘法和更多路由流量，这些由计算课程讨论。
