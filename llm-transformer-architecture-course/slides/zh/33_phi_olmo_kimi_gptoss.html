OLMo：全部公开，不只是权重

  • 1B 和 7B 模型至少训练了 2T token（7B：2.46T），采用 Apache 2.0 许可。
  • 模块：没有偏置项，非参数化的层归一化（无可学习的缩放或平移），隐藏维度 11,008 的 SwiGLU（约 8/3 · d），RoPE，词表 50,280 填充到 50,304，序列长度 2,048；只有 1B 共享嵌入。
  • 7B 模型同时在 AMD MI250X（LUMI）和 NVIDIA A100（MosaicML）集群上训练，结果几乎相同。
  • 意义：有了数据和检查点，研究者可以研究能力在训练中如何出现，以及数据里包含了什么。

Kimi K2：MuonClip 与没有尖峰的 15.5T token 训练

  • Muon 优化器比 AdamW 更省 token，但在大规模下注意力 logit 会爆炸：使用原版 Muon 时有些超过 1,000。
  • QK-Clip：每步之后，如果某个头的最大 logit 超过 τ = 100，就重新缩放该头的 query 和 key 权重将其拉回。与 QK-norm 不同，它适用于 MLA，因为 MLA 的 key 并不完整地显式生成。
  • 结果：15.5T token 的预训练中损失尖峰为零；之后用 YaRN 把上下文扩展到 128K。
  • 后训练以智能体为目标：大规模合成工具使用数据和强化学习。SWE-bench Verified 65.8（单次尝试，智能体模式）。

gpt-oss：注意力与格式

  • 各层在 128 token 窗口的带状注意力与稠密注意力之间交替（对比 Gemma 3，讲义 32）。
  • 64 个 64 维的 query 头和 8 个 KV 头（GQA）。每个头在 softmax 分母中有一个可学习的偏置，即注意力汇点，让头可以不关注任何 token（讲义 15）。
  • RoPE 加 YaRN 把稠密层扩展到 131,072 token。
  • 分词器 o200k_harmony，201,088 个 token；"harmony" 对话格式区分 analysis、commentary 和 final 三个通道（讲义 11）。
  • 推理强度（low、medium 或 high）在系统提示中设置。以 Apache 2.0 许可发布。

对建模的影响

  • 数据就是架构。Phi-3 表明，在固定规模下，过滤和合成数据对质量的影响大于模块改动。
  • 开放有不同层次。只有权重（Llama、Gemma）让你能使用模型；OLMo 的数据、代码和检查点让你能研究它是如何做出来的。
  • 优化器是设计的一部分。Kimi K2 的 QK-Clip 之所以存在，是因为 Muon 改变了 logit 的增长方式；架构和优化器是一起调的。
  • 量化格式塑造模型。gpt-oss 以 MXFP4 发布 MoE 权重，两个规模由 80GB 和 16GB 能放下多少决定。
  • 趋同的模块。前置 RMSNorm、SwiGLU、RoPE、GQA 或 MLA，以及细粒度 MoE 几乎出现在每个 2025 年的模型系列中；差异在于数据、规模和训练。

自测

  1. phi-3-mini 有 3.8B 参数。按每个权重 4 位验证 1.8GB 这个数字。
  2. 为什么一个研究小组可能更喜欢 OLMo 7B，而不是一个只公开权重但更强的模型？
  3. QK-Clip 在每步之后重新缩放权重，而不是归一化激活值。这对 MLA 为什么重要？
  4. gpt-oss-120b 的 116.83B 参数中约 90% 以 4.25 位存储，其余为 16 位。估算检查点大小并与 80GB 比较。
