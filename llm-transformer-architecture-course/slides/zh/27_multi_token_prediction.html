问题：下一 token 预测目光短浅

  • 从 GPT（讲义 02）开始，语言模型的训练目标就是预测下一个 token。教师强制让这件事变得容易：大多数下一个 token 在局部上显而易见。
  • 作者认为，训练信号被花在了简单的局部转移上，而花在决定后续段落的少数"选择点"上的太少。
  • 另外，解码时每次前向传播只输出一个 token，这让 GPU 处于内存受限状态（讲义 12）。

改动：共享主干上的 n 个头

损失 = Σi=1..n 给定 token ≤ t 时 token t+i 的交叉熵。n = 1 就是普通训练。前向和反向传播中各个头依次运行，所以峰值内存保持在 O(V + d)，而不是 O(nV + d)。

证据：更快的解码

  • 自投机解码。额外的头提出 token t+2 … t+n；下一次前向传播对其验证，保留最长的正确前缀。不需要单独的草稿模型。
  • 7B 的 4 token 模型在代码上解码快 3.0 倍、在文本上快 2.7 倍；8 字节模型快 6.4 倍。
  • 投机解码从不改变输出分布：验证会拒绝错误的草稿。
Gloeckle et al. 2024, arXiv:2404.19737 §3.2, 表 S2–S3 · 参考文献

证据：没有帮助的地方

  • 自然语言多项选择基准：n = 2 与基线持平，n = 4 略有退步。
  • 摘要：n = 2 和 n = 4 都提高了 ROUGE-L。
  • 小模型：在约 30M 非嵌入参数以下，2 token 损失有助于形成归纳头；到约 100M 时这一优势消失。
  • 论文的解释：n token 预测给选择点的权重约为 n(n+1)/2，而无关紧要的 token 只有 n，因此模型会在之后有影响的决策上投入更多。
Gloeckle et al. 2024, arXiv:2404.19737 §3.7, §4.1, §5.1 · 参考文献

后续：DeepSeek-V3 与 Qwen3-Next

  • DeepSeek-V3 用一个顺序 MTP 模块（深度 1）训练，在保持完整因果链的同时多预测一个 token：该模块看到主模型的表示和下一个 token 的嵌入。推理时该模块被丢弃，或用于投机解码。
  • 与 Gloeckle 等的独立头不同，每个额外预测深度都是一个完整的 Transformer 模块，串接在上一深度之后，并与主模型共享嵌入和输出头。DeepSeek-V3 使用深度 D = 1。
  • Qwen3-Next 内置原生 MTP 用于投机解码（讲义 25）。
DeepSeek-V3, arXiv:2412.19437 §2.2, §4.2 · Qwen3-Next blog · 参考文献

对建模的影响

  • 训练目标是架构的一部分。额外的头在训练中代价很小，却改变了主干学习表示的内容。
  • 无需草稿模型的解码。同一组权重既起草又验证，从训练目标一侧解决内存受限的解码步骤，而第三部分是通过缓存来解决的。
  • 依赖规模。对小模型有害，对大模型和代码有益：在新领域应重新测试，而不是想当然。
