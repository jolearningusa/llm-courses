DeepSeek-V3 与 DeepSeek-R1

DeepSeek-AI，2024 年 12 月和 2025 年 1 月。V3 把 MLA、带无损失均衡的细粒度 MoE、多 token 预测和 FP8 训练组合成一个 671B 模型，训练耗时 2.8M GPU 小时。R1 表明，仅用基于规则奖励的强化学习就能教会这个模型推理。

问题：在固定 GPU 预算下达到前沿质量

  • DeepSeek 在 2,048 块 H800 GPU 上训练。节点内 NVLink 提供 160 GB/s；节点间 InfiniBand 提供 50 GB/s。对于大型 MoE，token 要被送到其他节点上的专家，瓶颈是通信而不是算力。
  • 目标：一个与最好的闭源模型一样强、训练和部署成本都低的模型。
  • V3 的每个部件都针对其中一项成本：KV 缓存内存（MLA）、激活计算（MoE）、每个 token 的训练信号（MTP），以及算力和通信（FP8、DualPipe）。

改动：无辅助损失的均衡，以及 MTP

  • 无损失均衡（讲义 22）：每个专家有一个偏置，只在 top-K 选择时加到其分数上。每步之后它按 γ = 0.001 朝与该专家负载相反的方向调整。
  • 一个很小的序列级均衡损失（α = 0.0001）只防止单个序列内的极端不均衡。
  • 训练和推理中都不丢弃 token。
  • 多 token 预测（讲义 27）：一个额外的顺序模块预测下下个 token。它让训练信号更密集；推理时可以丢弃，也可以用于投机解码。

改动：FP8 与 DualPipe

  • V3 是最早用 FP8 矩阵乘法训练的超大模型之一；与 BF16 基线相比，相对损失误差保持在 0.25% 以下。
  • DualPipe 调度前向和反向的计算块，使 MoE 的 all-to-all 通信隐藏在计算之后。
  • 预训练在 14.8T token 上进行，没有出现不可恢复的损失尖峰，也没有回滚。

R1-Zero：仅靠强化学习获得推理能力

  • 从 V3 基座模型出发，不做 SFT。用 GRPO 训练；奖励基于规则：最终答案是否正确，推理过程是否放在规定的标签内。
  • 训练过程中 AIME 2024 pass@1 从 15.6% 升到 77.9%（多数投票为 86.7%）。
  • 回答自己变长了。模型开始复查自己的工作：出现了"顿悟时刻"（aha moment），它写下 "wait" 并回头检查某一步。
  • 问题：可读性差，一个回答里混用多种语言。

对建模的影响

  • 架构即成本工程。V3 的每个选择都可追溯到一个硬件瓶颈：内存、带宽或算力。
  • 前沿训练的成本下降了。2.8M GPU 小时让其他实验室重新审视自己的预算，MLA、无损失均衡和 FP8 迅速传播（Kimi K2 照搬了 V3 的结构，讲义 33）。
  • 推理靠训练，而不是靠提示。R1 让基于可验证奖励的强化学习成为构建推理模型的标准方法；Qwen3 等随后跟进（讲义 30）。
  • 长输出把成本转移到推理阶段。一个要思考数千 token 的模型把开销从训练转向部署，这提高了 MLA 和 MTP 的价值。

自测

  1. 为什么把每个 token 限制在 4 个节点，在 H800 上比在互连带宽更高的硬件上更重要？
  2. 均衡偏置改变的是选中哪些专家，而不是门控权重。这为什么对模型输出很重要？
  3. R1-Zero 只使用正确性和格式奖励。为什么这比学习得到的奖励模型更难被"奖励投机"（reward hacking）？
  4. V3 的 MLA 每层缓存 512 个潜向量值加一个 64 维的 RoPE key（讲义 16）。按 61 层、BF16 计算，与实验 L5 中 8 个 128 维 KV 头的 GQA 的 kv_bytes_per_token 比较。
