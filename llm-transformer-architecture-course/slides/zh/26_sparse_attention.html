问题：长上下文的成本主要在注意力

  • 在 64K token 时，注意力主导了每次前向传播和每个解码步的成本：每个 query 都要读取所有 key（讲义 14–16）。
  • 长上下文中大部分注意力权重集中在少数 token 上，所以大部分计算都浪费了。早期稀疏方法只在推理时利用这一点（模型仍是稠密训练的），或者使用在 GPU 上跑不快的模式。
  • 目标：可以端到端训练、并且在真实内核中运行很快的稀疏性。

NSA：每个 query 三个分支

  • 压缩：每 32 个 key 一块（步长 16），各自汇总成一个粗粒度 token：对整个上下文的廉价概览。
  • 选择：由压缩分支的注意力打分，选出最重要的 16 个块（每块 64 个 key），始终包含第一块和 2 个局部块。
  • 滑动窗口：最后 512 个 token。每个分支一个学习到的 sigmoid 门控，混合三路输出。
Yuan et al. 2025, arXiv:2502.11089 §3.2–3.3, §4.1 · 参考文献
3 / 10

NSA：为硬件而设计

  • 选择结果由一个 GQA 组（讲义 13）内的所有 query 头共享：分数在组内求和，于是一组 key 块只加载一次，供所有使用它的头使用。
  • 块是连续的，所以访存是合并的，内层循环使用张量核心，与 FlashAttention（讲义 14）类似。
  • 每个分支都可微，所以模型在预训练中学习往哪里看；没有事后附加的东西。

DSA：闪电索引器与 top-k token

It,s = Σj wt,j · ReLU(qt,j · ks)

  • 一个只有少数头、可用 FP8 运行的小型索引器，为 query t 给每个更早的 token s 打分。用 ReLU 代替 softmax，以提高吞吐。
  • 只有索引分数最高的 k = 2,048 个 token 进入注意力。选择按 token 进行，而不是按块。
  • 构建在 MLA（讲义 16）的 MQA 模式上，因此每个选中的潜向量由所有 query 头共享。
  • 核心注意力从 O(L²) 变为 O(L·k)；索引器仍是 O(L²)，但每对的成本低得多。
DeepSeek-V3.2, arXiv:2512.02556 §2.1, §2.3, Eqs. 1–2 · 参考文献

DSA：加到已训练好的模型上

  • 预热：1,000 步，每步 16 条 128K token 序列；稀疏阶段：15,000 步，每步 480 条 128K 序列。索引器先学习模仿稠密注意力的分布，然后模型适应只看到选中的 token。索引器的输入被 detach：它只从自己的 KL 损失中学习。
  • 结果（DeepSeek-V3.2-Exp）：在短上下文和长上下文基准上相对 V3.1-Terminus 没有明显退化，而长位置上每个 token 的成本低得多（H800 上的估算）。

对建模的影响

  • 稀疏性变得可训练。两篇论文都学习如何选择，NSA 从头训练，DSA 通过继续训练，而不是在推理时套用固定模式。
  • 主注意力的单 token 成本不再随上下文增长；一个廉价的打分器仍然会看所有内容。
  • KV 缓存不变。所有 key 都保留；稀疏性节省的是读取和计算，而不是内存。对比滑动窗口（讲义 15）会丢弃 key，循环模型（讲义 23–25）则从不存储 key。
  • 与内核协同设计。按 GQA 组共享块选择（NSA）和在 MLA 的 MQA 模式下做选择（DSA），都是为了让访存高效。

后续影响

  • DeepSeek-V3.2 以 DSA 作为其注意力；系列讲义（讲义 31）把它放在 V3 和 R1 之后。
  • 三分支思路（粗粒度汇总、选中的细节、局部窗口）是其他可学习稀疏注意力设计的模板。
  • 稀疏注意力、滑动窗口和线性注意力混合架构如今在争夺同一件事：以有界成本实现长上下文。
