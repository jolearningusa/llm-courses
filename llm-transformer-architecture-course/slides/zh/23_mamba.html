问题：注意力的成本随序列增长

  • 注意力把每个 token 与之前的每个 token 比较：训练时计算量是二次的，KV 缓存随每个生成的 token 增长（第三部分）。
  • 次二次的替代方案（线性注意力、门控卷积、S4 等结构化状态空间模型）在语言任务上一直没能赶上注意力。
  • Gu 和 Dao 指出了弱点：它们无法做基于内容的推理。时不变模型对每个 token 施加相同的动态，所以能解决普通复制，却在需要根据内容决定保留什么的选择性复制上失败。

改动：选择性

  • S4 从 h′(t) = Ah(t) + Bx(t)，y = Ch(t) 出发，用步长 Δ 离散化（零阶保持：Ā = exp(ΔA)）。A、B、C 和 Δ 在时间上固定，所以该层是一个卷积，可以并行训练。
  • Mamba 让 B、C 和 Δ 成为当前输入的函数：B = LinearN(x)，C = LinearN(x)，Δ = softplus(Linear(x))。
  • 大的 Δ 会把状态重置到当前 token；小的 Δ 保留过去、忽略当前 token。模型按 token 学习要记住什么。
  • 代价：卷积捷径没有了，该层必须按递推（扫描）计算。

改动：硬件感知扫描与简洁的模块

  • 扫描。内核融合、并行扫描以及反向传播中的重计算：展开后的状态留在片上 SRAM 中，从不写入 HBM（FlashAttention 的思路，讲义 14）。状态大小 N = 16 时，超过 2K token 后比 FlashAttention-2 更快。
  • 模块。一个重复的模块把早期的 H3 层与门控 MLP 合并：扩展 E = 2 倍、短卷积、SiLU、选择性 SSM、乘性门控、投影回原维度。没有注意力，也没有单独的 MLP。

Mamba 的证据

  • 合成任务。解决了选择性复制和归纳头；在长度 256 上训练后，归纳头的解法能泛化到约 1M token。
  • 语言。第一个在扩展曲线上与强 Transformer++ 配方（RoPE、SwiGLU、RMSNorm）相当的无注意力模型。Mamba-3B 胜过同规模的 Transformer，与两倍规模的 Transformer 相当。
  • 推理。生成吞吐量约为同规模 Transformer 的 5 倍，因为没有 KV 缓存要读。
  • 其他模态。DNA（上下文最长到 1M 时效果更好）和音频（SC09 FID 0.94，SaShiMi 为 1.99）。

Mamba-2：状态空间对偶

  • 把 A 进一步限制为标量乘单位矩阵（原来是对角矩阵）。这时 SSM 的序列变换等价于一种带掩码的线性注意力：同一个模型既有循环（线性时间）形式，也有二次的、类注意力的形式，二者通过半可分矩阵联系起来。
  • SSD 算法在块内用二次形式计算（在张量核心上做矩阵乘法），在块之间循环传递状态：比 Mamba 的扫描快 2–8 倍，在 16K token 时比 FlashAttention-2 快 6 倍。
  • 这使状态可以比 Mamba 大 8 倍以上，头维度可以像 Transformer 一样取 64 或 128。A、B、C 和 X 来自模块开头的同一个投影；输出投影前多一个归一化。

Mamba-2 的证据与局限

  • 在 Chinchilla 式扩展下，Mamba-2 在困惑度对墙钟时间上帕累托占优于 Mamba 和 Transformer++。在 300B Pile token 上训练的 2.7B Mamba-2 胜过 Mamba-2.8B、Pythia-2.8B 和 Pythia-6.9B。
  • 局限在于召回。固定状态必须压缩全部过去，所以需要某个确切早期 token 的任务，例如复制一段长文或从许多键值对中召回一个，终究会超出状态的容量；注意力则保留每个 token。
  • Jamba 的消融（讲义 24）展示了实际症状：纯 Mamba 模型无法遵循上下文中的回答格式，而注意力模型和混合模型可以。Gated DeltaNet（讲义 25）从循环内部攻克同一弱点。

对建模的影响与后续

  • 每个 token 的内存恒定。生成成本不再随上下文增长：没有 KV 缓存，每层只有一个状态。
  • 注意力与循环是同一族模型的两种视角。SSD 之后，先选定状态更新、再推导并行训练算法，成了设计新层的常规方法。
  • 混合架构胜出。主要的生产用法是在许多 Mamba 或线性注意力层之间放少数注意力层：Jamba（讲义 24），以及采用 Gated DeltaNet 的 Qwen3-Next（讲义 25）。
  • 论文评述的实验思路：把选择性扫描写成 Python 循环和二次 SSD 形式两种实现，并检查二者一致。
