Mixtral 混合专家

Jiang 等（Mistral AI），2024。以 Mistral 7B 解码器为基础，把每个 FFN 换成 8 个专家，每个 token 路由到其中 2 个。这是第一个能与大得多的稠密模型相当的开放权重 MoE 大模型。

证据：路由器学到了什么

  • 作者寻找按主题（ArXiv 论文、生物、哲学、数学、代码）专门化的专家，结果发现"no obvious patterns"（没有明显规律），只有 DM Mathematics 略有不同。
  • 路由更像是句法层面的：Python 中的 "self" 和英语中的 "Question" 这类 token 常常去同一个专家，代码中的缩进 token 也是如此。
  • 相邻 token 常常共用专家：在第 15 层和第 31 层，有 22–28% 的相邻 token 首选专家相同，而随机情况下只有 12.5%。

对建模的影响

  • 计算与内存分道扬镳。按单个 token 算，Mixtral 的成本与 13B 稠密模型相当；但在内存上它是 47B 模型，所有专家都必须加载。
  • 批处理改变了局面。在一个 batch 中，不同 token 选择不同专家，所以每一步大多数专家都会被读取；成本优势在计算受限的场景下最大。
  • 专家不是主题。"每个专家是一个领域专家"的设想并不成立；专门化体现在词法和句法上。
  • 局部性有助于服务部署。相邻 token 重复选择同一专家，这对专家缓存和专家并行很重要（见计算课程）。
Jiang et al. 2024, arXiv:2401.04088 §2.1, §5 · 参考文献

后续影响

  • 随后的 Mixtral 8x22B 沿用了同样的结构。"8 个专家、top-2"的形状在 2024 年被广泛模仿。
  • DeepSeekMoE（讲义 22）认为 8 个大专家粒度太粗，改用大量小专家加共享专家；Qwen3、DeepSeek-V3、Kimi K2 和 gpt-oss 都使用更多、更小的专家（第七部分）。
  • Mistral 的 GQA、RoPE 和 SwiGLU 模块（讲义 08、13、18）原样沿用；只有 FFN 改变了。
