问题：长序列预训练很昂贵

  • 注意力代价随长度增长（讲义 01），所以大多数预训练在 2K–8K token 上进行。而应用需要 32K–128K。
  • 让 RoPE 模型越过训练窗口运行，会输入它从未见过的旋转角度。困惑度会爆炸。
  • 直接在更长序列上微调适应得很慢：在 PI 论文中，LLaMA 的有效窗口在 10,000 多步后只从 2,048 增长到约 2,560。

改动 1：位置插值（PI）

f′(x, m) = f(x, m · L / L′)

  • 把所有位置按比例缩小，把新窗口 L′ 压进旧窗口 L。所有角度都留在训练范围内。
  • 论文给出了注意力分数误差的界：在 LLaMA 7B 的设置下，插值的界至少比外推的界小约 600 倍。

PI 的证据

  • LLaMA 7B 到 65B 在 Pile 上用约 1,000 步微调，从 2,048 扩展到最多 32,768 个 token。
  • 密钥检索在约 200 步内就覆盖了整个新窗口。
  • 长文档（PG-19、Proof-pile）上的困惑度随窗口增长而改善。
  • 代价：原窗口内有轻微退化，在 8,192 token 时基准测试最多下降约 2%，窗口更大时更多。压缩位置会模糊精细的局部顺序。

改动 2：YaRN 区别对待不同频率

  • 诊断。PI 对每一对 RoPE 维度做同样的缩放。快速旋转的维度对，其波长远短于窗口，承载局部顺序，不需要缩放；正是对它们的缩放模糊了短程细节。
  • NTK-aware：改变 RoPE 的底数而不是位置，使高频变化小、低频变化大。
  • NTK-by-parts：对每一对，比较其波长 λ 与上下文 L（r = L/λ）。r 小的完全插值，r 大的保持不变，中间平滑过渡（Llama 取 α = 1，β = 32）。
  • 注意力温度：用 1/√t = 0.1 ln(s) + 1 缩放 logits，s 为扩展倍数。它可以并入 RoPE 表，运行时零代价。
Peng et al. 2023, arXiv:2309.00071 §3 · 参考文献

YaRN 的证据

  • Llama 2 7B 和 13B 以 s = 16 扩展到 64K；再以 s = 32 训练 200 步即达到 128K，128K 时密钥检索准确率超过 99%。
  • 作者报告所需 token 比以往方法少 10 倍，训练步数少 2.5 倍。
  • 推理时的动态缩放按当前长度设 s = max(1, l′/L)，无需微调就能把模型扩展 2 倍以上。此时键必须在施加 RoPE 之前缓存，因为旋转随 s 变化。
Peng et al. 2023, arXiv:2309.00071 §3–4 · 参考文献

建模影响

  • 上下文长度成了后训练的旋钮。先廉价地短序列预训练，再在一个简短的最后阶段扩展。Llama 3 在预训练末期分六个阶段从 8K 增长到 128K。
  • KV 缓存随窗口增长。按 Llama 3 8B 每 token 128 KiB 计算，128K 窗口每条序列就是 16 GiB（实验 L0），这正是第三部分努力缩小的。
  • 窗口 ≠ 使用。通过密钥检索说明模型能找到一个事实；并不说明它用上了整个窗口（讲义 11）。
Llama 3, arXiv:2407.21783 §3.4 · lab L0 · 参考文献

后续

  • 公开配置把这个选择写在 rope_theta 和 rope_scaling 中。Llama 3 8B 用 θ = 500,000，不做缩放；Qwen2.5 用 θ = 1,000,000，并说明超过 32K 的输入使用 YaRN。
  • 提高底数（NTK-aware 思想的最简形式）成为默认的第一步；YaRN 式的按频率缩放成为默认的第二步。
  • 滑动窗口（讲义 15）、压缩 KV（讲义 16）和稀疏注意力（讲义 26）针对的是长窗口的代价，而不是位置。
