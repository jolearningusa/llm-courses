问题：参数要花计算

  • 在稠密网络中每个参数都用于每个 token，所以模型容量和每 token 的计算一起增长（讲义 05–06）。
  • 条件计算（每个输入只激活网络的一部分）已被提出多年，但在实践中遇到了算法和性能上的问题。
  • Shazeer 等列出了原因：GPU 擅长算术而不擅长分支；选择网络的一部分会缩小每部分看到的 batch；网络带宽；以及需要额外的损失来保持选择均衡。

改动：稀疏门控 MoE 层

y = Σi G(x)i Ei(x) , G(x) = Softmax(KeepTopK(H(x), k))

  • 专家是前馈网络。H(x) = xWg 加上按 Softplus(xWnoise) 缩放的高斯噪声；top k 之外的条目设为 −∞，因此它们的门值为 0。
  • 放在堆叠的 LSTM 层之间，在每个位置上应用。

让专家保持忙碌

  • 均衡损失。没有它们时路由器偏爱少数专家，这些专家训练得更快、被选得更多。论文加了 w · CV(Importance)²，其中 importance 是每个专家在 batch 中的门值总和，另加一项针对每个专家所接收 token 数的平滑估计的损失。
  • 缩小的 batch。n 个专家选 k 个时，大小为 b 的 batch 中每个专家只看到约 kb/n。把数据并行（副本）与模型并行（每个专家一份，由所有副本供给）结合，使每个专家的 batch 乘以设备数 d。

GShard：把 MoE 放进 Transformer

  • 专家容量：在一组 N/G 个 token 中，每个专家最多接收约 2N/(G·E) 个 token；所选专家已满的 token 通过残差连接跳过这一层。
  • 辅助损失：对各专家求 (ce/S) · me 的平均，即发往专家 e 的 token 比例乘以其平均门值。随机路由：第二个专家以与其门值成正比的概率被使用。

建模影响

  • 总参数与激活参数分离。模型可以拥有远多于每 token 所用的参数。此后每份 MoE 报告都同时给出两个数字。
  • FFN 是稀疏的部分。注意力保持稠密；专家取代的是持有大部分参数的前馈层（讲义 18）。
  • 路由是一种新的失效方式。均衡损失、容量上限和丢弃的 token 都成了超参数。
  • 模型是一个分布式系统。专家位于不同设备上，所以 all-to-all 通信和专家并行（计算课程）是设计的一部分。

后续

  • Switch Transformer（讲义 20）把路由简化为一个专家，并解决了训练不稳定的问题。
  • 在 8 个专家上做 top-2 路由在 Mixtral 中重现（讲义 21）。
  • 辅助均衡损失一直是默认做法，直到 DeepSeek 用一个偏置项取代了它的大部分（讲义 22）。
  • 带噪声的门控被放弃；容量因子和 token 丢弃仍用于训练，推理系统则避免丢弃。
