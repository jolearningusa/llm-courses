问题：从左到右的模型只看到半个句子

  • GPT-1 从左到右预训练，所以每个 token 的表示只取决于它前面的内容。
  • 理解类任务（问答、蕴含、序列标注）需要一个词两侧的上下文。
  • 双向模型不能用普通的下一个 token 损失训练：每个词会通过上层看到自己。
  • ELMo 把两个独立的单向 LSTM 拼起来。BERT 要的是一个每层都双向的深层模型。

改动：掩码语言建模

  • 随机选 15% 的 WordPiece token，用完整、未被遮盖的上下文预测这些位置上的原始 token。
  • 被选中的 token 中，80% 换成 [MASK]，10% 换成随机 token，10% 保持不变。这减小了与微调时的不一致，因为微调时不会出现 [MASK]。
  • 另加下一句预测（NSP）：给定句子 A 和 B，预测 B 是否紧跟在 A 之后（50% 的情况）还是随机的。
  • 没有因果掩码：注意力掩码只遮住填充部分。

这个技巧的代价：每次只有 15% 的位置提供训练信号，而因果 LM 是 100%。

证据

  • 在 11 个 NLP 任务上达到新的最好结果。排行榜上 GLUE 80.5（+7.7 分），MultiNLI 86.7%，SQuAD v1.1 测试 F1 93.2，SQuAD v2.0 测试 F1 83.1。
  • BERT-base 开发集上的消融：不带 NSP 的从左到右模型使 SQuAD F1 从 88.5 降到 77.8，MRPC 从 86.7 降到 77.5。双向性是主要的收益来源。
  • 在 BERT 自己的设置中，去掉 NSP 使 QNLI 从 88.4 降到 84.9，MNLI-m 从 84.4 降到 83.9。
  • 更大的模型即使在 MRPC（3,600 个训练样本）这样的小数据集上也有帮助。

建模影响

  • 仅编码器适合做表示。每个 token 看到整个输入，所以逐 token 和整序列的输出都很适合分类、标注、检索和重排序。
  • 它不能生成。没有因果顺序，生成文本需要多次前向或一个单独的解码器。这就是聊天模型都是解码器的原因。
  • 样本效率。掩码 LM 每次只从 15% 的位置学习；因果 LM 从所有位置学习。在大规模下这使解码器占优（讲义 04 做了测量）。
  • 长度固定。可学习位置把输入限制在 512 个 token。

后续

  • 在嵌入、检索和分类任务中，仅编码器模型仍是默认选择，双向上下文和小体积在这里很划算。
  • 掩码目标在视觉中以掩码图块预测的形式回归，也出现在 T5 的片段破坏中（讲义 04）：保留了思想，但用解码器生成缺失的片段。
  • RoBERTa 的教训是固定的架构可能训练严重不足，这与 Chinchilla（讲义 06）对解码器得出的教训相同。
  • 片段嵌入和 NSP 消失了；[CLS]/[SEP] 式的特殊 token 保留下来，并发展成聊天模板（讲义 11）。
