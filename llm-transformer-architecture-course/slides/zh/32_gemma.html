问题：单台设备上每字节的质量最大化

  • Gemma 面向能在笔记本、单块 GPU 或手机上运行的模型。在这些规模下，权重和 KV 缓存所占的内存决定了能放下什么。
  • Gemma 2 指出，把小模型训练得更久，其提升只随数据量呈对数增长；于是它把独热的下一 token 目标换成了更丰富的目标：教师模型的分布。
  • Gemma 3 又增加了两个需求：长上下文（128K）和图像，而且都不能让内存暴涨。

Gemma 2：局部层与全局层，软截断

  • 各层在 4,096 token 的滑动窗口（讲义 15）和覆盖 8,192 token 的全局注意力之间交替。
  • logit 软截断：logit 经过 cap · tanh(x / cap)，注意力中 cap 为 50，最后一层为 30。
  • 每个子层的输入和输出都做 RMSNorm（前置与后置归一化），GQA 中每个 KV 头对应 2 个 query 头。

Gemma 3：每个全局层配 5 个局部层，128K，视觉

  • 每个全局层配五个局部层，窗口缩小到 1,024 token。只有全局层在 KV 缓存中保留完整上下文。
  • 在报告的消融中（2B 模型，32K 上下文），KV 缓存的内存开销从只用全局层时的 60% 降到每三个局部层配一个全局层、窗口 1,024 时的不到 15%。
  • QK-norm 取代了 Gemma 2 的软截断。全局层为 128K 上下文把 RoPE 基数从 10K 提高到 1M（1B 模型为 32K 上下文）；局部层保持 10K。
  • 视觉：冻结的 400M SigLIP 编码器把 896 × 896 的图像转成 256 个软 token；Pan & Scan 仅在推理时把其他宽高比的图像切成多块。1B 模型只支持文本。

对建模的影响

  • 局部注意力作为 KV 缓存压缩。Gemma 3 让大多数层成为局部层来缩小缓存；gpt-oss 以同样思路交替使用带状层和稠密层（讲义 33）。
  • logit 控制转向 QK-norm。Gemma 3 放弃软截断、改用 QK-norm，Qwen3 也采用了它（讲义 30）：两者都防止注意力 logit 增长过大。
  • 蒸馏是小模型的配方。Gemma 2 和 3、Qwen3 以及 Llama 4（以 Behemoth 为教师）都从更大的模型训练小模型。
  • 词表大小是一种权衡。256K token 有利于多语言文本，但要付出嵌入参数的代价，对 1B–2B 模型来说占比很大。
