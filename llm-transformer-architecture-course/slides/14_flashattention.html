Problem: attention is limited by memory traffic

  • Standard attention writes the N × N score matrix to GPU memory (HBM), reads it back for softmax, writes the probabilities, and reads them again to multiply by V.
  • A100: 40–80 GB of HBM at 1.5–2.0 TB/s, and 192 KB of SRAM per streaming multiprocessor (108 of them) at about 19 TB/s. Moving data, not multiplying, sets the time.
  • The N × N intermediate also sets the memory: training at long N was impractical, so many "efficient attention" papers approximated attention instead, and few were used in practice because they did not run faster in wall-clock time.

Change: tiling with an online softmax

Softmax over a row can be built block by block: keep the running maximum m and the running sum ℓ, and rescale the partial output when m changes. The result equals full softmax exactly.

Change: recompute in the backward pass

  • The backward pass needs the attention probabilities. Instead of storing the N × N matrix, FlashAttention stores O and the statistics (m, ℓ) and recomputes the probabilities block by block.
  • More FLOPs, fewer bytes moved: the backward pass is still faster than reading a stored matrix.
  • HBM accesses: Θ(Nd + N²) for standard attention against Θ(N²d²/M) for FlashAttention, with SRAM size M. For typical d = 64–128 and M around 100 KB, that is many times fewer.
  • Extra memory beyond inputs and outputs is O(N), linear in sequence length.

Evidence: better models, not just faster ones

  • Longer context for the same budget. GPT-2 trained at 4K context with FlashAttention reached 17.5 perplexity, 0.7 better than Megatron at 1K context (18.2), and still trained 30% faster.
  • New capabilities. Path-X (16K tokens): 61.4% accuracy, the first Transformer better than chance. Path-256 (64K tokens): 63.1% with block-sparse FlashAttention.
  • Both results come from being able to train on sequences that did not fit before.

Modeling impact

  • Context length became affordable in training. Memory linear in N removed the wall that kept pre-training at 1–2K tokens; the 8K pre-training and 128K extension stages of deck 10 rely on it.
  • Exact beats approximate. Once exact attention was fast, approximate attention lost most of its reason to exist. Later efficient designs (Part VI) compete with a strong baseline.
  • Architectures are judged by kernels. A new attention variant is now asked whether it tiles well: GQA, sliding windows (deck 15) and sparse attention (deck 26) all map onto blocks.
  • It did not fix decoding: generation still reads the whole KV cache each step, which is why decks 12, 13 and 16 shrink the cache.

Afterlife

  • FlashAttention-2 (2023) improved work partitioning across thread blocks; FlashAttention-3 (2024) targets Hopper GPUs with asynchronous copies and FP8.
  • Fused, tiled attention is the default path in mainstream frameworks, for example PyTorch's scaled_dot_product_attention, and in inference engines.
  • The kernels, paging of the KV cache and decoding-specific variants are taught in the compute systems course; this course only needs the modeling consequence.
