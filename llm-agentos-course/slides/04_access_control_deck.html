The new part: the process (the model) can be talked into misusing its permissions by data it reads. Classic access control assumes the program does what its code says; an agent does what its context says.

Threat modelPrompt injection is not solved

  • Direct: the user tries to override instructions. Indirect: instructions hidden in a web page, email, file, tool result, memory or skill.
  • The Attacker Moves Second (Oct 2025; authors from OpenAI, Anthropic and Google DeepMind): adaptive attacks broke 12 published defenses, most with >90% success, though most had reported near-zero; human red-teamers (500 people) beat all of them.
  • Simon Willison: a guardrail that stops 95% of attacks is a failing grade in security.

So design as if injection will succeed sometimes, and limit what a hijacked agent can do.

PrincipleThe lethal trifecta and the Agents Rule of Two

  • Lethal trifecta (Willison, Jun 16, 2025): private data + untrusted content + external communication lets an attacker steal data. Users mixing tools should avoid the combination.
  • Agents Rule of Two (Meta, Oct 31, 2025): within a session an agent should have at most two of [A] untrusted inputs, [B] sensitive data or systems, [C] state change or external communication. All three: no autonomy, require approval or other validation.
  • Starting a new session with a fresh context is one way to separate the properties.
simonwillison.net/2025/Jun/16/the-lethal-trifecta; ai.meta.com/blog/practical-ai-agent-security.

WhoInbound access: pairing and allowlists

OpenClaw dmPolicy

  • pairing (default): unknown senders get a code and are ignored until approved; codes expire after 1 hour; at most 3 pending per channel.
  • allowlist, open (needs "*"), disabled.
  • Groups: requireMention, groupPolicy + groupAllowFrom.
  • Default session.dmScope: main shares one session across DMs; use per-channel-peer when several people talk to the bot.

Hermes gateway

  • Order: per-platform allow-all → pairing list → platform allowlist → global allowlist → global allow-all → deny.
  • unauthorized_dm_behavior: pair: 8-character code, 1-hour expiry, hermes pairing approve <platform> <code>.
  • Rate limit 1 request per user per 10 min, 3 pending per platform, 1-hour lockout after 5 failed approvals.

OpenClaw's model: one trusted operator per gateway, not a hostile multi-tenant boundary. Mixed-trust users get separate gateways, ideally separate OS users or hosts.

docs.openclaw.ai/gateway/security; hermes-agent.nousresearch.com/docs/user-guide/security.

WhatTool policy: deny by default where it matters

// OpenClaw hardened baseline (from the security docs)
{
  tools: {
    profile: "messaging",
    deny: ["group:automation",
           "group:runtime",
           "group:fs"],
    fs:   { workspaceOnly: true },
    exec: { security: "deny", ask: "always" },
    elevated: { enabled: false }
  }
}
// trusted personal default:
//   exec security="full", ask="off"  (by design)
  • Non-owner senders cannot use cron or gateway tools by default.
  • With an allowlisted interpreter, set tools.exec.strictInlineEval (python -c is arbitrary code).
  • tools.elevated runs outside the sandbox: keep allowFrom tight.
  • Sub-agents and skills have their own allowlists (multi-agent and skills decks).
  • Hermes: toolsets per platform; MCP stdio servers get only PATH, HOME, USER, LANG, LC_ALL, TERM, SHELL, TMPDIR, XDG_*.
docs.openclaw.ai/gateway/security ("hardened baseline", "exec approvals"); Hermes security docs (MCP credential filtering).

EscalationApprovals: manual, smart, or off

Hermes approvals.modeBehavior
smart (default)An auxiliary LLM rates risk: low → approve that command once, dangerous → deny, unsure → ask
manualAlways ask on dangerous commands
off / --yoloNo prompts; hardline blocklist still applies
  • Timeout 300 s, then deny (fail closed).
  • "Always" writes the pattern to command_allowlist.
  • Hardline blocklist (rm -rf /, fork bombs) has no override.
  • In container backends the container is the boundary, so dangerous-command checks are skipped.

Elsewhere

  • Codex: approvals on-request (ask to leave the sandbox) or never; sandbox read-only / workspace-write / danger-full-access.
  • OpenClaw: exec.ask (always … off) plus before_tool_call hooks that can block.
  • Claude Code: sandbox + proxy, 84% fewer prompts.

An LLM approving another LLM's command is a classifier, not a boundary: it is subject to the same injection.

Hermes security docs; Codex and Claude Code sandboxing (tools deck); OpenClaw security docs.

ContextInjection scanning of instructions, memory and skills

  • Hermes scans AGENTS.md, .cursorrules and SOUL.md before they enter the system prompt; a flagged project file is not loaded ("[BLOCKED: AGENTS.md contained potential prompt injection …]").
  • Skills: scan on install, trust levels, staged agent writes (skills deck).
  • Memory: a poisoned memory is a persistent injection; the memory-security material in this module (A-MemGuard, the memory lifecycle threat model) applies.
  • OpenClaw advice: treat web pages, email, attachments and pasted content as hostile even if only you can message the bot; consider a read-only reader agent that summarizes untrusted content.

Isolation inside one turn

Separate who reads untrusted content from who acts:

  • Reader sub-agent with no tools returns a summary.
  • Actor never sees the raw content.
  • Fresh session per untrusted source (Rule of Two).

Summaries can still carry instructions; this reduces risk, it does not remove it.

ResearchDefenses by design

Design patterns (Beurer-Kellner et al., 2025)

  • Action-selector: the model only picks from fixed actions.
  • Plan-then-execute: fix the plan before reading untrusted data.
  • LLM map-reduce: isolated workers per untrusted item.
  • Dual LLM: a privileged model never sees untrusted text; a quarantined one does, with no tools.
  • Code-then-execute: the model writes a program; untrusted data flows only as values.
  • Context minimization: drop the user prompt before acting on results.

CaMeL (Debenedetti et al., 2025)

  • Extracts control flow and data flow from the trusted user query, so retrieved data cannot change the program.
  • Capabilities on values block private data from flowing to unauthorized tool calls; policies are checked at each call.
  • AgentDojo: 77% of tasks solved with provable security vs. 84% undefended.

The cost of security is utility: some tasks can no longer be done autonomously.

arXiv:2506.08837; arXiv:2503.18813; AgentDojo arXiv:2406.13352.

SecretsCredentials, transcripts and the host

  • OpenClaw keeps config (openclaw.json), channel credentials, API keys (auth-profiles.json) and session transcripts under ~/.openclaw: keep it 700, files 600, full-disk encryption, a dedicated OS user on shared hosts.
  • Gateway binds to loopback by default; token auth fails closed; never expose it unauthenticated.
  • Skill env / apiKey are injected on the host for the run only, not into the sandbox.
  • Hermes redacts GitHub PATs, sk- keys, bearer tokens and token=/key=/password=/secret= in MCP errors.

Principle

Secrets the model never sees cannot be exfiltrated by the model.

  • Inject at the tool boundary, not in the prompt.
  • No secrets inside the sandbox.
  • Transcripts are sensitive data: telemetry content capture is off by default for a reason (observability deck).
docs.openclaw.ai/gateway/security ("secrets on disk", "network"); OpenClaw skills docs; Hermes security docs.

OperationsAudit and incident response

  • openclaw security audit checks inbound access, tool blast radius, exec approvals, network exposure, permissions, plugins and policy drift; --deep probes the live gateway; --fix applies safe fixes (open groups → allowlists, file modes); --json for CI.
  • Run it after every config change and on a schedule; alert on drift.

When something goes wrong

  1. Contain: stop the gateway, bind to loopback, disable risky DMs and groups.
  2. Rotate: gateway token, remote client secrets, provider and API keys.
  3. Audit: logs, transcripts, recent config changes; rerun the deep audit.
docs.openclaw.ai/gateway/security ("security audit", "incident response").

ExerciseRed-team your own agent

  1. Give an agent email read, a web fetch tool, and file access to a folder with a fake secret.
  2. Plant an indirect injection in a web page and in an email asking it to send the secret out.
  3. Run it with no defenses, then with each: Rule of Two split, approvals (manual), sandbox with no egress, reader sub-agent.
  4. Run openclaw security audit --deep before and after.

Measure

  • Attack success rate per defense (≥ 20 trials)
  • Benign task success rate (utility cost)
  • Approval prompts per task
  • Which OWASP agentic category each successful attack falls in
