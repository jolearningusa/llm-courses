How long-term memory is built

User memory, RAG and memory search tools: how an agent writes what it learns, stores it, finds it again, and gets it back into the context window. With the real designs in Hermes Agent, OpenClaw and Letta.

FramingThe context window is not memory

  • The model is stateless. Anything it "remembers" across sessions was written somewhere and put back into the prompt by the harness.
  • So long-term memory is a small data system: a write path, a store, an index and a read path.
  • In OS terms the context window is RAM and the memory store is disk. The harness decides what gets paged in (MemGPT).

Three kinds of long-term memory

SemanticFacts and preferences about the user or world: "prefers Rust", "lives in Seattle". Kept as a profile or a growing collection.
EpisodicWhat happened: past sessions, decisions, worked examples. Often reused as few-shot examples.
ProceduralHow to act: system prompt, rules, skills. Usually updated by reflection.
Taxonomy as used in the LangGraph memory docs (docs.langchain.com/oss/python/langgraph/memory); OS framing: Packer et al., MemGPT (arXiv:2310.08560).

Memory systems reuse RAG machinery (embeddings, vector + BM25 search, reranking) for the read path. What they add is the write path and lifecycle. A search tool can sit on top of either one.

The pipelineSeven stages of a memory system

Every harness implements all seven stages. They differ in who triggers each one (the harness, the model, or a background job) and in the index they choose.

Write pathCapture and extract: when do memories get written?

Hot path (in the turn)

  • The model calls a write tool: Letta archival_memory_insert, Mem0-in-Hermes mem0_add, LanceDB memory_store.
  • Available immediately; costs latency and model attention.

Background (after the turn)

  • A hook or job extracts memories without the model asking: Hermes sync_turn, on_pre_compress, on_session_end.
  • OpenClaw flushes unwritten context into daily notes before compaction; Letta sleep-time agents rewrite memory between steps.
  • No reply latency; harder to decide when to run.

What extraction looks like (Mem0)

  1. Look up related existing memories.
  2. LLM extracts preferences, decisions, plans.
  3. Deduplicate, then embed each memory.
  4. Extract entities for entity matching.
from mem0 import Memory
m = Memory()
m.add(messages, user_id="alice")
# infer=False stores raw text, no extraction

In practice: hybrid

OpenClaw's memory_search runs vector and BM25 in parallel and merges results (either side runs alone if the other is unavailable). Graphiti merges semantic + BM25 with Reciprocal Rank Fusion and can rerank by graph distance from a node.

docs.openclaw.ai concepts/memory-search; graphiti-core README (pypi); Hermes memory-providers docs.

RetrieveScoring: relevance is not enough

  • Relevance: embedding similarity and/or BM25.
  • Recency: newer memories score higher. OpenClaw decays dated daily notes; MEMORY.md never decays.
  • Importance: how much a memory matters, often rated by an LLM at write time.
  • Generative Agents combine recency + importance + relevance; OpenClaw's memory_search ranks by relevance, recency decay and importance.
  • Mem0 search fuses semantic, keyword, entity and temporal signals.
  • Scope first: filter by user_id / agent_id / run_id before ranking, or memories leak across users.

Better chunks, better recall

Anthropic's Contextual Retrieval prepends a short, chunk-specific context before embedding and BM25-indexing each chunk. Top-20 retrieval failure rate:

Contextual embeddings−35% (5.7% → 3.7%)

Read pathTwo ways memory gets back into the prompt

The "search tool" is just option B over the memory store. Most production harnesses use both: a small auto-injected profile plus a tool for deep recall.

Read pathThe hybrid pattern most harnesses converge on

Tier 1 · always resident

A small curated profile pinned in the prompt: MEMORY.md / USER.md, Letta core memory blocks.

Cheap to reason about. Keep it small, and freeze it per session to keep the prompt prefix cacheable (Hermes).

Tier 2 · auto-recall per turn

The harness prefetches a few relevant memories and injects them as hidden context.

Hermes provider prefetch (background, non-blocking); OpenClaw trigger injection (≤3 curated entries); LanceDB auto-recall.

Tier 3 · on demand

Large or noisy stores (transcripts, daily notes, archival) only through tools.

OpenClaw memory_search; Letta archival_memory_search; Hermes session_search and provider tools.

Escalation: a recall sub-agent

OpenClaw's Active Memory (default mode escalate) runs a blocking recall sub-agent only when the message asks about the past and the rule-based lane found no strong match. It can also be set to always or off. This targets prior decisions and temporal or multi-hop questions without paying for search on every turn.

docs.openclaw.ai concepts/active-memory and memory-architecture; Hermes memory-providers docs; Letta archival memory docs.

Harness · Hermes AgentBuilt-in memory plus one external provider

  • Built-in (always on): MEMORY.md + USER.md, frozen snapshot per session; SQLite FTS5 session search across past conversations.
  • External provider: exactly one active, added via hermes memory setup or memory.provider.
  • An active provider prefetches before each turn (background, non-blocking) and its context is injected into the system prompt.
  • Its tools come from get_tool_schemas(); writes from sync_turn, on_pre_compress, on_session_end.

Recall lanes

  • Auto, no model call: up to 3 curated entries whose trigger phrases match the message.
  • Tool: memory_search / memory_get, hybrid vector + BM25. Daily notes and transcripts are only reachable this way: they "never auto-inject".
  • Escalation: Active Memory sub-agent.

memory-lancedb plugin

LanceDB vector store with auto-recall and auto-capture; tools memory_store, memory_recall, memory_forget.

docs.openclaw.ai/concepts/memory-architecture; docs.openclaw.ai concepts/memory-search, active-memory; hub.openclaw.ai/openclaw/plugins/memory-lancedb.

Harness · LettaMemGPT's hierarchy: the agent pages its own memory

  • Core memory blocks (label, description, value, limit) are always in the context window. The agent edits them with memory tools; blocks can be shared between agents via block_ids.
  • Archival memory is a vector database of passages with optional tags. It is not in context: it "must be queried on-demand via tools".
  • Conversation search retrieves past messages.
  • Sleep-time agents consolidate memory in the background (every N steps, default 5).
# the agent's own tools
archival_memory_insert(content, tags)
archival_memory_search(query)

# the developer can write passages too
client.agents.passages.insert(
    agent_id=agent.id,
    content="Alice prefers tea",
    tags=["prefs"])

Letta is the purest form of option B: apart from core blocks, recall happens only when the model calls a tool.

docs.letta.com memory blocks, archival memory (V1 SDK) and sleep-time agents; Packer et al., MemGPT (arXiv:2310.08560).

Beyond flat chunksStructured retrieval ideas memory systems borrow

Graph-shaped

  • GraphRAG: build an entity graph and community summaries for global, query-focused questions.
  • LightRAG: graph + vector dual-level retrieval with incremental updates.
  • HippoRAG: knowledge graph + Personalized PageRank, modeled on hippocampal indexing.
  • Zep / Graphiti: temporal graph built from episodes.

Hierarchy and context

  • RAPTOR: recursively cluster and summarize chunks into a tree; retrieve at any level.
  • Contextual Retrieval: add chunk-specific context before indexing.
  • Reflections (Generative Agents) and dreaming (OpenClaw) are the memory analogue: summaries stored as memories.
Edge et al. arXiv:2404.16130; Guo et al. arXiv:2410.05779; Gutiérrez et al. arXiv:2405.14831; Sarthi et al. arXiv:2401.18059; Rasmussen et al. arXiv:2501.13956.

EvaluationHow do you know memory works?

Benchmarks

  • LoCoMo: very long-term conversations (many sessions) with QA, summarization and generation tasks.
  • LongMemEval: five abilities: information extraction, multi-session reasoning, temporal reasoning, knowledge updates, abstention. Commercial assistants and long-context LLMs drop about 30% accuracy over sustained interactions.

What to measure in your own harness

  • Recall@k on a labeled set of "should remember" questions
  • Injection precision: share of injected memories actually used
  • Staleness: answers that use superseded facts
  • Abstention: says "I don't know" when nothing was stored
  • Tokens and latency added per turn, auto vs. tool
  • Cross-user leakage: always zero
Maharana et al., LoCoMo (arXiv:2402.17753); Wu et al., LongMemEval (arXiv:2410.10813).

Design checklistBuilding memory for your own agent

  1. Decide what to remember: semantic, episodic, procedural.
  2. Pick the write trigger: hot path tool, background hook, or both.
  3. Pick the index by question type: exact → BM25, fuzzy → vector, relational → graph. Usually hybrid.
  4. Pick the read trigger per tier: pinned, auto-recall, tool.
  5. Define update and forget rules before launch.
  6. Scope everything by user.
  7. Measure recall, staleness, cost.
