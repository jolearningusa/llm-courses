LLM AgentOS · 模块 1 讲座 · 组件 3

上下文管理器

决定模型在每次调用时看到什么：组装、选择、压缩与隔离上下文， 保持提示缓存（prompt cache）处于热状态，以及 Hermes Agent 和 OpenClaw 中可插拔的上下文引擎。

写入选择压缩隔离上下文引擎

为什么上下文是预算，而不是水桶

  • 注意力预算：每个 token 都会消耗它；上下文越长，召回越差。目标是使用最小的一组高信号 token。
  • 上下文腐烂（Context rot）：在 18 个模型上，输入越长，性能越不可靠，即使是简单任务也是如此；干扰项会让情况更糟。
  • 迷失在中间（Lost in the middle）：当相关信息位于输入的开头或结尾时，准确率最高（呈 U 形）。

它同时也是成本预算

  • Manus 报告其智能体的输入与输出 token 比约为 100:1。
  • Claude Sonnet 上缓存输入的成本约为未缓存输入的十分之一。
  • 因此 Manus 称 KV-cache 命中率是“生产阶段 AI 智能体最重要的单一指标”。
Anthropic, "Effective context engineering for AI agents" (2025 年 9 月 29 日); Chroma, "Context Rot" (2025 年 7 月 14 日); Liu et al., Lost in the Middle (arXiv:2307.03172, TACL); Ji, Manus 上下文工程经验 (2025 年 7 月 18 日)。

策略含义示例AgentOS 组件

设计时需要防范的上下文失效模式

中毒（Poisoning）（幻觉进入并持续存在）· 分心（Distraction）（上下文压倒了训练所得）· 混淆（Confusion）（无关上下文左右了回答）· 冲突（Clash）（上下文的各部分相互矛盾）。

组装什么进入窗口，按什么顺序

  • 把很少变化的内容放在最前面，这样提供商的提示缓存（以及 vLLM 前缀缓存）就能复用它。
  • 把最新、与任务最相关的内容放在最后，模型在那里的注意力较好（迷失在中间）。
  • OpenClaw 由基础提示、技能提示、引导上下文（bootstrap context）和每次运行的覆盖项组装系统提示，并受模型限制和压缩预留量约束。
  • Codex：服务器对最初的提示项排序（沙箱、配置、AGENTS.md 式指令、环境）；用户消息最后追加。
OpenClaw 智能体循环文档（提示组装）; OpenAI, "Unrolling the Codex agent loop"。

缓存感知的上下文保持前缀稳定

应该做

  • 保持上下文只追加（append-only）；绝不编辑之前的条目。若要在会话中途更改设置，就追加一条描述该更改的消息（Codex）。
  • 确定性地序列化（JSON 中保持稳定的键顺序）。
  • 在会话期间冻结注入的记忆（Hermes 在会话开始时冻结其 MEMORY.md / USER.md 快照）。
  • 在提供商需要的位置放置缓存断点。

不应该做

  • 在系统提示顶部放置时间戳。
  • 在任务中途增删工具；Manus 的做法是按状态屏蔽（mask） token logits，并用工具名前缀（browser_、shell_）来允许某一组工具。
  • 切换模型、沙箱模式或工作目录，却不预期缓存未命中。

测量它：vLLM 中的前缀缓存命中率（vllm:prefix_cache_hits / _queries），或提供商返回的缓存 token 数。

Manus 经验 1–2; Codex 智能体循环文章; Hermes 记忆文档; vLLM 指标。前缀缓存本身在模块 3 中讲解。

选择即时（just-in-time）上下文

  • 在上下文中保留轻量标识符（文件路径、已存储的查询、链接），需要时再用工具加载内容。
  • 权衡：比预加载慢，但更新鲜、更聚焦。
  • 混合方式很常见：Claude Code 预先加载 CLAUDE.md，并即时搜索文件。
  • 工具集过大会削弱工具选择。工具也要选择：对工具描述做 RAG，或屏蔽不可用的工具而不是移除它们。

从记忆中选择

记忆课件详细讲解了读取路径：固定画像、每轮自动召回，以及按需搜索工具（OpenClaw memory_search、Letta archival_memory_search）。

上下文管理器决定预算；记忆管理器决定什么值得花这笔预算。

Anthropic, "Effective context engineering for AI agents"; LangChain, "Context Engineering"; Manus 经验 2; 02_long_term_memory_deck.html。

压缩压缩（compaction）及其更轻量的近亲

技术方式示例
清除工具结果丢弃旧工具调用的原始输出；保留调用本身Anthropic 称之为“最安全、最轻量的压缩形式之一”
可恢复压缩丢弃内容，但保留找回的途径（URL、文件路径）Manus：丢弃网页，保留 URL
裁剪移除超出窗口的最旧消息简单，但会丢失信息
摘要压缩在接近上限时总结历史，并以摘要继续Claude Code 超过 95% 时自动压缩（LangChain）；Hermes 为 50% 预检 / 85% 网关，保留最近 20 条消息
不透明压缩提供商侧的压缩状态Codex /responses/compact → encrypted_content
层级摘要在 DAG 中对摘要再做摘要；原始消息保留且可展开OpenClaw lossless-claw 插件

压缩应先保证召回，再裁掉多余内容。绝不要把工具调用与其结果拆开。每次压缩之后都应预期前缀缓存未命中。

Anthropic 上下文工程文章; Manus 经验 3; LangChain 文章; Hermes 智能体循环文档; Codex 文章; lossless-claw README (clawhub.ai)。

写入与隔离窗口之外的笔记，窗口旁边的子智能体

写入：结构化笔记与复述

  • 智能体把笔记保存在窗口之外并重新加载：Anthropic 的 Claude 玩宝可梦（Pokémon）智能体在数千步中跟踪进度和地图。
  • Manus 的任务约需 50 次工具调用；它维护一个 todo.md 并随进展不断重写，使目标保持在近期注意力中。
  • 把错误的东西留着：把失败的动作和错误留在上下文中，让模型更新自己的信念。

隔离：干净的窗口

  • 子智能体在自己的窗口中探索，并返回精炼的摘要，通常为 1,000–2,000 个 token。
  • Hermes 的子智能体只能看到 goal 和 context 字段；只有它们的最终摘要返回给父智能体。
  • 沙箱把大体量输出（文件、日志）挡在模型上下文之外，直到需要时。
  • 不要被 few-shot 化：上下文中重复的过往动作会让智能体重复它们；加入受控的变化。
Anthropic 上下文工程文章; Manus 经验 4–6; Hermes 委派文档。

度量上下文管理器在尽职吗？

  • 每次调用的上下文 token 数在整个会话中的变化（OpenClaw 导出 openclaw.context.tokens）。
  • 缓存命中率：缓存 / 总输入 token；vLLM 中的前缀缓存命中。
  • 每个会话的压缩次数，以及跨越压缩的任务与未跨越压缩的任务的成功率对比。
  • 压缩后的召回：询问压缩之前的某个事实（在你自己的转录上做大海捞针测试）。
  • 每个任务的成本：在 100:1 的比例下，输入 token 占主导。

危险信号

  • 框架改动后缓存命中率下降
  • 智能体重复已经做过的工作（笔记丢失）
  • 回答与先前的决定相矛盾（冲突）
  • 上下文线性增长且没有压缩（膨胀）
指标：06_observability_evaluation_deck.html; OpenClaw OpenTelemetry 文档。

练习比较两种上下文引擎

  1. 从你的实验 3 引擎出发：阈值压缩，或清除工具结果。
  2. 实现第二种引擎：清除工具结果 + 待办复述，或带展开工具的层级摘要。
  3. 用每种引擎运行一个 40 步以上的任务（例如重构一个小型仓库），各运行三次。
  4. 使用可观测性课件中的设置进行埋点。

报告

  • 每个任务的 token 和成本
  • 缓存命中率
  • 压缩次数和压缩后召回得分
  • 任务成功率（pass^3）
  • 一个引擎丢失所需事实的例子
