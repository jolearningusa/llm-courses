LLM AgentOS · 模块 1 讲义 · 组件 1

智能体循环

AgentOS 的“进程”：一轮对话如何从用户消息运行到最终答案，以及 Hermes Agent、 OpenClaw、Codex CLI 和 Letta 如何在其中处理预算、工具、错误、中断、压缩和钩子。

迭代停止条件中断与转向钩子

核心思想一个循环：思考、行动、观察、重复

  • ReAct (Yao et al., ICLR 2023) 命名了这一模式：把推理与行动交错进行，并把观察结果反馈回去。
  • 如今模型会输出结构化的工具调用；Harness 运行它们并追加结果，直到模型以文本作答。
Yao et al., ReAct (arXiv:2210.03629); OpenAI, "Unrolling the Codex agent loop" (Jan 2026).

设计空间工作流与智能体

  • 工作流 (Workflow)：LLM 与工具通过预先定义的代码路径编排。控制流归 Harness 所有。
  • 智能体 (Agent)：LLM 动态地指挥自己的流程和工具使用。循环只负责底层机制。
  • 两者共同的构件：增强型 LLM（检索、工具、记忆）。
  • 智能体在循环中运行，因此要加入停止条件，例如最大迭代次数。

工作流模式（位于循环之内或周围）

  1. 提示链 (Prompt chaining)
  2. 路由 (Routing)
  3. 并行化（分段、投票）
  4. 编排者-工作者 (Orchestrator-workers)
  5. 评估者-优化者 (Evaluator-optimizer)

Harness 两者兼用：自由的智能体循环，加上工作流式的部件，如压缩、审批和子智能体委派。

Anthropic, "Building effective agents" (Dec 19, 2024), anthropic.com/research/building-effective-agents.

Harness · Hermes Agent一次迭代的内部

#AIAgent.run_conversation() (agent/conversation_loop.py) 中的步骤操作系统类比
1生成 task_id；把用户消息追加到历史进程启动
2构建或复用缓存的系统提示词 (prompt_builder.py)加载镜像
3历史过大时进行预检压缩换出页面
4把历史转换为 API 模式：chat_completions、codex_responses 或 anthropic_messagesABI
5注入临时层（预算警告、上下文压力）；在 Anthropic 上添加 prompt-caching 标记信号
6可中断的 API 调用 (_interruptible_api_call)阻塞式系统调用
7工具调用 → 执行、追加结果，回到步骤 4；文本 → 持久化并返回陷入 / 返回

每一轮结束后，消息保存到 SQLite (hermes_state.py)，记忆被刷新写入 MEMORY.md / USER.md。

hermes-agent.nousresearch.com/docs/developer-guide/agent-loop.

Harness · Codex CLI一轮就是一个不断增长的无状态提示词

  • 一个轮 (turn) 从用户输入运行到助手消息；当模型不再输出工具调用时结束。
  • 每个 Responses API 请求都携带 instructions、tools 和 input 条目，并重发完整历史。Codex 不使用 previous_response_id，以保持无状态并支持零数据保留 (Zero Data Retention)。
  • 从原理上说，重发的开销是平方级的。但由于每个新提示词都以此前完全相同的提示词开头，提示词缓存使采样大致呈线性。

什么会破坏缓存

  • 在对话中途更改 tools（一个 MCP bug 曾以不一致的顺序列出工具）
  • 更换模型
  • 更改沙箱配置、审批模式或工作目录

解决办法：绝不编辑之前的条目；追加一条描述变更的新开发者消息或用户消息。

Michael Bolin, OpenAI, "Unrolling the Codex agent loop" (Jan 23, 2026), openai.com/index/unrolling-the-codex-agent-loop. 关联模块 3（前缀缓存）。

控制停止条件与预算

Harness预算 / 超时达到上限时会发生什么
Hermes AgentIterationBudget 默认 500 (agent.max_turns)；子智能体受 delegation.max_iterations 限制（委派指南中为 250；agent-loop 页面写的是 50）智能体停止并返回摘要；在此之前会注入预算警告
OpenClaw运行超时 agents.defaults.timeoutSeconds = 172800 s（48 h）；模型空闲超时上限 120 s；agent.wait 30 s（仅等待）runEmbeddedAgent 中的中止计时器；diagnostics.stuckSessionWarnMs = 120 s 之后发出会话卡住警告
Codex CLI助手消息使本轮结束；上下文用 auto_compact_limit压缩而不是停止
Letta (MemGPT 时代)request_heartbeat 默认为 false：除非智能体请求下一步，否则停止在 letta_v1_agent 中弃用（2025 年 10 月）

设计准则

同时使用多种限制：步数、墙钟时间、token / 成本，以及“无进展”检测器（重复相同的工具和参数）。在硬性停止前先警告模型，使其能够收尾。

Hermes agent-loop docs; docs.openclaw.ai/concepts/agent-loop; Codex agent-loop post; letta.com/blog/letta-v1-agent.

行动在循环内运行工具

  • 安全时并行：Hermes 在主线程上运行单个工具调用，多个则在 ThreadPoolExecutor 中并发运行。
  • 交互时串行：像 clarify 这样的工具强制顺序执行。
  • 保持顺序：无论完成顺序如何，结果都按原始调用顺序返回。
  • 保持成对：每个工具结果始终与产生它的调用配对（压缩绝不拆开一对）。
  • 拦截操作系统级工具：Hermes 在常规分发之前，把 todo、memory、session_search、delegate_task 路由给智能体自身处理。

结果重新进入提示词之前

  • OpenClaw 会针对大小和图像清理工具结果；tool_result_persist 钩子可在写入前对其进行转换。
  • 危险命令会等待审批回调（Hermes tools/approval.py）。
  • OpenClaw 的 before_tool_call 可返回 { block: true } 来阻止调用。
Hermes agent-loop docs; OpenClaw agent-loop docs. 工具与沙箱另有专门课件。

韧性错误、重试与回退

模型错误

  • Hermes 在 429、5xx 和 401/403 时进行故障转移，按顺序尝试 fallback_providers；遇到 401/403 时先尝试刷新凭据。
  • 某个 Codex Responses 轮次若在仅有推理输出的状态下停滞，连续三次续接后，会以原因 incomplete_response 进行故障转移。
  • 辅助工作（视觉、压缩、网页提取）有各自的回退链。

工具错误与空轮次

  • 把错误作为工具结果返回给模型，并附足够的细节以便恢复，而不是让循环崩溃。
  • OpenClaw：如果没有可渲染的内容且有工具出错，会发送一条回退的工具错误回复。
  • OpenClaw 导出 openclaw.model.failover 和工具循环指标（可观测性课件）。

重试会成倍增加成本。按轮次统计重试次数，并对重试风暴发出告警。

Hermes agent-loop docs; OpenClaw agent-loop docs; 06_observability_evaluation_deck.html.

控制中断与转向

Hermes：可中断的模型调用

  • HTTP 调用在后台线程中运行；主线程等待响应、中断或超时。
  • 发生中断时，API 线程被放弃，其响应被丢弃：不会有部分响应进入历史。

OpenClaw：队列模式

steer默认。把新消息注入当前运行
followup在当前运行结束后再运行
collect把排队的消息合并到之后的一轮
interrupt中止当前运行，开始处理最新消息

转向发生在模型边界

  1. 模型请求工具调用。
  2. 这一批工具运行至完成。
  3. 排空排队的转向消息。
  4. 在下一次模型调用之前，把它们作为用户消息添加进去。

转向绝不会打断正在运行的工具，因此工具结果始终与其请求保持配对。

Hermes agent-loop docs; docs.openclaw.ai/concepts/queue-steering.

并发每个会话同一时间只运行一次

  • OpenClaw 按会话键 (session key) 串行化运行（会话通道 session lane），也可选择再经过全局通道。
  • 写入转录记录时需获取基于文件、感知进程的会话写锁；写入方最多等待 session.writeLock.acquireTimeoutMs（60 000 ms），之后会话被报告为忙碌。
  • agent RPC 立即返回 { runId, acceptedAt }；agent.wait 等待生命周期结束或出错。
  • 事件通过三个通道流式输出：tool、assistant、lifecycle（start / end / error）。

为什么要串行化？

同一份转录上的两个并发运行会使工具调用和结果交错，并破坏历史。按会话串行化能让每份历史保持线性，而不同会话仍可并行运行。

这是“每进程一把锁”的智能体版本；跨会话和跨智能体的调度见调度器课件。

docs.openclaw.ai/concepts/agent-loop (openclaw 2026.7).

内存压力循环内的压缩

Harness触发条件保留什么
Hermes Agent超过上下文窗口 50% 时进行预检压缩；网关在轮次之间于超过 85% 时自动压缩先刷新记忆，总结中间轮次，保留最后 20 条消息 (compression.protect_last_n)，绝不拆开工具调用对；开启一个子会话谱系
Codex CLI超过 auto_compact_limit调用 /responses/compact；得到一个带有不透明 encrypted_content 的 compaction 条目
OpenClaw接近上限时自动压缩发出 compaction 流事件，并可能重试；before_compaction / after_compaction 钩子；先把记忆刷新到每日笔记

压缩会改变提示词前缀，因此也会重置前缀缓存的复用（模块 3）。上下文管理器课件会深入比较各种策略。

Hermes agent-loop docs; Codex agent-loop post; OpenClaw agent-loop and memory-architecture docs.

Harness · Letta从 MemGPT 心跳到 letta_v1_agent

MemGPT 式循环（旧版）

  • 每个动作都是工具调用，包括通过 send_message 回复。
  • 每个工具都带 request_heartbeat；只有模型提出请求时循环才继续（默认 false）。
  • 推理由提示词引导：把 thinking 参数注入工具 schema。

letta_v1_agent（2025 年 10 月）

  • request_heartbeat 和 send_message 已弃用。
  • 与其他 Harness 一样，模型直接发出的助手消息使本轮结束。
  • 仅使用原生推理（OpenAI 用 Responses API；跨提供者处理加密的推理内容）。

教训：随着模型原生学会工具调用，Harness 把循环控制技巧从提示词中移除，转而放进 API 和 Harness 本身。

Letta, "Rearchitecting Letta's agent loop" (Oct 14, 2025), letta.com/blog/letta-v1-agent; Packer et al., MemGPT (arXiv:2310.08560).

失效模式智能体循环中会出什么问题

失效症状循环内的缓解措施
失控循环相同工具、相同参数，毫无进展迭代预算、重复检测、预算警告
过早停止任务未完成模型就作答结果检查、todo / 计划工具、评估者-优化者步骤
上下文泛滥巨大的工具输出塞满窗口截断并清理结果；把大型输出存为文件
孤立的工具调用中断或压缩后，有调用而无结果绝不拆开成对；丢弃部分响应
丢失用户输入运行期间收到的消息被忽略队列模式：steer 或 follow up
缓存抖动会话中途延迟和成本骤增只追加的历史、稳定的工具列表
运行挂起在提供者或工具上无限等待空闲与运行超时、卡住会话检测

练习编写一个最小的智能体循环

def run_turn(history, tools, budget=25):
    for step in range(budget):
        resp = model(history, tools=schemas(tools))
        history.append(resp.message)
        if not resp.tool_calls:
            return resp.text            # turn ends
        results = run_parallel(resp.tool_calls)
        for call, out in zip(resp.tool_calls, results):
            history.append(tool_result(call.id,
                                       truncate(out)))
        if repeated(history):
            history.append(user("You are repeating "
                                "the same call. Stop or "
                                "change approach."))
        if step == budget - 3:
            history.append(user("3 steps left: wrap up."))
    return summarize(history)            # budget hit

扩展它，然后与 Hermes 对比

  • 让模型调用可中断（线程 + 事件）。
  • 让工具结果保持调用顺序。
  • 添加在模型调用之间排空的转向队列。
  • 添加钩子：pre_tool_call、post_tool_call。
  • 每一步输出一个 span（可观测性课件）。
  • 度量：每个任务的步数和前缀缓存命中率。
