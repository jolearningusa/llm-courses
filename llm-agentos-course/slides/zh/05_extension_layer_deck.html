可扩展的内容两种框架中的扩展点

Hermes Agent 插件类型

  • 通用（可多选）：工具、钩子、斜杠命令、CLI 命令、技能。
  • 记忆提供者（单选）。
  • 上下文引擎（单选）。
  • 模型提供者（可加载多个；每次运行选用一个）。
  • 另有平台和审批传输（register_platform、register_approval_transport）。

OpenClaw 原生插件

  • 工具、钩子、渠道、提供者、CLI 后端、技能。
  • 独占类型 "memory" 和 "context-engine"，通过 plugins.slots.memory 和 plugins.slots.contextEngine 选择。
  • 兼容的捆绑包：Codex、Claude 和 Cursor 的插件布局会被映射到 OpenClaw 的清单库存中。

为什么需要清单

  • OpenClaw 读取清单来在不执行插件代码的情况下校验配置；清单缺失或无效即为插件错误。
  • 只有 id 和 configSchema 是必需的；可选字段包括 kind、channels、providers、skills、uiHints、requiresPlugins、enabledByDefault；version 仅供参考。
  • 运行时钩子和入口点保留在代码和 package.json 中。
  • Hermes v2 清单新增 api_version 和 requires_plugins；更改 update_url 需要批准。

一个入口点，多项注册：每一部分何时运行由框架而非插件决定。这正是插件可组合的原因。

OpenClaw 排序规则

  • 处理器按 priority 降序运行；同级按注册顺序。
  • 受信任的工具策略先于普通的 before_tool_call 钩子运行。
  • 终止性拦截会跳过较低优先级的处理器。
  • before_agent_run 和 before_install 在输出有误或出错时以失败关闭（fail closed）。
  • 观察者的失败会被记录并忽略。
Hermes 插件文档（“Available hooks”）；docs.openclaw.ai/plugins/hooks.

独占角色槽位：每个角色恰好一个提供者

  • 有些组件在每个会话中必须恰好有一个所有者：谁存储记忆，谁组装并压缩上下文。
  • OpenClaw：插件声明 kind: "memory" 或 "context-engine"；配置通过 plugins.slots.* 选择其一。为槽位选中某个插件会强制启用它，但 plugins.deny 和 enabled: false 仍然优先。
  • Hermes：记忆提供者和上下文引擎是单选的（memory.provider、context.engine）；默认引擎为 compressor。
  • OpenClaw 的 legacy 上下文引擎是默认的槽位所有者（上下文管理器讲义）。

为什么不让两个同时运行？

两个上下文引擎都会改写对话记录；两个记忆提供者都会注入召回内容，使 token 翻倍。槽位把这种冲突变成配置错误，而不是运行时的意外。

与“同一时刻只有一个显示驱动”或“只有一个 init 系统”的思路相同。

docs.openclaw.ai/tools/plugin（“slots”）；Hermes 插件文档（“plugin types”）；配套讲义第 28 张幻灯片。

进程内还是进程外插件 vs. MCP 服务器

进程内插件MCP 服务器
运行方式框架内部的代码（Python / Node）独立进程或远程服务
能力任何事：钩子、槽位、提示编辑、工具提供工具、资源、提示；向用户请求输入（elicitation）
可移植性仅限一个框架任何 MCP 客户端
故障 / 信任崩溃或被攻陷 = 框架本身进程边界；环境变量被过滤（Hermes 仅传递一份简短的允许列表）
契约框架 API 版本协议版本 + 每个请求 _meta 中的客户端能力

自 MCP 2026-07-28 起，不再有 initialize 握手，也不再有会话：每个请求都携带自己的协议版本、客户端信息和能力，客户端可先调用可选的 server/discover。Sampling、roots 和 logging 已被弃用。

MCP 2026-07-28 发布说明（blog.modelcontextprotocol.io/posts/2026-07-28）；Hermes 安全文档（MCP 环境变量过滤）。Hermes plugins.isolation: host 将用户插件运行在单独的宿主进程中。

  • Claude Code 插件（2025 年 10 月 9 日，公开测试版）：斜杠命令、子智能体、MCP 服务器和钩子的任意组合；/plugin marketplace add owner/repo，然后 /plugin install。
  • OpenClaw 可安装兼容 Claude 的市场插件（--marketplace），并映射 Codex、Claude 和 Cursor 的捆绑包。

趋势

插件正在成为软件包：技能 + MCP 服务器 + 钩子 + 命令一起交付，可在共享布局的各框架间安装。

兼容层（OpenClaw 读取其他厂商的捆绑包）正是事实标准先于正式标准形成的方式。

版本管理保持插件兼容

  • 声明所针对的 API：Hermes 清单 v2 的 api_version；MCP 的 protocolVersion。
  • 声明依赖：Hermes requires_plugins，OpenClaw requiresPlugins。
  • 用别名实现弃用：OpenClaw 为兼容而保留 deactivate 作为 gateway_stop 的已弃用别名，保留 before_agent_start，并用 legacyPluginIds 处理重命名。
  • 不运行代码即可校验配置：清单中的 JSON Schema。
  • 生产环境中锁定版本：OpenClaw 推荐固定版本；Hermes 技能中心在更新时会跳过本地编辑过的技能，除非使用 --force。

插件作者检查清单

  • 语义化版本 + 目标 API 版本
  • 配置模式带 additionalProperties: false
  • 对钩子做特性检测；不要假定新钩子一定存在
  • 决策类钩子失败关闭，观察类钩子失败开放
  • 每个钩子都设置超时
Hermes 插件文档；OpenClaw 清单、插件和钩子文档；MCP 生命周期规范。

安全插件是以智能体权限运行的代码

  • Hermes：capabilities 是“a consent and audit layer, not isolation”（同意与审计层，而非隔离）；插件是进程内的 Python。安装时扫描，给出 safe / caution / dangerous 结论。
  • OpenClaw：“Treat plugin installs like running code”（把安装插件视同运行代码）；原生插件在进程内加载；security.installPolicy 在安装前运行运维方策略命令；before_install 钩子可以拦截并失败关闭。
  • 技能供应链攻击（ClawHavoc，技能讲义）同样适用于插件，而且插件的权力更大。

有效的控制措施

  • 默认关闭；显式允许列表（plugins.allow、plugins.enabled）
  • 绝不自动加载克隆仓库中的插件
  • 锁定版本；更新时审查差异
  • 尽可能放在进程外（MCP、Hermes plugins.isolation: host）
  • 审计：openclaw security audit 覆盖插件
Hermes 插件文档（“security”）；docs.openclaw.ai/tools/plugin（“security”）；OpenClaw 安全文档；访问控制讲义。

练习一个功能，三种扩展机制

  1. 功能：“记录智能体运行的每条 shell 命令，并拦截 curl | sh”。
  2. 分别实现为 (a) 带 pre_tool_call 钩子的 Hermes 插件，(b) 带 before_tool_call 的 OpenClaw 插件，(c) 封装 shell 执行的 MCP 服务器。
  3. 为每个插件添加带配置模式的清单；给它一个错误的配置，看看哪里会失败。
  4. 再安装一个同样钩住工具调用的插件；检查排序。

对比

  • 代码行数和设置步骤
  • 模型能绕过它吗？（钩子：不能。MCP 封装：如果同时存在原生 shell 工具则可以。）
  • 每次工具调用增加的延迟
  • 插件崩溃时会发生什么
