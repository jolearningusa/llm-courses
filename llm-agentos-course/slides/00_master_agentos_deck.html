Treating LLM agents as an operating-system problem: scheduling, context and memory management, KV-cache as a system resource, tools and isolation, and harnesses that rewrite themselves. Every component is mapped to how Hermes Agent, OpenClaw, Letta and AIOS actually implement it.

MotivationWhy talk about an "AgentOS"?

  • An agent is a long-running program: many LLM calls, tool calls and waits, not one request.
  • Many agents share scarce resources: GPU time, context windows, KV-cache memory, tools, credentials.
  • Without an OS layer, every agent re-solves scheduling, memory and isolation, usually badly.
  • Today's open "harnesses" (Hermes Agent, OpenClaw, Letta) are converging on the same OS-like components. This course names them and compares implementations.

The questions an OS answers

  • Who runs next? → scheduling
  • What stays resident? → context & memory management
  • What can a program touch? → sandboxing & access control
  • How is it extended? → plugin APIs ("drivers")
  • Is it healthy? → metrics & evaluation
Framing: Packer et al. (MemGPT, arXiv:2310.08560); Ge et al. (LLM as OS, Agents as Apps, arXiv:2312.03815); Mei et al. (AIOS, arXiv:2403.16971).

Context switching an LLM

Round-robin can pause an agent mid-generation. The context manager saves state so another agent runs, then resumes:

  • Text-based: save decoded output so far (works with closed API models).
  • Logits-based: save the intermediate search-tree state for finer-grained resume (open models).

Agents are written against the AIOS SDK (Cerebrum), which turns their calls into kernel syscalls.

Mei et al., arXiv:2403.16971 · github.com/agiresearch/AIOS · github.com/agiresearch/Cerebrum

Module 1Scheduling whole agent programs

Autellix (2025)

Intercepts LLM calls with program-level context; preempts and prioritizes each call by its program's previously completed calls, cutting head-of-line blocking. Reports 4–15× program throughput vs. vLLM at equal latency.

Continuum (2025)

When a request will make a tool call, pin its KV-cache on GPU for a time-to-live set from reload cost and queueing delay; pair with program-level FCFS. Over 8× better average job completion time.

KVFlow (NeurIPS 2025)

Builds an Agent Step Graph; each agent's steps-to-execution score drives KV eviction, and the next agents' KV is prefetched CPU→GPU in the background.

ThunderAgent (2026)

Models a workflow as an "LLM Program" spanning KV-cache, system state and tool assets (disk, ports); a program-aware scheduler raises KV hit rate and a tool resource manager prepares environments asynchronously.

Autellix arXiv:2502.13965 · Continuum arXiv:2511.02230 · KVFlow arXiv:2507.07400 · ThunderAgent arXiv:2602.13692

Module 1The context manager: select, compress, isolate

The agent loop appends every action and observation, so the input keeps growing, and long inputs degrade quality (lost-in-the-middle, "context rot"). The context manager's job is to put in what is needed and clear out what isn't.

  • Select: RAG over documents, tool RAG, memory RAG; just-in-time loading by reference.
  • Compress: summarize old turns; keep outcomes, drop click-by-click detail; offload to files.
  • Isolate: give subtasks to subagents with clean contexts that return only a summary.

Production lessons

  • "KV-cache hit rate is the single most important metric" (Manus): keep the prefix stable, make context append-only, serialize deterministically.
  • Mask tools rather than removing them mid-task.
  • Use the file system as external memory; make compression reversible (keep the URL, drop the page).
  • Compaction + structured note-taking + subagents for long horizons (Anthropic).
Hung-yi Lee, GenAI-ML 2025 Fall, "From LMs to AI Agents" (Agent.pdf) · Manus blog, Jul 2025 · Anthropic Engineering, Sep 2025

Modules 2–3Two memory planes

The planes interact: a Plane-1 edit to the prompt prefix invalidates Plane-2 cache. Hermes freezes its memory snapshot for the whole session for exactly this reason.

Module 2MemGPT / Letta: virtual context

  • The context window is "RAM"; the agent pages data in and out itself through tool calls.
  • Memory blocks: label, description, value, character limit; pinned in context. Can be read_only.
  • Archival memory: vector store of passages, queried with archival_memory_search.
  • Conversation search recovers messages that fell out of the window.
  • A block can be shared by several agents (Lab 1C), and sleep-time agents rewrite shared blocks in the background every N steps (default 5).
shared = client.blocks.create(
    label="sprint_state",
    value="Phase: scheduler benchmark",
    limit=2000)

for name in ["supervisor", "worker"]:
    client.agents.create(
        name=name, model=MODEL,
        memory_blocks=[{"label": "persona",
            "value": f"I am the {name}"}],
        block_ids=[shared.id])  # same block

# background memory consolidation
client.agents.create(..., enable_sleeptime=True)
Packer et al., arXiv:2310.08560 · Lin et al., Sleep-time Compute, arXiv:2504.13171 · docs.letta.com (memory blocks, archival memory, sleep-time agents)

Module 2Structuring long-term memory

Zep / Graphiti

Bi-temporal knowledge graph: timeline T (when facts held) and T′ (when ingested). A contradicting new edge sets the old edge's t_invalid instead of deleting it.

A-MEM

Zettelkasten notes: each memory gets context, keywords and tags and is linked to related notes; new memories can update older notes' descriptions.

Mem0

Extract salient facts, then an LLM picks ADD / UPDATE / DELETE / NOOP against similar memories via a tool call. Mem0g stores a directed labeled graph.

MemSkill

Memory operations as evolvable skills: a controller picks skills, an LLM executor applies them, a designer refines or adds skills from hard cases.

Zep arXiv:2501.13956 · A-MEM arXiv:2502.12110 · Mem0 arXiv:2504.19413 · MemSkill arXiv:2602.02474 · Survey: Du, arXiv:2603.07670

Module 3KV-cache as paged memory

PagedAttention (vLLM)

  • KV-cache split into fixed-size blocks mapped through a per-sequence block table, like virtual-memory pages.
  • Near-zero fragmentation; blocks shared copy-on-write across sequences.

RadixAttention (SGLang)

  • Keeps past KV in a radix tree keyed by tokens; any request sharing a prefix reuses it; LRU eviction.

Why agents care

Agents resend the same system prompt, tool schemas and history every turn. If the prefix is byte-identical, only the new suffix is prefilled.

Anything that rewrites the head of the prompt (timestamps, re-ordered tools, early compaction, mid-session memory edits) throws the cache away.

Harness-side answers: Hermes freezes memory at session start and applies prompt-cache breakpoints; Manus keeps context append-only.

Kwon et al., arXiv:2309.06180 · Zheng et al., arXiv:2312.07104 · Hermes developer guide: architecture

Module 3Beyond exact-prefix reuse

  • Agent prompts are assembled from pieces (skills, retrieved docs, tool outputs); the same piece often appears at a different offset.
  • LMCache stores KV in chunks (256 tokens in its examples) across GPU, CPU DRAM and disk, and shares it across engine instances.
  • Reusing a chunk at a non-prefix position needs CacheBlend: reuse the chunk's KV and recompute a small subset of tokens to fix cross-attention (LMCACHE_ENABLE_BLENDING).
  • AsymCache: Multi-Segment Attention + matching eviction + adaptive chunking for lossless segmented KV management.
# lmcache_config.yaml
chunk_size: 256
local_cpu: true
max_local_cpu_size: 64   # GiB

# vllm serve (Lab 2)
vllm serve Qwen/Qwen3-8B \
  --kv-offloading-backend lmcache \
  --kv-offloading-size 64
docs.lmcache.ai (CPU offload; blending) · Yao et al., CacheBlend, arXiv:2405.16444 · Shi et al., AsymCache, arXiv:2606.02964

Cache engineering (AKV)

Instead of context engineering (trim or summarize history, then re-prefill), the agent directly controls its active KV-cache:

  • Drop: exclude chosen entries from future attention.
  • Repos: adjust positions of retained keys.

The AKV engine keeps a stateless, API-compatible interface and handles stateful reuse internally, since identical tokens can now map to different caches.

Ganjihal, arXiv:2604.26968 · Fu et al., Cache Engineering for Agents, arXiv:2610.28577

Module 4Memory is an attack surface

Threats follow the memory lifecycle. Each phase has its own attacks and defenses:

1 · Write

Poisoned content enters memory (via a web page, email or tool output).

2 · Store

Tampering or leakage at rest.

3 · Retrieve

Entries engineered to be recalled for target queries.

4 · Execute

Recalled memory steers tool calls and actions.

5 · Share & propagate

Shared blocks spread a poisoned fact to other agents.

6 · Forget & rollback

Can a bad memory be removed and its effects undone?

Lin et al., A Survey on Long-Term Memory Security in LLM Agents, arXiv:2604.16548

Module 4Defenses and access control

A-MemGuard

  • Consensus validation: compare reasoning paths derived from several related memories; a poisoned entry diverges.
  • Dual memory: detected failures become "lessons", stored separately and consulted before acting.
  • No change to the agent's core architecture.

Agent libOS

Separates operation admission (identity, capabilities, approvals, budgets) from information-flow admission, so a self-evolving agent's new tools and skills don't silently gain authority.

What harnesses ship today

  • AIOS: privilege groups + confirmation for irreversible ops.
  • Hermes: dangerous-command detection and approval prompts; DM pairing; controlled env/credential passthrough to sandboxes.
  • OpenClaw: device pairing; optional sandbox (Docker by default), which docs call "not a perfect security boundary".
  • Letta: read_only blocks for shared policy.
Wei et al., arXiv:2510.02373 (ICML 2026 per authors' repo) · Zhang, Agent libOS, arXiv:2606.03895 · harness docs (slides 22–25)

Module 6Measuring the OS and evaluating trajectories

  • Throughput: agent tasks or tokens per second.
  • Latency: TTFT and P99 per LLM / tool syscall.
  • KV-cache hit rate and prefill tokens saved.
  • Fairness across n concurrent agents:

J(x) = (Σ xi)² / (n · Σ xi²)

J = 1 when all agents get equal service; 1/n when one gets everything.

Trajectory (tool-call sequence) + response evaluation with Google ADK:

adk eval <AGENT_MODULE_FILE_PATH> \
  <EVAL_SET_FILE_PATH_OR_ID> \
  [--config_file_path=test_config.json]

# defaults when no criteria are given
{ "criteria": {
    "tool_trajectory_avg_score": 1.0,
    "response_match_score": 0.8 } }
Jain, Chiu & Hawe, DEC-TR-301 (1984) · adk.dev/evaluate · Yehudai et al., Survey on Evaluation of LLM-based Agents, arXiv:2503.16416

Module 7Harness²: harnesses that improve themselves

  • Model weights stay fixed; the harness changes.
  • Task-level recursion: propose harness edits, probe them on the same task, compose a refined harness from behavioral contrasts. No ground-truth feedback.
  • Harnessing-level recursion: keep the adopted harness and the evidence-supported lessons for future tasks.
