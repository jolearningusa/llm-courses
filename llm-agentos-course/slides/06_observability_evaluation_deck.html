Observing and evaluating an AgentOS

Logging, tracing, telemetry, dashboards and evals: how to tell whether a harness is healthy, and whether its quality is going up or down. With the real exporters in OpenClaw, Hermes Agent and vLLM.

TracesMetricsOpenTelemetry GenAIEvalsDashboards

MotivationWhy agents are harder to monitor than services

  • Non-deterministic: the same input can take a different path each run.
  • Long and branching: one task is dozens of model calls, tool calls, memory reads and sub-agents.
  • Failures are often silent: the agent says "booked" but nothing was booked. The transcript and the outcome disagree.
  • Cost is a quality metric: tokens, retries and loops cost money even when the answer is right.
  • The harness changes often: prompts, tools, models and plugins, so regressions are constant.

Four questions, four signals

What happened?Traces: a span tree per run
What exactly was said?Logs and captured content (opt-in)
How is it running?Metrics: latency, tokens, cost, queues
Is it any good?Evals: graded tasks, scores on traces
Transcript vs. outcome: Anthropic, "Demystifying evals for AI agents" (Jan 2026).

Where signals come fromThree layers of an AgentOS emit telemetry

One trace ID should tie the three together: OpenClaw sends a W3C traceparent header on provider calls when the transport allows it.

TracesAnatomy of an agent trace

  • A run is a tree of spans: agent → model calls → tool calls → sub-agents.
  • Each span carries timing, tokens, cost and status; content (prompts, tool args) is optional.
  • Group runs by session (conversation) and by task (eval case).
  • The tree is the debugging unit: you read it to find the step that went wrong.

Two things to know

  • Status: Development. Names can still change; opt in to the newest with OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental.
  • Content is off by default. Many instrumentations turn it on with OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=true.
  • OpenInference (Arize) is a parallel convention used by Phoenix; the Hermes OTel plugin emits both.
  • The conventions moved to their own repo: open-telemetry/semantic-conventions-genai.

Harness · Hermes AgentTwo observability plugins, two privacy defaults

Bundled: observability/langfuse

  • Opt-in: hermes plugins enable observability/langfuse.
  • Root span per turn ("Hermes turn"), one generation per LLM call (model, usage, cost, latency), one observation per tool call.
  • Sessions grouped by Hermes session ID (task ID for sub-agents).
  • Fail-open: missing keys or SDK becomes a silent no-op.
  • HERMES_LANGFUSE_SAMPLE_RATE, HERMES_LANGFUSE_MAX_CHARS (12000).

Community: hermes-otel

  • Turns hooks (pre_llm_call, post_tool_call, subagent_start, …) into a span tree.
  • Emits OpenInference and gen_ai.* attributes; tested with Phoenix, Langfuse, LangSmith, Jaeger, Tempo, SigNoz, Honeycomb and more.
  • Config in ~/.hermes/hermes_otel.yaml.
  • Default content_capture: full: prompts, responses and tool data go to every backend unless set to preview or off.

Compare with OpenClaw, where content is off by default. Check the capture default of every exporter before pointing it at a shared backend.

langfuse.com/integrations/other/hermes; hermes-agent.nousresearch.com/docs/plugins/hermes_otel (requires Hermes 0.21+).

Why agent builders care

  • Agents resend long, mostly identical prompts. A falling prefix-cache hit rate after a harness change usually means the prompt prefix stopped being stable (for example, memory edited mid-session).
  • Rising queue time with flat model latency means the scheduler, not the model, is the bottleneck.
  • KV usage near 1.0 predicts preemption and latency spikes.

BehaviorDetecting agent pathologies from telemetry

Loops

Same tool, same args, again and again. OpenClaw exports openclaw.tool.loop as both a span and a metric.

Fix: loop detection in the harness, step limits, better tool errors.

Stuck sessions

A run that never finishes or waits forever on a tool. OpenClaw: openclaw.session.stuck, stuck_age_ms, recovery counters.

Fix: timeouts, heartbeats, recovery.

Context pressure

Context tokens creep toward the window; compactions fire every few turns. Watch openclaw.context.tokens and compaction counts.

Fix: better context engine (Module 1), memory tiers (memory deck).

Retry storms

Errors trigger retries that trigger more errors; tokens spike with no progress.

Silent wrong success

Final message claims success, environment disagrees. Only an outcome check catches it.

Provider drift

Same harness, new model version: latency, cost or tool-call style shifts. Track gen_ai.response.model.

EvalsVocabulary for agent evaluation

TaskOne test case: inputs + success criteria
TrialOne attempt at a task; run several, outputs vary
GraderLogic that scores one aspect of a trial
TranscriptFull record of a trial: outputs, tool calls, reasoning (the trace)
OutcomeFinal state of the environment after the trial

Grade the outcome where you can (is the reservation in the database?), and the transcript for how the agent got there.

GraderStrengthsWeaknesses

Anthropic Engineering, "Demystifying evals for AI agents" (Jan 9, 2026), anthropic.com/engineering/demystifying-evals-for-ai-agents.

EvalsReliability: pass@k is not pass^k

  • pass@k: probability that at least one of k trials succeeds. Rises with k. Fine when one success is enough (a coding attempt you can verify).
  • pass^k: probability that all k trials succeed. Falls with k. The right metric for customer-facing agents that must be consistent.
  • τ-bench: gpt-4o-class function-calling agents succeed on <50% of tasks, and pass^8 is below 25% in the retail domain.

Capability vs. regression suites

  • Capability: what can it do? Start with a low pass rate to climb.
  • Regression: does it still do what it did? Should sit near 100%; run on every harness change.
  • Capability tasks that saturate "graduate" into the regression suite.
  • Read transcripts from many trials: a failing score can be a bad grader.
Yao, Shinn, Razavi, Narasimhan, τ-bench (arXiv:2406.12045); Anthropic, "Demystifying evals for AI agents".

EvalsLLM-as-judge: useful, biased, calibrate it

  • Known judge biases: position (prefers the first or second answer), verbosity (prefers longer answers), self-enhancement (prefers its own model family's outputs).
  • Mitigations: swap answer order and average, use rubrics with yes/no checks, use a different model family as judge, sample several judgments.
  • Calibrate against human labels on a few dozen cases before trusting a judge on thousands.

Attach scores to traces

Store judge results as scores on the trace they graded (Langfuse, Phoenix and LangSmith all support this). Then a dashboard can slice quality by model, harness version, tool or user, and you can open the exact transcript behind any low score.

Zheng et al., "Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena" (arXiv:2306.05685); Anthropic, "Demystifying evals for AI agents".

ProcessThe quality loop: offline and online

  • Every production failure that a human confirms becomes a regression task, so the suite tracks reality.
  • Harness² (Module 7) automates part of this loop: it proposes harness edits, probes them on the task, and keeps evidence-backed lessons.

Lab ideaInstrument a harness and compare two configurations

  1. Run a local trace backend (Phoenix or Jaeger) and Prometheus + Grafana.
  2. Enable tracing in the harness: OpenClaw diagnostics-otel, or Hermes with hermes-otel (content_capture: preview).
  3. Point Prometheus at the Lab 2 vLLM server's /metrics.
  4. Write 10 tasks with outcome checks; run each 4 times (k = 4).
  5. Run with config A and config B (for example, two context engines from Lab 1).

Report

  • pass@1 and pass^4 per config
  • Tokens, $ and P95 latency per task
  • Prefix-cache hit rate per config
  • One trace of a failure, with the step that went wrong
  • Which config you would ship, and why
