The context manager

Deciding what the model sees on every call: assembling, selecting, compressing and isolating context, keeping the prompt cache warm, and the pluggable context engines in Hermes Agent and OpenClaw.

WriteSelectCompressIsolateContext engines

WhyContext is a budget, not a bucket

  • Attention budget: every token draws it down; recall from context degrades as it grows. Aim for the smallest set of high-signal tokens.
  • Context rot: across 18 models, performance became less reliable as input length grew, even on simple tasks; distractors made it worse.
  • Lost in the middle: accuracy is highest when the relevant information is at the start or end of the input (U-shaped).

And it is a cost budget

  • Manus reports about 100:1 input-to-output tokens for its agent.
  • Cached input on Claude Sonnet costs about a tenth of uncached input.
  • So Manus calls KV-cache hit rate "the single most important metric for a production-stage AI agent".
Anthropic, "Effective context engineering for AI agents" (Sep 29, 2025); Chroma, "Context Rot" (Jul 14, 2025); Liu et al., Lost in the Middle (arXiv:2307.03172, TACL); Ji, Manus context-engineering lessons (Jul 18, 2025).

Context failure modes to design against

Poisoning (a hallucination enters and persists) · Distraction (context overwhelms training) · Confusion (irrelevant context steers the answer) · Clash (parts of the context contradict each other).

LangChain, "Context Engineering" (Jul 2, 2025), citing Drew Breunig for the failure modes. Master deck slide 8 introduced select / compress / isolate.

AssembleWhat goes into the window, in what order

  • Put what rarely changes first, so the provider's prompt cache (and vLLM prefix cache) can reuse it.
  • Put the newest and most task-relevant content last, where models attend well (lost in the middle).
  • OpenClaw assembles the system prompt from the base prompt, skills prompt, bootstrap context and per-run overrides, within model limits and a compaction reserve.
  • Codex: the server orders the first prompt items (sandbox, config, AGENTS.md-style instructions, environment); the user message is appended last.
OpenClaw agent-loop docs (prompt assembly); OpenAI, "Unrolling the Codex agent loop".

Cache-aware contextKeep the prefix stable

Do

  • Keep context append-only; never edit earlier items. To change settings mid-session, append a message describing the change (Codex).
  • Serialize deterministically (stable key order in JSON).
  • Freeze injected memory for the session (Hermes freezes its MEMORY.md / USER.md snapshot at session start).
  • Place cache breakpoints where the provider needs them.

Don't

  • Put a timestamp at the top of the system prompt.
  • Add or remove tools mid-task; Manus instead masks token logits per state and uses tool-name prefixes (browser_, shell_) to allow groups.
  • Switch model, sandbox mode or working directory without expecting a cache miss.

Measure it: prefix-cache hit rate in vLLM (vllm:prefix_cache_hits / _queries) or cached-token counts from the provider.

Manus lessons 1–2; Codex agent-loop post; Hermes memory docs; vLLM metrics. Module 3 covers prefix caching itself.

SelectJust-in-time context

  • Keep lightweight identifiers (file paths, stored queries, links) in context and load content with tools when needed.
  • Trade-off: slower than pre-loading, but fresher and more focused.
  • Hybrids are common: Claude Code loads CLAUDE.md up front and searches files just in time.
  • Large tool sets degrade tool choice. Select tools too: RAG over tool descriptions, or mask unavailable tools instead of removing them.

CompressCompaction and its lighter cousins

TechniqueHowExample
Tool-result clearingDrop raw outputs of old tool calls; keep the callAnthropic calls it "one of the safest lightest touch forms of compaction"
Restorable compressionDrop content but keep a way back (URL, file path)Manus: web page dropped, URL kept
TrimmingRemove oldest messages beyond a windowSimple, loses information
Summary compactionSummarize history near the limit, continue with the summaryClaude Code auto-compact past 95% (LangChain); Hermes 50% preflight / 85% gateway, last 20 messages kept
Opaque compactionProvider-side compressed stateCodex /responses/compact → encrypted_content
Hierarchical summariesSummaries of summaries in a DAG; raw messages kept and expandableOpenClaw lossless-claw plugin

Tune compaction for recall first, then cut what is superfluous. Never split a tool call from its result. Expect a prefix-cache miss after every compaction.

Write & isolateNotes outside the window, sub-agents beside it

Write: structured notes and recitation

  • Agents keep notes outside the window and reload them: Anthropic's Claude-plays-Pokémon agent tracks progress and maps across thousands of steps.
  • Manus tasks take about 50 tool calls; it keeps a todo.md and rewrites it as it goes, keeping goals in recent attention.
  • Keep the wrong stuff in: leave failed actions and errors in context so the model updates its beliefs.

Isolate: clean windows

  • Sub-agents explore in their own windows and return a condensed summary, often 1,000–2,000 tokens.
  • Hermes children see only the goal and context fields; only their final summary returns to the parent.
  • Sandboxes keep heavy outputs (files, logs) out of the model's context until needed.
  • Don't get few-shotted: repetitive past actions in context make the agent repeat them; add controlled variation.
Anthropic context-engineering post; Manus lessons 4–6; Hermes delegation docs.

        ...   # track prompt tokens

    def should_compress(self, prompt_tokens=None):
        ...   # threshold policy

    def compress(self, messages, current_tokens=None):
        ...   # return the new message list

def register(ctx):
    ctx.register_context_engine(MyEngine())

# config.yaml:  context: { engine: my-engine }
  • Default engine: agent/context_compressor.py, a lossy summarization algorithm.
  • Built-in policy: preflight compression above 50% of the window, gateway auto-compression above 85% between turns, keep the last 20 messages, flush memory first, never split tool pairs.
  • Memory providers get on_pre_compress to extract facts before history is summarized.
  • Lab 12A plugs your Lab 3 engine in through this interface.

Example: lossless-claw

  • Stores every message in SQLite; "nothing is lost".
  • Summarizes older chunks, then condenses summaries into higher-level nodes: a DAG linked back to source messages.
  • assemble = summaries + recent raw messages (freshTailCount, default 64).
  • Recall tools lcm_grep, lcm_describe, lcm_expand let the agent drill back into detail.

MeasureIs the context manager doing its job?

  • Context tokens per call over a session (OpenClaw exports openclaw.context.tokens).
  • Cache hit rate: cached / total input tokens; prefix-cache hits in vLLM.
  • Compactions per session, and task success on tasks that crossed a compaction vs. those that didn't.
  • Recall after compaction: ask about a fact from before the compaction (a needle test on your own transcripts).
  • Cost per task: input tokens dominate at 100:1.

Red flags

  • Cache hit rate drops after a harness change
  • Agent repeats work it already did (lost notes)
  • Answers contradict earlier decisions (clash)
  • Context grows linearly with no compaction (bloat)
Metrics: 06_observability_evaluation_deck.html; OpenClaw OpenTelemetry docs.

ExerciseCompare two context engines

  1. Start from your Lab 3 engines: threshold compaction or tool-result clearing.
  2. Implement a second engine: tool-result clearing + todo recitation, or hierarchical summaries with an expand tool.
  3. Run a 40+ step task (for example, refactor a small repo) with each engine, three times.
