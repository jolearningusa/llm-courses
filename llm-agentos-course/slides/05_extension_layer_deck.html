The extension layer

The extension layer is where the other eight components become replaceable: memory, context, tools, skills, channels and model providers all arrive as plugins.

What can be extendedExtension points in two harnesses

Hermes Agent plugin types

  • General (multi-select): tools, hooks, slash commands, CLI commands, skills.
  • Memory provider (single-select).
  • Context engine (single-select).
  • Model providers (many load; one chosen per run).
  • Also platforms and approval transports (register_platform, register_approval_transport).

OpenClaw native plugins

  • Tools, hooks, channels, providers, CLI backends, skills.
  • Exclusive kinds "memory" and "context-engine", chosen with plugins.slots.memory and plugins.slots.contextEngine.
  • Compatible bundles: Codex, Claude and Cursor plugin layouts are mapped into OpenClaw's inventory.

}

Why a manifest

  • OpenClaw reads it to validate config without executing plugin code; a missing or invalid manifest is a plugin error.
  • Only id and configSchema are required; optional fields include kind, channels, providers, skills, uiHints, requiresPlugins, enabledByDefault; version is informational.
  • Runtime hooks and entry points stay in code and package.json.
  • Hermes v2 manifests add api_version and requires_plugins; changing update_url needs approval.

RegisterThe registration API

# Hermes: __init__.py
def register(ctx):
    ctx.register_tool(name="search_tickets",
        toolset="tickets", schema=SCHEMA,
        handler=search_tickets)
    ctx.register_hook("post_tool_call", audit)
    ctx.register_command("tickets", show,
        "Show open tickets")
    ctx.register_skill("triage", "skills/triage")
    # also: dispatch_tool, inject_message,
    #       call_mcp(server, tool, args, timeout=30)
// OpenClaw: runtime module
export default function register(api) {
  api.on("before_tool_call", async (ev) => {
    if (isDangerous(ev)) return { block: true };
  }, { priority: 100, timeoutMs: 2000 });

  api.on("before_prompt_build", async () => ({
    appendSystemPrompt: "..."   // illustrative
  }));
  // slots: api.registerContextEngine(...)
  // policy: api.registerTrustedToolPolicy(...)
}

One entry point, many registrations: the harness, not the plugin, decides when each piece runs. This is what makes plugins composable.

OpenClaw ordering rules

  • Handlers run in descending priority; ties in registration order.
  • Trusted tool policies run before ordinary before_tool_call hooks.
  • A terminal block skips lower-priority handlers.
  • before_agent_run and before_install fail closed on bad output or errors.
  • Observer failures are logged and ignored.
Hermes plugins docs ("Available hooks"); docs.openclaw.ai/plugins/hooks.

Exclusive rolesSlots: exactly one provider per role

  • Some components must have exactly one owner per session: who stores memory, who assembles and compacts context.
  • OpenClaw: a plugin declares kind: "memory" or "context-engine"; config picks one with plugins.slots.*. Selecting a plugin for a slot force-enables it, but plugins.deny and enabled: false still win.
  • Hermes: memory providers and context engines are single-select (memory.provider, context.engine); default engine compressor.
  • OpenClaw's legacy context engine is the default slot owner (context manager deck).

Why not let two run?

Two context engines would both rewrite the transcript; two memory providers would both inject recall and double the tokens. A slot turns that conflict into a config error instead of a runtime surprise.

Same idea as one active display driver or one init system.

docs.openclaw.ai/tools/plugin ("slots"); Hermes plugins docs ("plugin types"); companion deck slide 28.

In or out of processPlugins vs. MCP servers

In-process pluginMCP server
Runs asCode inside the harness (Python / Node)Separate process or remote service
Can doAnything: hooks, slots, prompt edits, toolsOffer tools, resources, prompts; ask the user for input (elicitation)
PortabilityOne harnessAny MCP client
Failure / trustCrash or compromise = the harnessProcess boundary; env filtered (Hermes passes a short allowlist)
ContractHarness API versionProtocol version + client capabilities in every request's _meta

Since MCP 2026-07-28 there is no initialize handshake and no session: each request carries its protocol version, client info and capabilities, and a client can call the optional server/discover first. Sampling, roots and logging are deprecated.

BundlesPlugins as distribution units

  • Claude Code plugins (Oct 9, 2025, public beta): any combination of slash commands, sub-agents, MCP servers and hooks; /plugin marketplace add owner/repo, then /plugin install.
  • OpenClaw installs Claude-compatible marketplace plugins (--marketplace) and maps Codex, Claude and Cursor bundles.
  • Codex recommends plugins for distributing your own skills (skills deck).
  • Hermes plugins can register skills (register_skill).

Trend

The plugin is becoming the package: skills + MCP servers + hooks + commands shipped together, installable across harnesses that share layouts.

Compatibility layers (OpenClaw reading other vendors' bundles) are how a de facto standard forms before a formal one.

VersioningKeeping plugins compatible

  • Declare the API you target: Hermes manifest v2 api_version; MCP protocolVersion.
  • Declare dependencies: Hermes requires_plugins, OpenClaw requiresPlugins.
  • Deprecate with aliases: OpenClaw keeps deactivate as a deprecated alias for gateway_stop, before_agent_start for compatibility, and legacyPluginIds for renames.
  • Validate config without running code: JSON Schema in the manifest.
  • Pin in production: OpenClaw recommends pinned versions; the Hermes skills hub skips locally edited skills on update unless --force.

Checklist for a plugin author

  • Semantic version + target API version
  • Config schema with additionalProperties: false
  • Feature-detect hooks; don't assume new ones exist
  • Fail closed in deciding hooks, open in observers
  • Timeouts on every hook
Hermes plugins docs; OpenClaw manifest, plugin and hooks docs; MCP lifecycle spec.

SecurityA plugin is code you run with the agent's privileges

  • Hermes: capabilities are "a consent and audit layer, not isolation"; plugins are in-process Python. Install-time scan with safe / caution / dangerous verdicts.
  • OpenClaw: "Treat plugin installs like running code"; native plugins load in process; security.installPolicy runs an operator policy command before installs; before_install hooks can block and fail closed.
  • The skill supply-chain attacks (ClawHavoc, skills deck) apply to plugins with even more power.

Controls that work

  • Default off; explicit allowlist (plugins.allow, plugins.enabled)
  • Never auto-load plugins from a cloned repo
  • Pin versions; review diffs on update
  • Out-of-process where possible (MCP, Hermes plugins.isolation: host)
  • Audit: openclaw security audit covers plugins
Hermes plugins docs ("security"); docs.openclaw.ai/tools/plugin ("security"); OpenClaw security docs; access control deck.

ExerciseOne feature, three extension mechanisms

  1. Feature: "log every shell command the agent runs and block curl | sh".
  2. Build it as (a) a Hermes plugin with a pre_tool_call hook, (b) an OpenClaw plugin with before_tool_call, (c) an MCP server that wraps shell execution.
  3. Add a manifest with a config schema to each plugin; give it a bad config and see what fails.
  4. Install a second plugin that also hooks tool calls; check ordering.
