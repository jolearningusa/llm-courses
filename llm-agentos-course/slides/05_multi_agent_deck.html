The debateTwo production reports, two conclusions

Anthropic: multi-agent research (Jun 13, 2025)

  • Opus 4 lead + Sonnet 4 sub-agents beat a single Opus 4 agent by 90.2% on an internal research eval.
  • On BrowseComp, token usage alone explained 80% of performance variance (95% with tool calls and model choice).
  • Cost: agents use about 4× the tokens of chat; multi-agent systems about 15×.
  • Parallel sub-agents (3–5) and parallel tool calls cut research time by up to 90%.
  • Poor fit: tasks where all agents need the same context or many dependencies, including most coding.

Cognition: "Don't build multi-agents" (Jun 12, 2025)

  • Principle 1: share context, and share full agent traces, not just individual messages.
  • Principle 2: actions carry implicit decisions, and conflicting decisions carry bad results.
  • Flappy Bird example: one sub-agent builds a Mario-style background, another a bird that doesn't match; the merger fails.
  • Default: a single-threaded linear agent; for long tasks, add a model that compresses history.

Both agree: split when sub-tasks are read-mostly and parallel (search, research, review); keep one thread when sub-tasks write shared state (code, documents).

anthropic.com/engineering/multi-agent-research-system; cognition.com/blog/dont-build-multi-agents.

PatternOrchestrator-worker

  • Brief each worker fully: objective, output format, tools, boundaries. Workers do not see the parent's history.
  • Scale effort to the query: 1 agent and 3–10 tool calls for a fact; 2–4 sub-agents for a comparison; more than 10 for complex research.
  • Return condensed results: the parent's context grows by summaries, not transcripts.
  • Persist the plan: the lead saves its plan to memory because context past 200k tokens is truncated.
  • Verify at the end: a separate citation / checker pass.
Anthropic multi-agent research system; Anthropic "Building effective agents" (Dec 19, 2024) for orchestrator-workers as a workflow pattern.

Hermes Agentdelegate_task: fresh context, summary back

  • One task (goal, context) or a batch (tasks, each with optional output_schema); children inherit the parent's toolsets.
  • A child starts with no access to the parent's history; it gets goal, context and the workspace's project context files (not SOUL.md).
  • Only the child's final summary enters the parent's context.
  • delegation.model / provider run children on a cheaper model.
  • delegation.worktree_isolation: true: one git worktree per child, so parallel coders don't collide.

Roles and limits

  • Leaf children lose delegate_task, clarify, memory, send_message, cronjob.
  • role="orchestrator" keeps delegate_task, only if max_spawn_depth > 1 (default 1).
  • 10 children per batch, 250 iterations per child (scheduler deck).
  • /stop ends background children; they return status="interrupted" with partial output. A restart does not resume them.
hermes-agent.nousresearch.com/docs/user-guide/features/delegation.

OpenClawSub-agents: spawn, announce, archive

  task: "Compare the three vendors' SLAs",
  label: "sla-compare",
  model: "cheap-model",        // optional
  context: "isolated",         // or "fork"
  mode: "run",                 // "session" needs thread
  cleanup: "keep"              // or "delete"
})
→ { status: "accepted", runId, childSessionKey }
// child session: agent:<agentId>:subagent:<uuid>
// result arrives later as an announce event;
// the parent waits with sessions_yield, not polling

Defaults

  • maxSpawnDepth 1 (1–5); 2 enables orchestrators.
  • maxChildrenPerAgent 5; subagent lane maxConcurrent 8.
  • archiveAfterMinutes 60; runTimeoutSeconds 0 (none); announceTimeoutMs 120000.
  • Children get only AGENTS.md and TOOLS.md, not SOUL.md, USER.md or MEMORY.md.
  • Always denied: gateway, agents_list, session_status, cron, sessions_send; leaves also lose spawn and history tools.
OpenClaw docs: docs.openclaw.ai/tools/subagents (tool reference, nesting, announce, tool policy, operations).

OpenClawMany agents in one gateway: routing and IPC

  • An agent is a full persona scope: workspace files, auth profiles, model registry and session store under ~/.openclaw/agents/<agentId>/. Never share an agentDir.
  • Bindings route inbound messages to agents, deterministic and most-specific-wins: exact peer → parent peer → peer wildcard → guild+roles → guild → team → account → channel → default agent.
  • Agent-to-agent messaging is off by default: tools.agentToAgent: { enabled, allow: ["home", "work"] }.

Two kinds of multi-agent

Vertical: a parent spawns short-lived children for one task (sub-agents).

Horizontal: long-lived peer agents with separate identities and data (home vs. work), connected only where allowed.

Horizontal separation is also an access-control boundary: a work agent cannot read the home agent's memory unless you allow it.

OpenClaw docs: docs.openclaw.ai/concepts/multi-agent.

Shared stateLetta: shared memory between agents

  • Shared memory blocks (older API, still supported): one in-context memory block attached to several agents.
  • Shared memory repositories (current): a Git repository per organization, attached per agent with letta shared-memory attach <name> --agent <agent-id>.
  • Agents edit files with file and Git tools, commit and push; other agents pull. Concurrency is resolved the way Git resolves it.
  • Requires cloud-hosted agents.

Message passing vs. shared memory

  • Messages / summaries: explicit, small, easy to trace; information is lost at each hop.
  • Shared memory: everyone sees the same facts; needs write discipline, history and conflict handling.
  • Cognition's principle 1 argues for sharing more; Anthropic's design shares less and pays for it with careful briefs.
docs.letta.com/concepts/shared-memory. Sleep-time agents that edit a primary agent's memory: memory deck (02).

Across vendorsA2A: agent-to-agent protocol

  • Open standard for independent, possibly opaque agents: they collaborate without sharing internal state, memory or tools.
  • Agent Card: JSON describing identity, skills, endpoint and auth, commonly served at /.well-known/agent-card.json.
  • Task (stateful, with an ID), Message (role user / agent, made of Parts: text, file, data), Artifact (task output).
  • States include working, input-required, auth-required, completed, failed, canceled, rejected.
  • Bindings: JSON-RPC, gRPC, HTTP+JSON; streaming and webhook push notifications. Latest release 1.0.0.

ResearchWhy do multi-agent systems fail? (MAST)

Cemri et al. annotated 1,600+ traces from 7 frameworks (κ = 0.88) and found 14 failure modes in 3 categories:

System designInter-agent misalignmentTask verification
Disobey task specConversation resetPremature termination
Disobey role specFail to ask for clarificationNo or incomplete verification
Step repetitionTask derailmentIncorrect verification
Loss of conversation historyInformation withholding
Unaware of stopping conditionsIgnored other agent's input
Reasoning-action mismatch

Takeaways

  • Most failures are organizational, not model errors: unclear roles, lost context, nobody checking.
  • Fixes look like management: role specs, explicit hand-off formats, termination rules, a verifier.
  • Use the taxonomy as labels for trace review (observability deck).
Cemri et al., "Why Do Multi-Agent LLM Systems Fail?", arXiv:2503.13657.

SystemsServing cost of multi-agent workflows

  • Sub-agents multiply tokens (about 15× chat) and requests; each child has its own prompt prefix.
  • Shared prefixes (system prompt, tool schemas, skill index) should be identical across children so prefix caching can reuse them.
  • KVFlow uses the workflow graph to predict which agent runs next and keeps its prefix cached: 1.83× (single workflow) and 2.19× (many concurrent) over SGLang with hierarchical cache.
  • Program-aware schedulers (Autellix, Continuum) treat the whole agent program, not each call, as the unit to schedule.

Rules of thumb

  • Use a cheaper model for workers, a strong one for the lead.
  • Cap depth and fan-out; recursion is the agent fork bomb.
  • Give each child a timeout and a budget.
  • Measure cost per task, not per call.
KVFlow, arXiv:2507.07400 (NeurIPS 2025); scheduler deck (Autellix 2502.13965, Continuum 2511.02230); Anthropic multi-agent research system.

ExerciseSame task, three architectures

  1. Pick a research task with 4–6 independent sub-questions and a verifiable answer key.
  2. Run it as (a) one Hermes agent, (b) Hermes with delegate_task batch of workers, (c) OpenClaw with sessions_spawn workers on a cheaper model.
  3. Repeat each 5 times.
  4. Label every failed trace with a MAST failure mode.

Measure

  • Answer accuracy and pass^5
  • Total tokens and cost per task
  • Wall-clock time
  • Parent context size at the end
  • Most common MAST category per architecture
